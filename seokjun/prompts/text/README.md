# 글 버전 프롬프트 (`prompts/text`)

밤 단계에서 AI에게 주는 시스템 프롬프트 4개(자기반성 2개, 시각 찾기 1개, 덩어리 만들기 1개)다. 실행할 때마다 쓴 파일의 지문 값(sha256)을 기록에 남긴다(`pam/text_messages.py`). 논문 원본(`prompts/paper/`)은 고치지 않는다. 계획: `../../../설계문서/2026-11-14_PAM_80퍼센트_p-value_구현계획서.md`

| 파일 | 단계 | 받는 것 | 내는 것 | 논문 원본 |
|---|---|---|---|---|
| `reflector_text_build.txt` | 첫날 밤 자기반성 | 로봇 할 일 목록, 그날 기록(기록 간격대로 한 줄씩) | 후보 FSM (규칙마다 트리거 후보 1~3개) | `reflector_fsm_build.txt`를 고침 |
| `reflector_text_update.txt` | 다음 날부터 자기반성 | 로봇 할 일 목록, 그날 기록(기록 간격대로 한 줄씩), 지금까지의 FSM, 검사 결과, 피드백 | 후보 FSM | `reflector_fsm_update.txt`를 고침 |
| `chunking.txt` | 하루 기록을 덩어리로 바꾸기 (2026-11-18 새로, 실제 영상 실험) | 그날 기록(기록 간격대로 한 줄씩) | 하는 일 덩어리 목록 (시작, 끝, 한 문장) | 없음 (새로 씀). 같은 일이 이어지는 줄과 방금 한 일을 다시 말하는 줄을 한 덩어리로 묶는다. 예시 문장은 우리 기록에 없는 장면(수건 개기)으로 썼다 |
| `marking.txt` | 후보 시각 찾기 | 상태 설명, 찾을 후보(상태 포함), 찾을 행동, 그날 기록(기록 간격대로 한 줄씩) | 후보와 행동이 일어난 시각, 사람이 안 보인 구간 | 없음 (새로 씀) |

## 논문 원본에서 바꾼 곳

줄 번호는 논문 원본 파일의 줄이다. 적지 않은 줄은 원문 그대로다(같은 물건 트리거 금지, 로봇이 도와도 사람이 할 신호만 트리거로, 상태 나누기, 전이, 첫 상태 정하기 등).

## 정해 둔 숫자와 가정 (확인 필요)

- **검사 기준 시간:** 프롬프트 글에는 숫자를 쓰지 않는다. 계산에 쓰는 값을 자기반성 입력에 자동으로 넣는다(`pam/text_messages.py`). 기본은 5분(`pam/trigger_check.py`의 `FOLLOW_SECONDS`)이고, 실행할 때 `--window-seconds`로 바꿀 수 있다(실제 영상 실험은 하루가 5분이라 1분, 2026-11-18). 밤마다 `done.json`에 적고, 한 실행 폴더 안에서 섞이지 않게 막는다. 5분 자체는 임시 값이다.
- **기록 한 줄 간격:** 세 프롬프트의 「one line every {line_step}」 자리에 기록의 실제 간격을 코드가 넣는다(2초 기록이면 「2 seconds」, 1초 기록이면 「second」). 전에는 「2 seconds」로 적혀 있었다(2026-11-18 바꿈).
- **후보를 바꿀 수 있는 기준:** 3번 이상 나왔고 75% 미만(통과 기준과 같은 숫자). 계획서에는 "계속 떨어지는 후보"라고만 적었다. 통과 기준과 함께 80%였는데, 2026-11-18 사용자 결정으로 둘 다 75%로 낮췄다(`pam/trigger_check.py`의 `RATE_MIN`). 4번 중 3번 따라온 정답 신호를 80% 미만이라고 AI가 버렸기 때문이다.
- **시각 찾기:** 같은 후보가 10초 안에 다시 나오면 한 번으로 친다 (고개를 잠깐 돌린 것 같은 끊김).
- **하루 길이:** 아침 합성 기록은 1시간(2초 간격 1,800줄), 실제 영상 실험은 5분쯤(1초 간격 280~300줄). 자기반성과 시각 찾기에 기록을 통째로 넣는다(2026-11-16).
- **기록 문장 모양:** 한 줄이 장면 전체(자세, 하는 일, 주변 물건)를 적고, 방금 한 일을 몇 초 동안 다시 말한다. 실제 예측 모델 관찰 문장(`artifacts/routine_vllm_fsm_2026-11-04`)이 그렇다. 그래서 자기반성과 시각 찾기의 입력 설명에 이 모양을 적고, 시각 찾기에는 "방금 한 일을 다시 말하는 줄은 앞의 그 순간이니 다시 세지 않는다"를 넣었다(2026-11-16).
- **할 일 찾기 (`marking.txt`):** 할 일은 로봇 입장에서 쓴 문장이라, 사람이 직접 같은 결과를 만들었으면 말이 달라도 센다. 장소 이름이 다른 경우("사람 옆" = 그 사람이 있는 곳에서 손 닿는 곳)와 물건 이름이 다르거나 더 구체적인 경우(같은 물건일 때만)를 적었다. 답의 시각은 기록에 있는 줄의 시각만 받는다(`pam/contracts.py`의 `validate_marks`). 이 집의 가구·전등 이름은 일부러 넣지 않았다. 실험 ② 1일째(2026-11-16)에 식탁·책상에 컵을 놓은 4번과 "천장 불 끄기"를 "사람 옆에 컵 놓기", "방 불 끄기"로 찾지 못해서 넣었다. 할 일의 시각은 사람이 그 일을 하러 그쪽으로 걸어가기 시작한 줄이다. AI는 먼저 일을 해낸 순간을 찾고, 거기서 거꾸로 올라가 걸어가기 시작한 첫 줄을 찾는다(처음에 「출발한 첫 줄」만 찾게 했더니 커튼·불 끄기에서 2~4초 늦게 짚어서 2026-11-16 바꿈). 손 뻗기·집기는 넣지 않았다(2026-11-17 사용자 결정). 전에는 일을 해낸 순간을 썼는데, 그러면 "커튼 쪽으로 감"처럼 이미 하러 가는 동작이 매번 몇 초 뒤 행동이 따라오는 신호로 검사를 통과했다(2026-11-16 실험 ②). 논문 본문의 "신호는 사용자가 그 일을 시작하기 전에 나와야 한다"를 셈하는 법으로 지키려는 것이다.
- **"로봇은 오늘 아무것도 하지 않았다":** 합성 기록 시험용이다. 로봇이 실제로 돕기 시작하면 로봇이 한 일도 입력에 넣도록 고쳐야 한다.
- **집 설명(Environment):** 합성 기록의 집에 맞췄다. 실제 집이 다르면 바꾼다.
