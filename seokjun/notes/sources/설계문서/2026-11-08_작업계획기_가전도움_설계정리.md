# 작업 계획기 · 가전 도움 설계 정리 (2026-11-05 ~ 11-08)

> 이 문서는 대화로 정한 설계, 시험 결과, 남은 결정을 모은 개인 작업 기록이다. 팀 기준 문서(SSOT)를 바꾸는 결정은 아니다.
> **[정함]** = 사용자가 정한 것, **[제안]** = Claude가 낸 안(아직 확정 아님), **[확인함]** = 파일·논문에서 직접 확인한 사실.

## 0. 한눈에 보기

- PAM 판단(지금 우리 모델) 뒤에 **작업 계획기**(목표를 원자 행동 순서로 쪼개는 부분)를 붙인다.
- 첫 버전은 **가전과 관련된 도움만** 한다. 가전은 미리 연결돼 있다고 가정한다.
- 시험은 영상 대신 **글로 만든 합성 데이터**로 한다. 영상을 넣었다고 치고, 사진에서 나왔을 글을 우리가 직접 쓴다.
- 그 글은 **지금 1초 판단이 쓰는 «장면 한 문장(observation)»과 같은 모양**으로 써야 실제와 맞는다(3장).
- 간단 실험 결과: 행동을 «정해진 틀»로 적게 하는 것보다 «자유롭게, 단 원자 행동으로 쪼갤 수 있게» 적게 하는 쪽이 나았다(7장). 단 하루 기록 1개, 방식마다 3번뿐이다.

## 1. 전체 구조

```
[입력]  장면 문장(사진→글) + 가전 상태 + 가전 신호
  → ① 1초 판단(PAM): 지금 무엇을 도울 때인가 → 목표 하나 (예: 마실 것 가져오기, 에어컨 켜기)
  → ② 확률 부분: 마실 것이면 콜라냐 우유냐 (횟수 + 최근 무게)
  → ③ 작업 계획기: 목표 → 원자 행동 순서 (가전 기능 목록을 보고 단계를 넣고 뺌)
  → ④ 실행(글 시험에서는 «가짜 집»이 결과를 글로 돌려줌) → 못 하면 «대신할 일» 판단
  (①~④ 모두 단계마다 기록)

[밤]  ⑤ 자기반성: 하루 기록 → 가전 신호마다 앞뒤 5분을 잘라 봄 → 새 기억(규칙)
```

|---|---|---|---|
| 1초 판단 | 논문 지시문 + 기억 + 행동 목록 0~9 | `Wall-clock time of the final frame: <시각>` + 사진 9장(1초 간격) | JSON `{observation, reasoning, task_index}` |

### 3.2 사진을 글로 뽑는 규칙 [확인함]

- 따로 정한 «사진→글 템플릿»은 없다. **1초 판단 지시문의 출력 칸 하나가 전부다** (논문 부록 E.3, 33~34쪽 = `ai/prompts/paper/predictor_fsm.txt:51`).
  - 원문: `` `observation` should be a single concise sentence describing the current scene state, focusing on task-relevant objects, humans, and state changes. ``
  - 번역: observation에는 지금 장면 상태를 짧은 문장 **하나**로 쓴다. 할 일과 관련된 **물건, 사람, 상태 변화**에 초점을 맞춘다.
- 논문도 같다. 별도의 사진→글 단계는 없고, 판단과 자기반성 모두 사진을 직접 본다(논문 3.1절, 부록 A.2).
- **논문에 없는 우리 선택:** 밤 자기반성에 주는 «하루 요약»을 1초 판단의 장면 문장으로 만든 것은 우리 코드의 선택이다. 논문은 «그날 행동 이력의 요약»을 준다고만 쓰고, 무엇으로 만드는지는 적지 않았다(3.3절, 부록 A.2).

### 3.3 글 시험에서 바꾸는 점 [제안]

- **1초 판단:** 사진 9장 대신 아래 글을 준다.
  ```
  [지금 가전 상태]  air conditioner off · indoor 29°C / refrigerator door closed / washing machine idle
  [최근 5분 신호]   t=1200s washing machine · cycle finished · caused by: device
  [최근 9초 장면]
  t=1202s: The person is sitting on the sofa watching TV.
  ...
  t=1210s: The person is sitting on the sofa watching TV.
  ```
- **밤 자기반성:** 사진 없이 하루 요약만 준다. 장면 줄 사이에 가전 신호 줄을 같은 `t=` 시각으로 끼운다.
  ```
  t=1620s: The person starts washing the plate and the bowl from this meal in the sink.
  t=1680s: [SIGNAL] coffee machine · brewing started · caused by: user
  t=1680s: The person presses the start button on the coffee machine and returns to washing.
  ```
- 신호 줄 모양: `<가전> · <신호> · caused by: <device | user | robot | schedule>`
- 코드가 신호마다 앞뒤 5분 범위의 줄만 잘라 자기반성에 준다.

### 3.4 합성 글 작성 규칙 [제안]

1. **영어, 1초에 한 문장.** 실제 출력과 같은 모양으로 쓴다.
2. **사람이 하는 일 + 할 일과 관련된 물건 + 상태 변화**를 쓴다(논문 E.3 규칙).
3. **눈에 보이는 사실만 쓴다.** «더워 보인다», «커피를 원한다» 같은 해석·의도는 쓰지 않는다. 정답이나 촬영 의도를 흘리지 않는다.
4. **바뀐 게 없으면 같은 문장을 반복해도 된다.** 실제 출력도 그렇다.
5. **들고 있는 물건은 문장 안에 자연스럽게 쓴다.** 예: «holding a book». 따로 칸을 두지 않기로 했으므로, 문장에 안 쓰면 «들고 있는 물건엔 손대지 않는다» 규칙이 작동하지 않는다.
6. **물건 이름은 늘 같은 이름으로 쓴다.** 행동에 쓸 물건 이름 목록과 맞춘다.
7. 실제 출력에는 실수가 섞인다. 예: 4일 실험 B1(B 일과 첫날) 53초에 빈 책상에서 컵을 봄. 합성 글에는 실수가 없으므로 결과가 실제보다 좋게 나올 수 있다.

### 3.5 아직 정할 것

- 하루 전체를 1초마다 다 쓸지, 신호 근처만 촘촘히 쓸지
- 실제처럼 일부러 틀린 문장을 섞을지
- 사진→글을 판단과 따로 부를지(실제 파이프라인용)
- 둘째 날부터 요약 머리줄 «로봇은 오늘 아무것도 안 했다»를 로봇이 한 일로 바꿔 쓸지

## 4. 원자 행동 (의사코드) [정함: 형식 / 제안: 내용]

실무의 이동 기능(예: ROS 2의 Nav2)은 «지금 위치 → 목표»로 길을 짜고(지도 전체), 따라가면서 센서로 본 주변 정보로 움직임을 정하고, 막히면 제자리 돌기·물러나기 같은 복구 동작을 한다([Nav2 문서](https://docs.nav2.org/jazzy/getting_started/navigation_concepts/navigation_servers/)). 그래서 작업 계획기는 `go(목표)`의 결과(성공 / 실패와 이유)만 받으면 된다. 우리 로봇(LG CLOiD)이 Nav2를 쓰는지는 확인 못 했다.

```
go(목표 장소)
  하는 일        디지털 트윈 지도로 지금 위치 → 목표까지 길을 짜고 따라감
  먼저 필요한 것  목표 장소가 지도에 있음
  결과           성공 / 실패(길 막힘, 없는 장소, 시간 초과)

pick(물건)
  하는 일        눈앞의 물건을 집음
  먼저 필요한 것  물건 앞에 있음, 손이 비어 있음
  결과           성공 / 실패(물건 없음, 못 집음)
```

간단 실험에서 쓴 원자 행동 목록: `go`, `open`, `close`, `look`, `pick`, `place`, `set`(연결로 가전 조종), `read`(가전 상태 읽기). 나머지의 «먼저 필요한 것 / 결과»는 아직 안 썼다.

## 5. 가전 신호 읽기와 트리거

### 5.1 신호 두 종류 [정함]

| 신호 종류 | 예 | 볼 곳 | 배우는 규칙 |
|---|---|---|---|
| 가전이 스스로 내는 신호 | 세탁 끝남, 실내 29°C, 문이 1분째 열림 | 신호 **뒤** 5분: 사람이 한 일 | 신호 = 트리거, 사람이 한 일 = 로봇이 대신할 행동 |
| 사람이 조작해서 생긴 신호 | 에어컨 켬, 냉장고 문 열림 | 신호 **앞** 5분 | 그 조작 = 로봇이 대신할 행동, 트리거는 앞에서 찾음 |

- 나쁜 점: 신호와 상관없는 도움(예: 책 가져다주기)은 못 배운다. 신호를 누가 일으켰는지(사람 / 가전 / 로봇 / 예약) 디지털 트윈 쪽에서 알려 줘야 한다.

### 5.2 논문 원문의 트리거 규칙 [확인함]

- 처음 만들 때(`ai/prompts/paper/reflector_fsm_build.txt`): 사람이 한 행동을 다시 적고 «로봇이 어떻게 대신할 수 있었나»를 생각한다 → 규칙 행동은 사람이 한 일을 그대로 따른다 → 같은 물건 트리거 금지 → **«로봇이 돕든 말든 나타나는 신호»만 트리거로** → 트리거는 짧은 문장 하나.
- 고칠 때(`reflector_fsm_update.txt`): 기억에 있는 행동을 사람이 직접 했으면(로봇이 놓침) 그 규칙 트리거에 **«또는(OR)»으로 신호를 덧붙인다**(66줄). 트리거가 오늘 안 나왔다는 이유로는 지우지 않는다.
- **«OR만 써야 한다»는 규칙은 없다. AND를 막는 문장도 없다.** OR는 놓친 일을 잡으려고 넓힐 때만 나온다.
- **전이는 로봇 행동이 아니다**(build 39줄). 행동은 상태 안의 규칙에만 둔다.
- 행동 형식은 `Pick up <물건> and place it <장소>.` 하나뿐이다(82~85줄). 4일 실험에서는 «끄기»와 «식기세척기 안»을 더해 썼다.

### 5.3 우리가 더한 것 [제안, 간단 실험 지시문에 넣음]

- 가전 신호 읽는 법(5.1)
- 사람이 조작한 신호는 그 일을 대신하는 규칙의 트리거로 쓰지 않는다. 예: «냉장고 문 열림(사용자)» → «냉장고에서 음료 가져오기» 금지
- 트리거는 사람 행동, 가전 신호·상태, 또는 둘을 섞은 것
- 알려진 문제: «집에 왔음 + 29°C»처럼 사람 상황과 가전 상태를 **같이** 따져야 하는 경우를 지시문이 말하지 않는다 → 간단 실험에서 한 번도 같이 쓰지 않았다.

## 6. 행동(목표) 적는 법 — 두 방식

| 구분 | 조건 1: 틀 | 조건 2: 자유 + 원자 행동 |
|---|---|---|
| 자기반성이 적는 법 | 틀 세 개에 빈칸을 채움: 가전 조종 / 꺼내서 두기 / 넣기 | 가전별 할 수 있는 일과 원자 행동 목록을 보고 자유롭게 씀 |
| 걸러 내는 곳 | 틀 자체 | 작업 계획기가 원자 행동으로 쪼갤 수 있는지 검사 |
| 할 수 없는 부분 | «할 수 있는 부분만» 쓴다 (예: 우유 따라 주기 → 우유 가져다 놓기) | 같음 |

- 가전 조종의 명령은 «연결로 하는 일 + 직접 하는 일»(예: 냉장고 문 닫기)을 모두 포함한다.
- 논문도 틀을 하나 둔다(집어서 놓기). 논문은 자기반성에게 행동 목록을 주지 않아, 4일 실험에서 목록 밖 규칙(그릇 가져오기, 캔 → 쓰레기통)이 나왔다.

| 열린 냉장고 문 닫기 | ○ | ○ | ○ | ○ | ○ | ○ |
| 빨래 → 건조기 | ○ | ○ | × 사람 옆에 둠 | ○ | ○ | ○ |
| 건조기 켜기 | ○ | △ 같은 트리거, 순서 없음 | △ 같음 | ○ | ○ | ○ |
| 우유(가져오기만) | △ | × | × | × | × | × |
| 컵 → 식기세척기 | ○ | ○ | ○ | ○ | ○ | ○ |
| 규칙 수 | 8 | 6 | 12 | 5 | 5 | 5 |

- **알게 된 것:** 틀은 여러 단계의 일을 같은 트리거의 규칙 여러 개로 쪼개 순서를 잃는다. 자유는 한 일 = 한 규칙, 단계가 순서대로 들어갔고 세 번 모두 규칙 수가 같았다. 둘 다 에어컨 트리거에 «집에 옴 + 덥다»를 같이 쓰지 못했고, 우유는 «할 수 있는 부분만»도 거의 안 썼다.
- **한계:** 하루 기록 1개, 3번씩, 채점은 Claude가 읽고 판단, 다음 날 실제로 돕는지는 안 봄.

## 8. 간단 실험 2: 커피 전이 지시문 (2026-11-07)

- 사용자가 쓴 지시문(식사 중 → 식사 후, 판단 기준·사용자 선호 포함)을 그대로 돌림. 결과: 트리거 «치우기 완료 **AND** 세척 시작», 액션 «커피 미리 준비». 지시문이 «두 조건을 모두 담아라»라고 해서 AND가 나왔다.
- 이 지시문은 트리거와 액션을 기준에 거의 다 적어 주므로, «모델이 스스로 찾았나»가 아니라 «기준을 지켰나»를 본 것이다.
- OR 버전을 기존 규칙으로 주고 «다음 전이 규칙»을 만들게 하자, 관찰 글이 없어서 «주방 조명 대기 모드, 다음 식사 일정 알림», «30분 경과» 같은 근거 없는 내용을 지어냈다.
- 비용 약 $0.002 + $0.004.

## 9. 커피 정답을 만들기 위한 시나리오 [제안]

**정답(논문 모양):** 전이 «식사 중 → 식사 후», 조건 «이번 식사 그릇을 식탁에서 치움 OR 그 그릇 세척 시작». 규칙: 트리거 같음 → «커피 머신으로 커피 내리기».

**2일 시나리오:** 1일째 = 세척 시작 뒤 커피를 내림(치우기는 8분 전이라 «앞 5분» 밖) → 규칙 «세척 시작 → 커피». 2일째 = 치우자마자 커피를 내림 → 로봇이 놓침 → 고칠 때 «OR 치우기 완료»가 붙음.

| 정답 요소 | 지금 지시문으로 나오나 | 고칠 것 |
|---|---|---|
| 상태 식사 중 → 식사 후 | 나올 것으로 봄 | 없음 (채점은 뜻으로) |
| 액션 «커피 내리기» | 논문 원문으로는 안 나옴 | 가전용 지시문 + 가전 목록에 커피 머신 추가 |
| 1일째 트리거 «세척 시작» | 나올 것으로 봄 | 없음 |
| 2일째 «OR 치우기 완료» | 논문 고치기 방식에 있음 | 가전용 «고치기» 지시문을 새로 만들어야 함 |
| 전이 조건에도 OR | 안 나올 수 있음 | 돌려 보고 안 되면 한 줄 추가 |
| «사용자 선호» 글 | 필요 없음 | 넣으려면 2일째 «사람 피드백» 자리 |

입력 데이터 초안은 아직 «12:20 [장면]» 모양이다. 3.3의 `t=초:` 모양으로 다시 써야 한다.

## 10. 확률 부분 계산 [정함: 방식 / 제안: 숫자]

- 가져갈지 말지는 FSM 규칙이 정하고, 확률 부분은 «무엇을 가져갈지»만 고른다. 그래서 기록이 1번이면 그 음료를 가져간다.
- 점수 = 기록마다 «며칠 전인지»에 따라 무게를 곱해 더함(하루 지날 때마다 곱하는 값, 예 0.8).

| 하루마다 곱하는 값 | 콜라 5번(3~7일 전) | 우유 2번(오늘·어제) | 고름 |
|---|---|---|---|
| 1 | 5 | 2 | 콜라 |
| 0.9 | 2.99 | 1.9 | 콜라 |
| 0.8 | 1.72 | 1.8 | 우유 |

- 나쁜 점: 곱하는 값을 정해야 한다. 콜라가 없어서 우유를 마신 날은 냉장고 기록으로 따로 표시해야 한다.
