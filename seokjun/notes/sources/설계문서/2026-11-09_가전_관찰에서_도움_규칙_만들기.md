# 가전 사용을 관찰해 로봇의 도움 규칙 만들기

2026년 11월 9일 · 박석준 개인 설계안 · 1차 버전

**낮에는 사람이 실제로 한 일을 기록한다. 밤에는 그중 로봇이 맡을 수 있는 일을 골라, 다음번에 어떤 조건에서 먼저 수행할지 정한다.** 모델은 관찰을 시각이 붙은 사실로 바꾼다. 코드는 그 사실과 가전 로그를 대조해 규칙을 채택하거나 보류한다. 보류한 후보는 다음 날의 기록이 들어오면 다시 검사한다.

| 규칙을 읽는 순서 | 뜻 | 예시 |
|---|---|---|
| 작업 상태와 전이 | 지금 어느 단계이며 어떤 일을 마치면 다음 단계가 되는가? | TV 시청 중 → 맥주를 사용자 곁에 놓음 → 맥주 제공 완료 |
| 트리거 | 언제 로봇이 이 일을 맡을지 검토하는가? | TV가 켜진 순간 |
| 가드 | 그 순간에 추가로 만족해야 할 조건은 무엇인가? | 금요일 |
| 실행 직전 확인 | 지금 실제로 수행할 수 있고, 아직 도움이 필요한가? | 맥주가 있고 사용자가 이미 가져오기 시작하지 않았는지 확인 |

## 1. 사람과 로봇이 같은 작업 흐름을 쓴다

**작업 흐름을 나타내는 유한 상태 기계(FSM)는 하나다.** 상태는 작업이 어디까지 진행됐는지 나타내고, 전이는 한 상태에서 다음 상태로 넘어가는 사건이다. 로봇 규칙은 **로봇이 맡을 수 있는 전이**에 붙인다. 전이마다 맡을 행동, 트리거, 필요한 가드를 기록한다. 상태 목록은 미리 고정하지 않는다. 관찰된 한 전이와 다음 전이 사이를 하나의 상태로 정의한다. 예를 들어 접시가 비워진 것을 식사 종료 증거로 확인했다면, 그때부터 접시를 치우기 전까지가 ‘식사 후’ 상태다.

~~~text
[세탁 중] ── 기기가 세탁 종료를 알림 ──→ [세탁 완료]
[세탁 완료] ── 세탁물 꺼내기 (사람 또는 로봇) ──→ [꺼낸 상태]
[꺼낸 상태] ── 건조기에 넣기 (사람 또는 로봇) ──→ [건조 대기]
~~~

세탁 종료는 기기가 알려 주는 시작 전이로 받는다. 사람이 먼저 빨래를 꺼내면 흐름은 이미 ‘꺼낸 상태’에 있으므로 로봇의 꺼내기 작업은 사라진다. 다음 전이는 **누가 했든 앞 전이가 완료된 사실**을 사용할 수 있다. 로봇이 맡은 전이는 실제 동작이 성공했을 때 완료한다. 이동·집기·실패 처리는 해당 전이를 수행하는 하위 동작에서 다룬다.

## 2. 어떤 행동을 배울지 고른다

1. **기기의 신호는 뒤를, 사람의 조작 신호는 앞뒤를 본다.** 세탁 종료 뒤 사람이 무엇을 했는지, 냉장고를 열기 전에는 어떤 상황이었고 연 뒤에는 무엇을 꺼냈는지 확인한다. 로봇이나 예약이 일으킨 조작은 주체를 구분해 기록한다.
2. **기록을 수집할 구간과 결과를 인정할 마감을 따로 정한다.** 가전 신호 주변 5분은 짧은 장면을 읽는 예다. 세탁 종료 뒤 30분이 지나 꺼낸 빨래도 찾을 수 있도록, 기기별로 더 긴 수집 구간이나 같은 기기의 다음 사람 조작까지를 설정할 수 있다. 결과 마감은 행동별 설정이다. 예를 들어 ‘이 행동은 트리거 후 30분 이내에 시작해야 결과로 인정’이라고 정하면 그 이후 행동은 해당 기회의 성공으로 세지 않는다. **기기별 수집 범위와 행동별 마감의 구체적인 값은 구현 전에 정할 설정값**이다.
3. **사람이 실제로 한 일에서 로봇이 수행할 수 있는 부분을 고른다.** 우선 관찰된 목적과 결과로 행동을 묶고, 로봇의 동작 목록과 집에 등록된 물건·장소로 표현할 수 있는지 확인한다. 세탁 종료만 보고 건조기 사용을 가정하지 않는다. 사람이 건조기에 넣은 사실이 관찰된 뒤 그 행동을 후보로 만든다.
4. **기기 동작상 직접 연결되는 관계와 사용자의 습관을 구분한다.** 기기 규칙표로 확인되는 필수 관계는 관찰 한 번으로 채택할 수 있다. 예를 들어 ‘완료된 빨래 꺼내기’에는 해당 회차의 세탁 완료가 선행한다. 어떤 건조 방법을 고르는지처럼 선택이 가능한 관계는 4절의 습관 기준으로 판단한다. 처음 본 행동도 후보로 보관한다.

### 같은 행동을 같은 이름으로 세는 방법

행동은 **동작 / 대상 / 출발 → 도착**으로 기록한다. 동작은 로봇에 정의된 가져오기·옮기기·열기·닫기·끄기 등의 목록에서, 대상과 장소는 해당 집의 목록에서 고른다. 예를 들어 ‘빨래를 건조기에 옮겼다’와 ‘세탁기에서 빨래를 꺼내 건조기에 넣었다’가 **같은 관찰 결과**를 뜻한다면 둘 다 `옮기기 / 세탁물 / 세탁기 → 건조기`로 센다. 단순히 빨래를 꺼냈을 뿐이라면 건조기까지 옮겼다고 붙이지 않는다.

**구현 제안:** 네 칸은 화면에 읽기 쉬운 이름으로 표시하고 내부에서는 등록된 동작·물건·장소의 고유 번호로 비교한다. ‘문 닫기’처럼 출발·도착 칸이 필요 없는 경우는 ‘해당 없음’, 필요한데 관찰되지 않은 경우는 ‘모름’으로 구분한다. 하나의 옮기기를 여러 동작으로 실행하더라도 같은 행동 성공을 두 번 세지 않는다.

활동 종료도 관찰로 확인한다. 식사를 멈추고 전화를 받은 것만으로 접시를 치우지 않는다. 직접 보이는 종료 증거가 있을 때 **30초~1분간 활동이 재개되는지** 추가로 확인할 수 있다. 시간이 지났다는 사실만으로 종료를 판정하지 않는다. 종료가 불분명하면 접시 치우기를 보류하고, 사람이 싱크대에 둔 뒤 식기세척기에 넣는 다음 전이를 검토한다.

## 3. 트리거 후보와 기회 한 건을 만드는 방법

**트리거 후보**는 사람이 행동을 시작하기 전에, 해당 작업 상태 안에서 발생한 사건과 **그 상태에 들어오게 한 사건**에서 모은다. 기기 로그는 코드가 읽고 문장에만 나타나는 사건은 모델이 시간과 근거를 추출한다. 사건 후보가 통과하지 못하면 행동 시작 시각이 모이는지 확인해 시각 자체를 후보로 시험한다. 계산 방법은 아래 ‘시각 후보 만들기와 기회 세기’를 따른다.

“로봇이 이 일을 대신해도 이 사건이 그대로 일어날까?”를 기준으로 행동의 일부를 뺀다. 로봇이 빨래를 옮겨도 세탁 종료음은 울린다. 반면 음료를 가지러 가면서 사람이 연 냉장고 문은 음료 가져오기의 일부다. 고정된 몇 초 차이로 이 관계를 정하지 않는다.

**한 장면**에는 TV 켜짐, 냉장고 열림, 음료 꺼냄처럼 여러 기록이 들어갈 수 있다. **기회 한 건**은 그 장면을 특정 트리거·행동 쌍에 대해 평가하는 단위다. TV 켜짐을 평가할 때 뒤따른 냉장고 열림은 같은 장면의 증거로 묶고, 관찰에서 실제로 꺼낸 물건을 확인한다. 같은 날 같은 시간대에 같은 트리거가 여러 번 발생하면 기회 한 번으로 묶는다. 대표 시각은 **첫 신호 시각**이며, 가드와 결과 인정 마감도 첫 신호를 기준으로 정한다. 날짜 수를 계산할 때는 그날 여러 기회가 맞아도 한 날짜다.

| 기회에 저장하는 칸 | TV와 맥주 예시 | 코드가 지킬 기준 |
|---|---|---|
| 트리거 시각 | 23:00 TV 켜짐 | 같은 날·시간대의 같은 트리거 묶음에서 첫 신호 시각을 판단 시점으로 고정한다. |
| 가드 값 | 23:00에 마지막으로 확인한 동석자 값은 ‘혼자’ | 각 항목에 대해 **트리거 시각과 같거나 더 이른 기록 중 최신 값**을 쓴다. 확인 불가면 ‘모름’이다. |
| 결과 인정 마감 | 이 행동의 설정이 30분이면 23:30 | 판단 시점에 마감을 정한다. 정해진 구간에 해당 행동이 뒤따랐는지 확인한다. |
| 결과 | 함 / 하지 않음 / 이미 함 / 관찰 불가 / 로봇이 대신함 | ‘함’과 ‘하지 않음’만 적중률 계산에 쓴다. **이미 함·관찰 불가·로봇이 대신함은 분자·분모 모두에서 제외**한다. ‘하지 않음’은 마감까지 관찰할 수 있었을 때만 쓴다. |

**‘이미 함’은 모든 트리거에 적용한다.** 트리거 시각을 기준으로 같은 주기(예: 같은 날의 같은 시간대) 안에 해당 행동을 이미 완료한 관찰이 있으면 ‘이미 함’이다. 예를 들어 TV를 켜기 전에 그날 마실 맥주를 이미 꺼냈다면 그 TV 신호는 도움 기회로 평가할 수 없다. 규칙별로 ‘이미 함’ 횟수를 따로 남긴다. 자주 발생하면 시작 신호가 늦다는 단서이므로, 행동 전의 더 이른 사건이나 시각을 다시 살핀다.

예를 들어 **23:00 TV 켜짐(혼자) → 23:05 친구 도착 → 23:10 TV 다시 켜짐 → 23:15 맥주 꺼냄**은 TV 규칙에서 한 기회다. 첫 신호인 23:00과 당시의 ‘혼자’를 쓴다. 23:10의 TV 신호로 가드를 다시 고르지 않는다. 친구 도착은 맥주를 꺼내기 전 별도 사건이므로 ‘친구 도착 → 맥주’ 후보로 시험할 수 있다.

### 시각 후보 만들기와 기회 세기

1. **모임 판정:** 서로 다른 4일의 행동 시작 시각 중 **3일 이상이 폭 30분인 한 구간** 안에 있으면 시각 후보를 만든다. 범위 밖의 행동은 이 후보가 설명하지 못한 ‘놓침’으로 따로 기록한다.
2. **시각 선택:** 구간 안에 모인 날들 중 **가장 이른 행동 시작 시각**을 트리거 시각으로 쓴다. 범위 밖 시각은 이 계산에서 제외한다. 여기서 3일은 후보를 만드는 기준이다. 4절에서 습관 규칙을 채택하려면 별도로 서로 다른 4일의 일치가 필요하다.
3. **기회 집계:** 분석 기간에 그 시각이 돌아온 날마다 기회 한 건을 만든다. 금요일 가드가 있으면 금요일만 평가한다. 그 시각에 이미 끝낸 행동은 ‘이미 함’, 아직 하지 않았고 결과 인정 마감까지 관찰했으나 끝내 시작하지 않으면 ‘하지 않음’이다.
4. **야간 갱신:** 매일 밤 행동 시각을 다시 모은다. ‘이미 함’으로 적중률 계산에서 제외한 날도 **그날 관찰한 실제 행동 시각**은 남으므로, 평소 구간 안에서 더 일찍 시작한 날이 있으면 다음 트리거를 앞당길 수 있다. 그날의 실행 결과는 당시 적용한 규칙 기준으로 보존한다.

| 관찰 기록 | 그때의 판정 |
|---|---|
| 첫 주의 4일에 07:05, 07:00, 07:10, 07:02에 행동함 | 네 시각이 10분 안에 모인다. 후보 시각은 **07:00**이다. |
| 다음 주 월요일에는 06:55에 행동을 시작해 07:00 전에 마침 | 당일 07:00 기회는 ‘이미 함’이다. 그날 밤 평소 구간에 속하는 06:55를 반영해 다음 후보 시각을 **06:55**로 앞당긴다. |
| 다른 날 한 번 05:30에 행동을 마침 | 05:30은 평소 구간 밖이므로 행동 기록에서는 ‘놓침’, 당일 06:55 기회에서는 ‘이미 함’이다. 같은 날을 적중률의 실패로 더하지 않고 **06:55를 유지**한다. |

분모 예시로, 28일의 기회 중 26일에 마감 안에 행동을 시작했고 이틀은 ‘하지 않음’이면 **26/28 = 92.9%**다. 나머지 이틀이 ‘이미 함’, ‘관찰 불가’, ‘로봇이 대신함’ 중 어느 하나에 해당하면 적중률은 **26/26 = 100%**다. 제외한 사유별 건수도 함께 기록한다.

### 모델이 추출할 사실과 코드가 채울 값

모델은 관찰한 행동의 시작·완료 시각을 기록한다. 동석자처럼 센서로 얻기 어려운 값은 처음 확인한 때와 값이 바뀐 때마다 시각·근거 문장과 함께 고정된 JSON으로 출력한다. 코드는 이 기록에서 기회를 묶고, 첫 신호 시점에 알려진 값을 조회한다.

~~~json
{
  "사실": [
    {"시각": "23:00", "항목": "동석자", "값": "혼자", "근거": "화면에 거실 전체가 보이고 사용자가 혼자 있다."},
    {"시각": "23:05", "항목": "동석자", "값": "친구", "근거": "친구가 거실에 들어와 사용자 옆에 앉는다."}
  ]
}
~~~

**사실 추출 지시문 초안**

> 관찰에서 확인한 사건·행동과 허용된 관찰 항목의 값을 지정된 JSON으로 출력하라. 각 사실에 시각과 근거 문장을 붙이고, 항목의 값이 바뀔 때마다 새 시각과 값으로 기록하라. 기회 묶기와 트리거 시점의 값 조회는 코드가 맡는다. 행동명은 제공한 동작·대상·장소 목록을 사용하라. 확인할 수 없는 값은 ‘모름’으로 남겨라. 뒤에서 알게 된 정보를 앞선 시각의 사실로 쓰지 마라. 반복 여부, 빈도, 가드 선택과 규칙 채택은 코드가 계산한다.

| 사전에 허용할 가드 | 값의 예와 출처 |
|---|---|
| 시간 | 요일, 시간대 범위. **날짜 종류는 평일 / 주말 / 공휴일**로 두고 코드가 달력에서 채운다. |
| 장소·사람 | 위치, 동석자. 통화 중·손님 방문처럼 본래 활동과 겹치는 상황도 관찰된 경우 가드로 쓴다. |
| 환경 | 날씨, 실내 온도 구간 |
| 기기 | 코스, 채널, 모드 등 기기 상태 |
| 이력 | 직전 활동, 오늘 이미 한 일. 예를 들어 ‘아침 8시대 외출’은 관찰할 수 있다. 달력만 보고 개인이 출근했다고 추정하지 않는다. |

가드로 허용한 항목·값만 코드가 조합한다. **물건 재고는 실행 직전 필수 확인**으로 둔다.

## 4. 습관 규칙 채택 — 가드 유무에 따라 다른 기준

밤마다 최근 기록(예: 최근 12주)을 사용한다. **서로 다른 날 4회**는 검사를 시작하는 최소 일치 요건이다. 주기를 미리 가정할 필요가 없으며, 조건에 금요일이 들어가면 일치 날짜도 자동으로 서로 다른 금요일이 된다. 미달 또는 검사 실패 시 보류하고 다음 밤에 다시 계산한다.

| 코드가 검사할 항목 | 가드 없는 규칙 | 가드 있는 규칙 |
|---|---|---|
| 서로 다른 일치 날짜 | 트리거가 먼저 발생하고 마감 안에 행동한 날 **4일 이상** | 트리거와 가드가 먼저 성립하고 마감 안에 행동한 날 **4일 이상** |
| 행동 비율 | **80% 이상** | **80% 이상** |
| 가드 추가로 오른 비율 | 검사 생략 | **가드 적용 비율 − 가드 없는 비율 ≥ 20%p** |
| 우연한 조합을 걸러내는 검사 | 검사 생략 | **단측 이항검정 p < 0.001** |

**행동 비율**은 해당 조건에서 ‘함 ÷ (함 + 하지 않음)’이다. ‘함’이 4건이어도 모두 같은 날이면 날짜 요건은 1일만 충족한다. 사용자 행동 전체를 분모로 삼지 않으므로, 평일에 간혹 맥주를 마셔도 금요일 규칙에서 감점하지 않는다. 별도의 ‘최소 기회 6회’ 조건도 두지 않는다.

**가드 없는 후보부터 검사한다.** 같은 트리거·행동 쌍에는 가드 없는 후보가 하나다. 날짜와 행동 비율을 통과하면 즉시 채택한다. 이때 가드를 붙인 효과를 비교하면 자기 자신과 비교하게 되므로 20%p와 이항검정을 적용하지 않는다. 이 예외는 **해당 쌍에서 가드 조합을 탐색하지 않는다**는 범위에 해당한다.

**가드를 붙일 때만** 두 검사를 추가한다. 상승 폭은 현재 탐색에 남은 해당 트리거 기회에서 가드 적용 여부에 따른 차이다. 20%p는 예컨대 65%에서 85%로 오른 차이다. 이항검정의 기준 확률은 **현재 남은 기회 전체의 기본 행동 비율**이며 하한은 0.01이다. ‘이 기본 확률에서도 관찰만큼 또는 그보다 많은 성공이 나올 수 있는가’를 한쪽 방향으로 계산한다. 코드로 표현하면 성공 수는 가드 안에서 행동한 횟수, 시행 수는 그 가드 안에서 결과를 확인한 기회 수다.

**트리거가 없었던 같은 길이 구간의 행동 비율**도 비교용으로 기록한다. 1차 버전의 탈락 기준에는 넣지 않는다. 예를 들어 평소 물을 자주 마셔도 ‘귀가’ 때 물을 마시는 비율 자체가 80% 이상일 수 있다. 트리거 후보가 여럿일 때 이 참고값을 함께 볼 수 있다.

### 계산 예시 — 매일 밤 11시대에 TV를 켠 경우

4주 동안 서로 다른 28일 모두 밤 11시대에 TV를 켰고, 서로 다른 금요일 4일에만 뒤이어 맥주를 마셨다고 가정한다. 다른 기회는 모두 관찰됐고 로봇 개입은 없다.

| 검사 | TV 켜짐 | TV 켜짐 + 금요일 |
|---|---:|---:|
| 일치 날짜 | 4일 | 4일 |
| 행동 비율 | 4/28 ≈ 14.3% | 4/4 = 100% |
| 가드 효과 및 이항검정 | 검사 생략. 80% 미달 | 약 85.7%p 상승. 기준 확률 4/28에서 4회 모두 성공할 확률은 (4/28)⁴ ≈ 0.000416 |
| 판정 | 가드를 탐색한다 | **채택** |

최종 규칙은 **트리거 ‘TV 켜짐’, 가드 ‘금요일’, 행동 ‘맥주 가져다주기’**다. 모든 기회가 같은 시간대이므로 ‘밤 11시대’를 더해도 추가로 구별되는 날이 없다.

### 가드 조합 선택과 남은 기회 재탐색

1. 가드 없는 규칙이 탈락하면 허용 어휘에서 **단일 가드 전부**를 시험한다. 통과한 단일 가드가 없을 때만 **두 개 조합**을 시험한다. 최대 두 개다.
2. 같은 탐색 단계에서 통과한 후보 중 **맞춘 행동 수가 가장 많은 후보**를 선택한다. 동점이면 가드 수가 적은 것, 시간·장소·기기 가드를 이력 가드보다 우선하는 것, 행동 비율이 높은 것 순서로 정한다.
3. 선택한 규칙이 다루는 기회 전체를 빼고, 남은 기회로 기본 비율을 다시 계산해 같은 순서로 탐색한다. 스포츠 채널 규칙 하나로 설명될 수도 있고, 금요일 규칙과 화요일 규칙이 따로 나올 수도 있다. 아무것도 통과하지 않으면 보류한다.
4. 규칙이 없는 상태에서 사용자가 직접 한 행동도 기록한다. 서로 다른 날 4일 이상 쌓이면 새 후보를 탐색한다. 기존 규칙의 범위 밖에서 한 행동과, 기존 규칙이 늦어서 사람이 먼저 한 경우를 구분한다.

## 5. 다음 날 실행하고 밤에 보정한다

**트리거 감지 → 가드 확인 → 실행 직전 필수 확인(재고, 사용자가 이미 시작했는지, 대상 상태) → 확인이 끝나면 추가 대기 없이 실행.** 이것이 1차 버전의 ‘즉시 실행’이다. 사람이 기다렸던 시간을 복사하지 않는다. 로봇의 이동·준비 시간을 계산해 출발 시점을 앞당기는 기능은 후속 버전에서 다룬다.

- 같은 행동의 규칙이 동시에 여러 개 발동해도 한 번만 실행한다. 같은 날 같은 시간대에 같은 트리거가 다시 와도 첫 신호에서만 이 행동을 판단한다. 사람이 먼저 시작하면 로봇은 취소하고, 사람이 전이를 끝내면 다음 상태로 넘어간다.
- 상태마다 신호 누락에 대비한 제한 시간(예: 식사 중 2시간)을 둔다. 만료 시 기본 상태로 복귀한다. 시간 만료를 식사 종료나 도움 실행의 증거로 쓰지 않는다.
- 미확정 규칙은 되돌리기 쉽고 비용·안전·건강 영향이 작은 행동만 시험할 수 있다. 맥주·간식처럼 건강 관련 행동은 **규칙 확정 후에만** 실행한다.

| 사용자 반응 | 보정 |
|---|---|
| 실행을 되돌림 | 오개입 가능성을 기록한다. 반복되면 가드를 재탐색하고, 계속되면 규칙을 중단하고 재관찰한다. |
| 로봇보다 먼저 시작함 | 취소하고 늦은 실행으로 기록한다. 반복되면 행동 전에 나타난 다른 시작 사건을 시험한다. |
| 제공한 물건을 사용함 | 도움이 됐다는 근거로 기록한다. |
| 그대로 두거나 반응 불명 | 성공 여부를 미확인으로 둔다. 로봇이 대신한 기회는 사람의 자연 행동을 학습하는 분자·분모에서 제외하고 반응 기록만 남긴다. |

## 6. 검증 기록과 다음 시험

**가드 탐색 시뮬레이션 — 사용자 제공 결과.** 가상 기록에서 가드 탐색 시 단측 이항검정(p < 0.001)을 추가하면 무작위 행동 시나리오의 가짜 규칙이 시드 50개 중 20~24회에서 1회로 줄었다. 이 기준은 가상 기록에서 비교해 선택한 1차 기준이며, 수백 개 조합 탐색의 전체 오류율을 보장하지 않는다. 기본 비율과 가드를 같은 자료에서 구하므로 엄밀한 검정이 아니라 우연한 조합을 걸러내는 실용적 필터로 쓴다.

사용자 제공 결과에서는 진짜 규칙의 탐지가 대체로 유지됐다. 스포츠 채널, 운동 후 물, 손 씻기(가드 없음), 아침 커피 규칙이 검출됐다. **이 시뮬레이션의 아침 커피 조건은 이전 어휘인 ‘근무일/휴일’로 실행했다.** 1차 설계에서 쓰는 달력 기준 ‘평일/주말/공휴일’로 재시험한 결과는 아직 없다. 드문 금요일 맥주 습관은 6주에서 탐지율이 낮고 12주에서 높았다. **건조기 사용의 두 조건(비·수건)도 6주에서는 탐지율이 낮았고, 12주에서는 대체로 검출됐다.** 문서 갱신 과정에서 시뮬레이션 자체를 다시 실행하지 않았다.

| 구현 확인 항목 | 통과 조건 |
|---|---|
| 사실 추출과 시점 조회 | 같은 시간대에 두 번째 TV 신호가 와도 첫 신호 시각의 값을 유지한다. ‘이미 함’, ‘관찰 불가’, ‘로봇이 대신함’은 성공·실패 양쪽에서 제외하고 각각 건수를 남긴다. |
| 규칙 채택과 반복 탐색 | 가드 없는 후보는 두 검사만, 가드 있는 후보는 네 검사를 통과한다. 금요일 예시의 수치와 최종 가드를 재현한다. |
| 사람·로봇 작업 흐름 | 사람이 먼저 꺼내면 로봇의 꺼내기 작업이 사라지고, 다음 전이를 사람 또는 로봇이 이어서 수행할 수 있다. |
| 고정한 규칙 재생 | 올바른 실행·오개입·놓침·대기를 집계하고, 행동이 일치한 기회마다 사람이 실제로 시작한 시각과 로봇이 움직이기 시작한 시각의 차이를 따로 기록한다. |

**재생에서 두 가지를 따로 채점한다.** 행동별 결과 인정 마감 안에 같은 행동이 뒤따르면 ‘행동 적중’ 1건이다. 그때 얼마나 일찍 움직였는지는 **사람의 실제 행동 시작 시각 − 재생에서 로봇이 움직이기 시작한 시각**으로 구한다. 예를 들어 마감이 30분이고, 19:00 세탁 종료 때 로봇이 바로 움직였으며 사람이 19:28에 빨래를 꺼내기 시작했다면 **행동 적중 1건, 일찍 개입 28분**이다. 사람의 시작을 확인할 수 없으면 시간 차이는 미측정으로 둔다. 일찍 개입한 시간이 큰 규칙은 후속 버전의 시점 조정 후보로 표시한다. 1차 버전의 실행 순서는 그대로 유지한다.

**냉장고 모델 실험.** 11월 8일 시험은 두 장면을 따로 입력했다. 첫 출력은 ‘경고가 울리면 문 닫기’, 둘째 출력은 행동 규칙 없음이었다. 첫 기록에서 사용자는 10초에 소파에 앉았고 60초에 경고가 울렸지만, 60초의 냉장고 앞 상황은 명시되지 않았다. **60초는 합성 장면에 넣은 가정**이다. 실제 LG 기기가 문 열림을 알리는 시각이나 경고 조건은 사용 기종에서 확인해야 한다.
