# 가전 도움 규칙 1차 구현계획서

2026년 11월 9일 · 구현 전 계획 · 기준 저장소 `noonchi-home/ai`

**목표**는 한 집의 시간순 관찰을 받아, 밤에는 로봇이 맡을 만한 행동과 시작 규칙을 저장하고, 다음 날에는 그 규칙으로 **실행·대기·취소**를 결정하는 것이다. 첫 완성본에서는 가전 로그와 클로이봇 시점의 관찰 문장을 입력하고, 로봇이 맡을 행동을 명령으로 출력한다. 실제 가전 제어는 같은 명령에 기기별 구현을 연결하는 후속 작업이다. 규칙의 정의와 채택 기준은 [가전 관찰에서 도움 규칙 만들기](2026-11-09_가전_관찰에서_도움_규칙_만들기.md)를 따른다. 이번에 확정한 수집·집계·실행 경계값은 이 계획서 4절에 모았다.

**첫 산출물**은 계산 검사용 금요일 TV 예시의 28일 기록을 넣었을 때 나오는 **기회 28건, 금요일 가드, 채택 이유, 다음 금요일의 판단 한 건**이다. 처음부터 모델까지 연결하면 잘못된 규칙의 원인이 관찰 해석인지 집계인지 알기 어렵다. 먼저 사실이 확정된 입력으로 이 흐름을 끝까지 통과시키고, 같은 입력 형식을 모델이 채우게 한다.

## 1. 관찰 입력과 코드 변경 범위

**관찰 주체는 사용자를 따라다니는 클로이봇이다.** 입력은 이동하는 로봇의 시야에서 얻은 시간순 관찰과 가전이 직접 보낸 신호다. 로봇이 떠난 장소의 현재 상황을 마지막 장면만으로 단정할 수 없다. 특히 **욕실 내부는 관찰 불가**다. 욕실 안의 행동을 직접 봤다고 기록하지 않는다. 시야가 끊긴 기회의 결과는 4절 ‘마감 전 관찰 공백’ 기준으로 판정한다. 가전이 별도로 보낸 상태값은 출처를 구분해 보존한다.

날씨는 외부 날씨 API에서 받으며 합성 데이터에서는 `weather.json`을 읽는다. 실내 온도는 가전 로그에 30분마다 들어오는 에어컨의 `현재온도` 상태값을 읽는다. 온도 갱신으로 관찰 구간을 만들지 않고, 가드(실행에 필요한 추가 조건)를 조회할 때만 사용한다.

기존 PAM 실험은 각 상태의 `rules`에 행동을 담고, `next`에는 상태 전환 조건을 담는다. 기존 검사기는 이 형식을 엄격하게 확인하며, 기억 저장 코드도 같은 검사기를 쓴다. 새 설계는 **사람 또는 로봇이 수행할 작업 전이 하나에 시작 조건을 연결**한다. 새 형식은 버전을 구분해 별도 실행 경로로 추가한다. 기존 실험과 과거 기억 파일은 현재 명령으로 계속 읽고 검증할 수 있어야 한다. [기존 형식 검사기](https://github.com/noonchi-home/ai/blob/d030470/pam/contracts.py) · [날짜별 기억 저장 코드](https://github.com/noonchi-home/ai/blob/d030470/pam/memory_store.py)

| 위치 제안 | 맡길 일 |
|---|---|
| `pam/` 안의 가전 관찰·기회 집계 코드 | 기기 신호와 모델이 추출한 사실을 같은 시간축에 놓고, 트리거가 발생할 때 코드가 알 수 있었던 값과 이후 행동 결과를 묶는다. |
| `pam/` 안의 규칙 학습·실행 코드 | 밤에는 기회에서 규칙을 고른다. 낮과 재생 시험은 같은 판단 함수를 써서 실행·대기·취소를 결정한다. |
| `scenarios/` 아래 가전 실험 설정 | 집의 기기·물건·장소, 가능한 동작, 직접 연결되는 기기 관계, 시간대와 마감, 행동별 시험 허용 범위를 둔다. |
| `experiments/` 아래 가전 실험과 `tests/` | 앞쪽에는 작은 입력과 사람이 읽을 결과를, 뒤쪽에는 계산값과 상태 변경을 자동 대조하는 검사를 둔다. |

텍스트 사실 추출에는 기존 실험의 Qwen 모델·제공자 설정을 참고한다. 현재 PAM 전송 코드는 역할마다 입력 사진 장수를 검사한다. 가전 관찰 텍스트에는 별도 입력 검사를 두고, 기존 설정 읽기·오류 처리·인증키 보호 로직은 적용 가능한 범위에서 재사용한다. [기존 전송 코드](https://github.com/noonchi-home/ai/blob/d030470/pam/openrouter.py)

구현은 착수 시점의 GitHub 기본 브랜치에서 새 작업 사본을 만든다. 계획 작성 때 원격 기준은 `d030470`이며, 로컬의 기존 사본에는 4일 실험 자료 변경이 있다.

**실행 방법 제안.** 같은 가전용 명령에 세 가지 작업을 둔다. `extract`는 관찰 문장과 가전 로그에서 시각별 사실 파일을 만들고, `learn`은 지정 날짜까지의 사실로 기회 목록·채택 또는 보류 근거·다음 날 적용할 규칙 파일을 저장한다. `replay`는 저장된 규칙과 새 날짜의 사실을 받아 시각별 판단과 채점 보고서를 출력한다. 손으로 검토한 사실 파일도 `learn`에 바로 넣을 수 있게 해, 모델 사용료 없이 집계부터 재시험한다. 세 이름은 구현할 명령의 제안이다.

## 2. 구현 순서와 단계별 합격 조건

| 순서 | 구현할 동작과 결과물 | 다음 단계로 넘어가는 기준 |
|---|---|---|
| **① 사실과 행동의 입력 형식** | 클로이봇이 3초마다 관찰한 내용을 `시각 / 위치 / 문장` 형식으로 한 건당 한 줄씩 읽는다. 같은 문장이 이어져도 모든 줄을 시간순으로 입력한다. 가전 신호는 발생 주체·기기·시각·값을 읽는다. 사람 행동은 시작·완료 시각, 근거 문장, ‘동작 / 대상 / 출발 → 도착’을 저장한다. 먼저 손으로 확인한 작은 입력 파일을 만든다. | 23:00:00, 23:00:03, 23:00:06에 같은 행동이 관찰되면 입력도 세 줄이다. 빨래를 옮겼다는 두 가지 표현은 같은 행동으로 집계한다. 꺼낸 사실만 보인 장면에서 건조기로 옮겼다고 기록하면 실패다. |
| **② 행동과 트리거 후보 만들기** | 기계 신호는 뒤 10분, 사람 조작은 앞뒤 각 10분의 관찰을 읽어 사람이 실제로 한 일을 묶는다. 등록된 동작으로 로봇이 맡을 수 있는 범위를 정한다. 작업 상태 안과 그 상태로 진입한 사건에서 후보를 수집한다. 대신하면 사라질 동작을 제외할 때는 해당 행동의 시작과 구성 동작 기록을 사용한다. | 세탁 종료음은 후보로 남고, 음료를 가져오려고 냉장고로 향한 걸음은 그 음료 가져오기의 시작 신호에서 빠진다. 근거가 없는 동작은 보류된다. |
| **③ 기회 집계** | 후보가 있었던 시각 전체를 찾아 성공과 실패를 함께 모은다. 같은 트리거는 첫 신호부터 60분 동안 한 기회로 묶고 첫 시각을 쓴다. 그 시점까지의 최신 가드 값과 행동별 결과 마감을 저장한다. | 아래 TV 재점등 예시에서 동석자는 ‘혼자’로 고정된다. 행동 비율에는 ‘함’과 ‘하지 않음’만 들어간다. |
| **④ 밤의 규칙 채택** | 확인된 기기 필수 관계는 한 번 관찰해도 채택할 수 있다. 습관은 서로 다른 날짜 수와 비율로 판정한다. 가드 없는 후보부터 검사하고, 통과하지 못하면 단일 가드 전체, 그다음 두 개 조합을 시험한다. 사건 후보가 통과하지 못한 경우 시각 후보를 시험한다. | 금요일, 가드 없는 습관, 이른 시각·예외 시각 사례의 계산을 각각 재현한다. 규칙에는 근거 기회와 보류 사유를 남긴다. |
| **⑤ 작업 흐름과 다음 날 재생** | 관찰된 전이 사이를 상태로 삼고, 로봇 규칙을 수행할 전이에 붙인다. 첫 신호 → 가드 → 재고·사용자 선행·현재 대상 상태 확인 → 즉시 실행 순서다. 사람이 먼저 하면 취소한다. 하위 동작 성공을 확인한 뒤 상태를 넘긴다. | 사람과 로봇이 번갈아 세탁물을 꺼내고 넣어도 하나의 작업 흐름이 이어진다. 동시 발동은 실행 한 번, 하위 동작 실패 시 완료 0건·재시도 0건이며, 사람이 해당 전이를 맡을 수 있다. |
| **⑥ 모델 연결과 전체 검증** | 모델은 허용된 관찰 사실과 값이 변한 시각을 고정 형식으로 출력한다. 코드가 가드를 선택하고 비율을 계산한다. 실제 모델 출력으로 ①~⑤를 다시 거친 뒤, 사람이 확인한 입력으로 돌린 결과와 대조한다. | 같은 기록에서 ‘사실을 잘못 읽어서 생긴 오류’와 ‘사실은 맞지만 잘못 발동한 규칙’을 구별할 수 있다. 기존 PAM 명령의 회귀 검사도 통과한다. |

## 3. 집계·채택에서 그대로 지킬 기준

- **기회 한 건**에는 첫 트리거 시각, 당시 가드 값, 결과 인정 마감, 결과, 근거가 된 관찰을 저장한다. 결과는 ‘함 / 하지 않음 / 이미 함 / 관찰 불가 / 로봇이 대신함’이다. 뒤의 세 결과는 분자·분모에서 모두 빼고 사유별로 센다. ‘이미 함’으로 제외한 날도 실제 행동 시각은 야간 재학습에 쓴다.
- **추가 조건이 없는 규칙**은 서로 다른 4일 이상 일치하고 적중률이 80% 이상이면 채택한다. **추가 조건이 있는 규칙**은 같은 두 기준에 더해 가드 없는 비율보다 20%p 이상 높고 단측 이항검정 값이 0.001 미만이어야 한다. 기준 확률은 해당 트리거 탐색에 남은 기회 전체의 기본 행동 비율이며 하한은 0.01이다. 통계 계산은 독립적으로 계산한 기준값과 경계값으로 검사한다.
- **가드 탐색**은 설계 문서의 고정 어휘만 사용한다. 달력에서 평일·주말·공휴일을 읽고, 개인 출근 여부를 임의로 채우지 않는다. 통과한 후보는 맞춘 행동 수 → 적은 가드 수 → 정해 둔 가드 종류 우선순위 → 높은 비율 순으로 선택한다. 선택한 규칙이 다룬 기회는 같은 트리거의 탐색에서만 빼고, 다른 트리거는 자체 기회로 평가한다. 트리거 없는 비교 구간의 비율은 참고값으로 기록한다.
- **시각 후보**는 최근 12주 안의 모든 생활일에서 행동 시작 시각을 모아 만든다. 서로 다른 4일 중 3일 이상이 폭 30분 안에 모이는 후보 생성 기준을 적용하되, 전체 기록에서 임의의 4일만 추리지 않는다. **가장 많은 서로 다른 날**을 포함하는 30분 구간을 고르고, 동률이면 생활일 기준으로 먼저 오는 구간을 고른다. 그 구간 안의 가장 이른 실제 시작 시각이 트리거다. 습관 규칙 채택에는 별도로 4일 일치와 적중률 기준이 필요하다.
- **시간 누출 방지**를 위해 그날 결과로 갱신한 규칙은 이후 판단부터 사용한다. 재생 전 각 날짜에 사용할 규칙 버전을 고정한다. 같은 입력으로 밤 작업을 다시 실행해도 같은 날·기회가 두 번 늘지 않게 하고, 저장 중 실패하면 직전 완성본에서 이어간다.
- **반응 보정**은 실행을 되돌림, 로봇보다 먼저 시작함, 실제 사용, 반응 불명으로 기록한다. 확정된 규칙은 자연 관찰 일치가 4일 미만으로 줄어도 유지하고, 사용·되돌림 등 반응으로 유지 여부를 판단한다. 늦은 규칙은 앞선 사건을 재탐색하고, 되돌림이 반복되면 가드를 재평가한다. 상태 제한 시간 만료는 기본 상태 복귀로 처리한다. 미확정 행동의 시험 가능 여부는 설정에서 확인하며, 건강 관련 행동은 확정된 뒤에만 실행한다.

## 4. 확정한 구현 기준과 경계 사례

| 항목 | 구현 규칙 | 같은 입력에서 기대하는 결과 |
|---|---|---|
| 반복 신호 | 첫 신호부터 60분을 한 묶음으로 잡는다. 뒤의 반복 신호가 묶음 시작 시각을 갱신하지 않는다. | 22:59와 23:01의 TV 켜짐은 한 기회다. 가드는 22:59 시점의 값으로 고정한다. |
| 관찰 수집 | 합성 데이터와 같이 기계가 낸 신호는 뒤 10분, 사람이 일으킨 신호는 앞뒤 각 10분을 읽는다. | 19:00 기계 신호의 후보 수집은 19:10까지, 사람 조작의 수집은 18:50~19:10이다. |
| 결과 인정 마감 | 행동별 설정을 쓰며 기본값은 트리거 후 30분이다. 마감까지의 후속 기록으로 결과를 판정한다. | 19:00의 기본 마감은 19:30이다. 19:10에 후보 수집이 끝났다는 이유로 ‘하지 않음’으로 처리하지 않는다. |

검증은 **계산 검사 → FSM 학습 확인 → 실행 판단 확인 → 실제 모델 입력** 순서다. 계산 검사는 위 표의 고정 입력과 기대값으로 수행한다.

- **FSM 학습 확인:** 2주 합성 데이터(2026-09-21 ~ 2026-10-04)를 날짜순으로 하루씩 넣고 밤 계산만 수행한다. 날짜별로 채택·보류한 규칙과 그 이유를 기록하고, 14일째 밤의 최종 FSM(작업 상태와 전이별 도움 규칙)을 출력한다.
- **실행 판단 확인:** 14일째 밤의 최종 FSM을 고정한다. 같은 습관 설정과 **다른 시드**(가상 기록 생성의 시작값)로 만든 **새 1주 합성 데이터**(2026-10-05 ~ 2026-10-11)에서 미래 관찰을 가리고 실행·대기·취소를 채점한다. 학습에 쓴 2주 기록은 이 점수에 넣지 않고, 평가 주간에는 규칙을 다시 학습하지 않는다.
- **합성 데이터 생성·인수:** 학습·평가용 합성 데이터는 추후 별도 작업으로 준비한다. 생성할 때부터 클로이봇의 3초 관찰마다 `시각 / 위치 / 문장` 한 줄을 쓴다. 습관과 나머지 데이터 형식은 「합성데이터 인수인계」 문서를 따른다. 학습기나 평가기에 넣기 전에 연속된 동일 관찰도 시각별로 한 줄씩 보존됐는지 검사하고, 가전 로그·날씨 파일, 학습·평가 기간과 시드 구분도 확인한다.
- **실제 모델 입력:** 모델에는 기대 판단을 보내지 않고 요청·응답 원문과 사용량을 기록한다. 기존 냉장고 실험은 두 장면에서 각각 규칙을 생성한 결과이므로, 규칙 하나를 고정한 실행 판단 시험과 구분한다. [이전 냉장고 실험 원문](../../../2026-11-08_fridge-door-two-scenes/a_content.txt)

**1차 완료 조건:** 관찰 입력부터 야간 규칙 저장, 다음 날 실행·대기·취소, 반응 기록까지 한 경로로 재현한다. 각 규칙의 근거 기회와 제외 사유를 확인할 수 있고, 재생 보고서에서 올바른 도움·오개입·놓침·확인 불가와 개입 시차를 따로 볼 수 있어야 한다.

**시드 50개 시뮬레이션 대조.** 시드(가상 기록 생성의 시작값) 50개로 실험한 기존 코드 `sim.py`와 `fix.py`는 이미 작성돼 있다. 두 파일을 전달받으면 기존 ‘근무일/휴일’ 어휘와 원래 설정으로 먼저 실행해 보고된 결과와 대조한다. 그다음 같은 시드로 새 달력 어휘 ‘평일/주말/공휴일’을 적용한 결과를 별도로 기록한다. 기존 보고에서 건조기 두 조건은 6주에서 탐지율이 낮고 12주에서 대체로 검출됐다. 이번 계획 수정에서는 해당 코드를 실행하지 않았다.
