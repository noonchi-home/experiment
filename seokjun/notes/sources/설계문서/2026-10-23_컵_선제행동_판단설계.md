## 1. 논의 목적

사용자의 명령을 기다리지 않고 관측된 생활 상황에서 도움의 필요성을 발견하는 **선제적 행동 판단(proactive decision making)**을 연구한다. 첫 실험은 컵 하나를 대상으로 하며, 판단에 필요한 정보가 부족할 때 추가 관찰을 선택하는 능력까지 검토한다.

핵심 질문은 다음과 같다.

> 시간에 따른 컵 사용 이력과 주변 상황을 받은 AI가 지금 컵을 치울지, 그대로 둘지, 무엇을 더 확인할지 결정할 수 있는가?

기존의 ‘안전 규칙 → 해석 → 제안 → 승인 → 피드백’ 설명은 역할을 나눈 개략 구조였다. 이번 논의에서는 각 역할의 내부에 필요한 입력, 추정, 행동 선택, 평가 방법을 컵 사례로 구체화했다. 그 층별 구조 전체를 확정한 것은 아니다.

## 2. 확정 조건과 제안의 구분

### 2.1 사용자가 명시한 조건

| 조건 | 내용 |
| --- | --- |
| 연구 주제 | 매번 명령을 받지 않는 proactive 판단 |
| 사용자 부담 | 매번 정보를 입력하거나 질문에 답해야 하는 방식은 피함 |
| 첫 대상 | 컵을 치울지 판단하는 상황 |
| 첫 데이터 | 모두 합성 데이터 사용 |
| 초기 모델 이용 | DeepSeek API를 활용해 실험할 계획 |
| 추가 정보 판단 | 결정에 필요한 정보가 부족하면 무엇을 더 확인할지 AI가 선택하기를 원함 |
| 최종 방식 | 계속 논의하며 결정. 현재 로컬 모델·학습·멀티에이전트 구조 미확정 |

### 2.2 Codex가 제안한 초기 실험 방향

다음 항목은 검토할 제안이며, 사용자가 최종 채택한 사양은 아니다.

- 센서가 관측한 결과를 가정한 **시각이 붙은 텍스트·JSON**으로 판단을 먼저 시험한다.
- 같은 모델에서 현재 상태, 시간 이력, 활동 기억, 추가 관찰의 효과를 나누어 비교한다.
- 첫 기준선은 별도 미세조정 없는 모델 호출로 만들고, 반복되는 실패를 본 뒤 학습 여부를 판단한다.
- 단일 모델이 상황 평가와 다음 행동을 구조화해 출력하도록 시작할 수 있다.
- 모델은 의미를 해석하고 행동을 선택하며, 코드는 관측 관리와 실행 조건 검사를 담당하게 한다.

### 2.3 아직 정해야 할 사항

| 미결정 항목 | 결정에 필요한 내용 |
| --- | --- |
| ‘치우기’의 의미 | 수거 위치로 이동, 싱크대로 이동, 세척 중 어디까지 포함할지 |
| 허용된 도움의 범위 | 내용물이 있는 컵, 타인의 컵, 재사용 가능성이 있는 컵을 어떻게 다룰지 |
| 사용 종료 판단 | 어떤 관측 조합과 라벨 기준으로 평가할지 |
| 관찰 도구 | 컵 내부 확인·기록 조회 등 실제로 제공할 합성 도구와 반환 형식 |
| 대기와 재평가 | 어떤 사건이나 시간 간격에 다시 판단할지, 최대 관찰 횟수 |
| 기억 표현 | 사건 이력, 유사 사례, 활동 단계별 기억 중 무엇을 비교할지 |
| 최종 모델 | 로컬 모델의 종류·크기·하드웨어와 API 대비 성능 |
| 학습·구조 변경 | SFT/LoRA, 개입 시점 전용 모델, 멀티에이전트가 필요한지 |

## 3. 판단 문제의 정의

입력은 현재 관측만이 아니라 **현재까지의 관측 이력, 생활 기억, 허용된 도움의 범위, 가능한 행동**이다. 출력은 당장 수행할 다음 선택이다.

```text
현재까지의 관측 + 과거 기억 + 역할·제약 + 행동·관찰 도구
                         ↓
        사용 단계와 재사용 가능성, 미확인 정보 평가
                         ↓
           그대로 두기 / 추가 관찰 / 컵 이동
                         ↓
            새 관측과 실행 결과를 받고 재평가
```

API 자체가 지속적으로 환경을 감시하는 것은 아니다. 실험 프로그램이 새 관측이나 정해진 시점에 모델을 호출한다. 이때 ‘지금 컵을 치워라’라는 사건별 명령은 제공하지 않는다. **모델을 호출하는 시점과 모델이 실제 개입을 선택하는 시점은 다르다.** 호출 결과가 무개입일 수도 있다.

### 3.1 관측 사실과 추정의 구분

| 구분 | 예 |
| --- | --- |
| 관측 사실 | 컵 내부에 액체가 보임, 사람이 컵을 입에 댐, 노트북을 닫음 |
| 관측에서 계산한 값 | 마지막 음용 이후 경과 시간, 같은 컵이 놓여 있던 시간 |
| 추정 | 음료 사용을 마쳤을 가능성, 잠시 자리를 비웠을 가능성 |
| 도움의 기준 | 사용 종료 후 정리를 돕는 것이 허용되는지 |
| 결정 | 지금 그대로 둘지, 더 볼지, 옮길지 |

`컵이 비어 있음`과 `컵 사용이 끝났음`을 동일하게 취급하지 않는다. 전자는 관측할 수 있는 물체 상태이고, 후자는 맥락에서 추정해야 하는 경우가 많다. `사용종료=true`, `치워도됨=true`를 처음부터 입력하면 평가하려는 판단의 답이 노출될 수 있다.

### 3.2 컵 실험의 입력 후보

| 입력 묶음 | 후보 정보 | 판단에서의 역할 |
| --- | --- | --- |
| 물체 | ID, 위치, 내용물, 사람이 잡고 있는지, 관측 시각 | 컵의 현재 상태와 실행 가능성 |
| 시간 이력 | 채우기, 음용, 내려놓기, 이동의 사건과 시각 | 사용 전·사용 중·중단·종료 구분의 단서 |
| 사람·주변 활동 | 재실, 물병을 가져옴, 작업 지속, 노트북을 닫음, 방 이탈 | 재사용 또는 활동 전환의 단서 |
| 과거 기억 | 유사 상황에서 실제로 관측된 재사용·정리 기록 | 개인 생활 흐름에 대한 문맥 |
| 관측 품질 | 출처, 시각, 가림, 판독 불가, 관측 중단 | 모르는 사실과 오래된 사실의 구분 |
| 역할·기기 | 도움의 범위, 이동 목적지, 지원 행동, 관찰 도구 | 선택 가능한 도움의 범위 |

모든 집안 센서를 매번 넣는 것을 목표로 하지 않는다. 첫 실험은 컵 판단에 관련된 정보를 중심으로 구성한다. 합성 텍스트 입력의 성능은 실제 영상 인식 성능까지 검증한 것으로 해석하지 않는다.

## 4. 컵 사례에서의 판단 과정

다음은 **설명용 가상 사례**다. 실제 API 응답이나 확정된 정답이 아니다.

임시 조건은 ‘사용이 끝난 빈 컵을 지정 수거 위치로 옮기는 도움을 허용한다’이다. 내용물 버리기와 세척은 포함하지 않는다. 내용물이 있는 컵을 이동하지 않는다는 조건도 이 예시의 조건이며, 모든 가정에 적용되는 규칙으로 확정한 것이 아니다.

| 사건 | 시각 | 관측 |
| --- | --- | --- |
| E1 | 10:00 | cup_07에 음료가 담김 |
| E2 | 10:10 | 사람이 cup_07로 마심 |
| E3 | 10:12 | 컵을 책상에 내려놓음 |
| E4 | 10:13 | 노트북을 닫고 가방을 들고 방에서 나감 |
| E5 | 10:14 | 컵은 그대로 있으며 내부는 보이지 않음 |

1. **관측 정리:** 같은 컵의 사건을 시간순으로 연결한다. 내용물을 ‘비어 있음’으로 임의 보완하지 않는다.
2. **상황 해석:** 활동을 마쳤다는 가설과 잠깐 나갔다가 다시 쓸 수 있다는 가설을 함께 고려한다.
3. **부족한 정보 확인:** 내용물은 현재 이동 조건과 관련되지만, 재사용 의도는 내부 확인만으로 해결되지 않는다.
4. **다음 선택:** 기다리기와 내부 확인을 비교한다. 방 이탈 직후이므로 내부 확인을 유일한 정답으로 지정하지 않는다.
5. **관찰 후 재판단:** 비어 있어도 재사용 여부를 다시 평가한다. 결과가 판독 불가이면 모르는 상태를 유지한다.
6. **행동 후 확인:** 모의 이동이 수행되었는지와 후속 상태를 확인한다. 호출 성공과 실제 상태 변화는 구분한다.

모델의 판단 기록에는 선택 행동, 근거가 된 관측 ID, 경쟁 가설, 미확인 정보, 추가 확인의 목적을 포함하는 방안을 검토한다. 이 설명은 모델의 내부 사고를 증명하지 않으며, 검토 가능한 출력 기록이다.

### 4.1 추가 관찰 선택의 기준

추가 관찰은 **결과에 따라 이후의 선택이 달라질 수 있는지**, 관찰에 드는 시간·횟수와 지연이 감수할 만한지를 평가한다.

- 현재 조건에서 내용물이 있으면 이동할 수 없다면 내부 확인이 유용할 수 있다.
- 사람이 컵을 잡고 있어서 당장 옮길 수 없다면 내부 확인보다 대기가 적절할 수 있다.
- 같은 정보를 반복 확인하거나 관측으로 알아낼 수 없는 의도를 계속 확인하려 해서는 안 된다.
- 불확실할 때마다 사용자에게 질문하는 방식을 기본 동작으로 두지 않는다.

### 4.2 같은 현재 상태, 다른 시간 맥락

| 현재 관측 | 다른 맥락 | 시험할 판단 |
| --- | --- | --- |
| 책상 위 빈 컵 | 방금 꺼내 놓았으며 음료를 준비함 | 사용 전인 컵을 치우지 않는가 |
| 책상 위 빈 컵 | 방금 마신 뒤 물병을 가져옴 | 재사용 단서를 반영하는가 |
| 책상 위 빈 컵 | 사용 후 활동 전환과 종료 근거가 함께 있음 | 허용된 정리 기회를 발견하는가 |
| 책상 위 빈 컵 | 누가 언제 사용했는지 기록이 없음 | 근거 부족을 인식하는가 |

위 표는 반례 구성을 위한 제안이다. 숨은 정답을 모델이 관측으로 구분할 수 없는 사례에서는 유일한 행동을 강제하지 않는다.

## 5. 모델·코드·기억의 역할

| 구성 | 초기 실험에서 제안하는 책임 |
| --- | --- |
| 데이터 처리 코드 | ID 연결, 시간 정렬, 경과 시간 계산, 관측 누락 보존 |
| 판단 모델 | 사용 맥락 해석, 도움 필요성 판단, 관찰·대기·이동 선택 |
| 외부 기억 | 과거 관측과 유사 사례 제공. 현재 시험 에피소드의 미래는 제외 |
| 실행 검사 코드 | 대상 존재, 행동 지원 여부, 현재 필수 조건 검사 |
| 합성 환경 | 선택된 도구의 관측 결과와 행동에 따른 후속 상태 반환 |
| 평가기 | 정답 기준과 비교하고 오개입·미개입·관찰 비용·지연 기록 |

초기 1·2층은 모델의 상황 평가와 선택에, 3층은 실행 조건 검사에, 4층은 후속 관측과 결과 기록에 대응할 수 있다. 가스 관련 0층은 이번 컵 실험의 범위에 포함하지 않는다.

‘코드가 피해 비용표로 최종 행동을 고른다’는 방식은 확정하지 않았다. 모델 직접 선택과 확률·비용 기준을 사용한 선택은 비교 가능한 설계다. 모델이 출력한 확신 숫자를 검증된 확률로 간주하지 않는다. 수치를 사용할 경우 무엇에 대한 확률인지 정의하고 별도 데이터로 보정 정도를 평가한다.

사용자가 컵을 되돌려 놓았다는 관측도 그 자체로 ‘AI의 이전 판단이 틀렸다’는 라벨은 아니다. 선호 변경, 상황 변화, 실행 실패 등 가능한 원인을 후속 근거와 함께 평가해야 한다.

| [PAM — An Agentic Framework for Proactive Robots with Procedural Assistance Memory](https://arxiv.org/html/2610.21211v1) | 활동 단계별 기억과 최근 관찰로 행동/NO_ACT 선택. 판단 가중치 대신 외부 기억 갱신 | 주요 평가는 한 사람의 짧은 책상 루틴. 로봇 실행기는 별도 학습. 선택적 추가 관찰을 검증한 결과가 아님 |
| [Proactive Physical AI through Continuous Observation and Timely Intervention](https://arxiv.org/html/2610.16967v1) | 개입 시점 모델을 학습하고 응답·행동 생성과 구분 | 컵 정리의 직접 검증이 아니며, 현재 확인 범위는 최신 사전공개 연구 |
| [Proactive Robot Assistance via Spatio-Temporal Object Modeling](https://proceedings.mlr.press/v205/patel23a.html) | 합성 가정의 물체 배치 이력으로 학습하여 선제 이동을 예측 | 미래 위치 예측과 현재 정리 허용 여부는 다름. 현재 사람 활동·물체 상태의 한계 |
| [ContextAgent](https://arxiv.org/html/2505.14668) | 상황에서 선제 서비스와 도구 호출을 판단하는 SFT/LoRA 접근 | 예시 프롬프트만 쓰는 ICL 비교군과 학습한 주 모델을 구분 |
| [Horvitz, Principles of Mixed-Initiative User Interfaces](https://www.microsoft.com/en-us/research/publication/principles-mixed-initiative-user-interfaces/) | 불확실한 의도 아래에서 행동·무개입·질문의 이익과 비용 비교 | 일정관리 사례의 이론적 참고. 질문을 컵의 자동 관찰로 바꾸는 것은 별도 설계 |

PAM의 CoRL 2026 표기는 저자 페이지와 arXiv에서 확인한 수준이며, 별도 공식 학회 목록·수상·독립 재현은 확인하지 않았다. 최신 논문과의 관련성이 높다는 이유로 일반 가정에서 검증된 해결책이라고 해석하지 않는다.

Codex는 PAM을 활동 맥락 표현의 우선 참고 후보로 제안했다. 논문 조합을 확정한 것은 아니며, **추가 관찰의 선택 능력은 별도 검증 대상**으로 남는다.

## 7. 합성 데이터와 평가 설계 제안

### 7.1 한 장면 대신 진행하는 에피소드

합성 환경의 전체 상태와 모델에게 현재 공개한 관측을 분리한다. 모델이 관찰 도구를 선택하면 환경이 해당 시점의 결과를 돌려준다. 모델이 관찰 결과까지 스스로 지어내도록 하지 않는다.

```text
현재까지의 관측 제공 → 다음 행동 선택 → 관찰 또는 모의 행동
       ↑                                      ↓
       └────────── 환경의 새 결과 반환 ────────┘
```

상태는 시간과 행동에 따라 변해야 한다. 컵을 이동한 경우와 그대로 둔 경우에 동일한 미래 기록을 붙여서 실행 결과처럼 평가하지 않는다. 관찰 이후 실행 전까지의 변화, 중복 실행, 관측 예산도 고려한다.

### 7.2 라벨 원칙

- 관측이 충분한 사례에는 허용 행동과 적절한 개입 시점 구간을 표시한다.
- 관측만으로 구분 불가능한 사례에는 허용 가능한 선택 집합이나 추가 정보 필요성을 표시한다.
- 생성기가 알고 있는 숨은 의도를 모델이 반드시 맞혀야 하는 답으로 사용하지 않는다.
- 기억에는 이전 에피소드에서 얻은 기록만 사용하며 현재 시험의 미래를 넣지 않는다.
- 같은 모델이 상황·정답·평가를 모두 만들어 자기 기준으로 평가하지 않도록 라벨 기준을 독립 검토한다.
- 문장만 바꾼 동일 템플릿이 학습과 시험에 섞이지 않도록 에피소드·루틴 단위로 분리한다.

### 7.3 비교 조건

| 조건 | 제공 정보 | 확인할 효과 |
| --- | --- | --- |
| A | 현재 상태 | 현재 장면만으로 가능한 판단 |
| B | A + 시간순 사용 이력 | 시간 맥락의 효과 |
| C | B + 과거 활동 기억 | 생활 흐름 기억의 효과 |
| D | C + 추가 관찰 도구 | 선택적 정보 획득의 효과와 비용 |

모델, 도움의 범위, 물리 행동 목록, 판단 출력 형식을 동일하게 두고 비교한다. D에만 추가한 관찰 도구의 정보량·비용 차이를 명시한다. 단순 시간·상태 규칙도 비교군으로 검토한다.

### 7.4 평가 항목

| 항목 | 평가할 질문 |
| --- | --- |
| 너무 이른 개입 | 아직 사용하는 컵을 치우려 하는가 |
| 놓친 도움 | 적절한 정리 기회가 있었는데 계속 방치하는가 |
| 개입 지연 | 허용된 시점부터 실제 선택까지 얼마나 늦는가 |
| 관찰 선택 | 결정에 영향을 주는 정보를 요청하는가 |
| 관찰 비용 | 불필요하거나 반복되는 확인이 얼마나 있는가 |
| 근거 사용 | 다른 컵의 이력, 오래된 관측, 없는 사실을 근거로 쓰는가 |
| 일관성 | 같은 입력을 반복했을 때 선택이 얼마나 달라지는가 |
| 상태 갱신 | 실행·관찰 결과에 맞춰 판단을 바꾸는가 |

일시적 자리 비움, 재사용, 여러 컵, 가림·누락, 관측 충돌, 생활 습관 변경, 긴 무개입 구간을 포함한다. 모든 상황에서 기다리는 모델이 좋은 성능으로 평가되지 않도록 정리가 필요한 사례를 함께 둔다. 구체적인 사례 수와 수치 합격 기준은 미정이다.

## 8. 모델 학습과 멀티에이전트에 대한 현재 입장

로컬 모델 사용과 추가 학습 여부는 별개의 선택이다. API에서 로컬 모델로 옮긴다고 자동으로 컵 판단을 잘하게 되는 것은 아니며, 처음에 추가 학습을 하지 않는다는 제안도 최종 제품을 학습 없이 만든다는 결론은 아니다.

| 반복되는 실패 | 우선 검토할 개선 |
| --- | --- |
| 필요한 관측이 입력에 없음 | 관측·도구·이력 구성 개선 |
| 사실은 있으나 시간 흐름을 잘못 해석 | 시간 표현·기억 구조·모델 비교 |
| 충분한 정보에서도 일관되게 잘못된 개입 | 판단 사례로 SFT/LoRA 검토 |
| 개입 시점과 행동 내용의 성능이 다름 | 개입 시점 전용 모델 분리 검토 |
| 역할 분리가 실제 실패를 줄일 근거가 있음 | 멀티에이전트 비교 실험 검토 |

현재는 어느 개선이 필요한지 판단할 컵 실험 결과가 없다. 모델 종류·가중치 학습·구조 변경을 먼저 확정하지 않는다.

## 9. Claude 검토와 반영 기록

앞선 `#` 요청에서 **Claude Opus 5.5 / XHigh를 실제 호출**하여 Codex 초안을 검토했다. 응답은 `revise`였고, 제공된 원문 질문·출처 메모·초안을 대상으로 했다. Claude가 외부 논문을 직접 열람하거나 실험을 실행한 것은 아니다. 외부 원자료 확인은 Codex가 수행했다.

| 검토 내용 | 반영 또는 판단 |
| --- | --- |
| ContextAgent의 ICL 설명 | ICL이 비교군이며 SFT 주 제안과 다름을 수정 |
| 최신 논문의 성능 해석 | 같은 조건의 기준선과 지표의 의미를 함께 기록 |
| 합성 자료·피드백 선례 | HOMER의 합성 데이터와 PAM의 선택적 사용자 피드백을 명시 |
| 모델 확신 | 기록과 보정 검증을 구분. 자기보고 수치를 필수 실행 기준으로 삼지 않음 |
| 비용표의 필요성 | 검증 데이터 사용이 비용표 필수를 뜻하지는 않으므로 비교 가설로 유지 |
| 모호한 컵 사례 | 기다림도 가능함을 명시하고 재사용 반례를 추가 |

최종 수정 문서는 동일 내용으로 Claude의 재승인을 받은 문서는 아니다. 이번 문서화는 기존 검토 기록을 정리한 것이며 새 Claude 호출은 수행하지 않았다.
