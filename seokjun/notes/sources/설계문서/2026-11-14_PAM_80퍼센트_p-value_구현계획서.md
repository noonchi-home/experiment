## 1. 한 줄 요약

PAM 논문 방식은 그대로 두고, 밤마다 자기반성 모델이 만든 트리거 후보를 80% 검사와 p-value 검사로 거른다. 통과한 후보만 다음 날 로봇(예측 모델)에게 준다. 먼저 혼자 사는 사람의 평일 5일 합성 기록으로 시험하고, 한 장면은 실제 영상으로도 시험한다.

## 4. 기록

예시는 읽기 쉽게 우리말로 적었다. 실제 기록은 영어다.

### 4.1 원본 기록

- 형식: `시각 | 문장`. 위치와 상태는 적지 않는다.
- 일정한 간격으로 한 줄씩 적는다. 같은 문장이 이어져도 합치지 않고 그대로 남긴다. 합성 기록은 2초마다, 실제 예측 모델은 1초마다 적는다.
- 원본은 지우지 않는다. 새 후보가 생기면 지난 날짜에서도 다시 찾기 때문이다.

### 4.2 합성 기록 (이번 시험용)

- 혼자 사는 사람의 평일 5일, 하루 16시간(07:00~23:00), 2초마다 한 줄 → 하루 28,800줄, 모두 144,000줄
- 사람이 한 일만 적는다. 로봇이 먼저 도운 장면과 그에 대한 사람 반응은 넣지 않는다.
- 같은 일을 여러 표현으로 섞어 쓴다. 예: "휴대폰을 본다", "폰 화면을 보고 있다", "스마트폰을 들여다본다"
- 정답(어느 게 진짜 습관인지, 사건이 실제로 언제였는지, 그때 상태가 무엇이었는지)은 기록에 적지 않고 정답표에 따로 둔다.
- 13가지 경우를 심는다 (7장).

**만드는 방식 (2026-11-15 다시 만듦)**
- 하루를 07:00부터 시간 순서대로 따라가며 한 줄씩 쓴다. 그러면서 컵에 물이 있는지(식탁·책상·소파), 손에 숟가락과 젓가락 중 무엇을 들었는지, 밥을 다 먹었는지, 방 불·스탠드·노트북이 켜졌는지, 손님이 와 있는지를 기억한다. 그래서 치운 컵으로 마시거나, 다 먹은 뒤 또 먹는 줄이 나오지 않는다.
- 다 만든 뒤 앞뒤가 안 맞는 줄을 찾는 검사를 따로 돌린다. 5일 모두 0개였다.
- 다시 만든 이유: 예전 7일 기록은 숟가락을 저녁마다 딱 한 번만 내려놓았고, 다 먹은 뒤에도 "저녁을 먹는다"가, 컵을 치운 뒤에도 "컵으로 물을 마신다"가 나왔다(사용자가 찾음). 실험 ①(코드 확인)에는 문제가 없지만, 실제 AI가 기록을 읽는 실험 ②에서는 AI가 틀려도 기록 탓인지 AI 탓인지 가릴 수 없다.

### 4.3 한 일 목록 만들기 (밤 ①)

- 같은 뜻의 줄이 이어지면 하나의 일로 보고, 시작과 끝을 한 줄씩 적는다. 예: "물 마시기 (시작)", "물 마시기 (끝)"
- 줄 한두 개(4초 이하)인 짧은 일은 한 줄만 적는다. 예: "숟가락을 내려놓는다"
- 다른 일이면 아무리 짧아도 새 줄을 쓴다. "아침을 먹는다" 같은 큰 묶음은 만들지 않는다. "내려놓는다", "연다", "앉는다" 같은 짧은 동작이 사라지면 자기반성 모델이 그걸 후보로 쓸 수 없기 때문이다.
- 같은 뜻인지는 AI가 판단한다. 표현이 매 줄 조금씩 달라지기 때문이다.
- 결과 형식: `시각`, `종류`(시작 start / 끝 end / 짧은 일 moment), `내용`
- 기록은 1,800줄(1시간)씩 나눠 보낸다. 조각이 끝날 때 아직 이어지는 일은 다음 조각에 "이미 하고 있던 일"로 넘겨서, 다음 조각에서 시작을 또 적지 않고 끝만 적게 한다.
- 이 목록을 자기반성 입력(논문의 사진 200장 + 그날 요약 자리)과 언제 했는지 찾기의 입력으로 함께 쓴다.
- 후보는 늘 이 목록의 순간 하나가 된다. 그래서 "5분을 언제부터 세나"가 헷갈리지 않는다.

지어낸 예:
```
원본
07:49:36 | 사용자가 컵으로 물을 마신다
07:49:38 | 사용자가 물을 마시고 있다
07:49:40 | 사용자가 컵으로 물을 마신다
07:49:42 | 사용자가 숟가락을 내려놓는다
07:49:44 | 사용자가 숟가락을 식탁에 둔다

한 일 목록
07:49:36 | 물 마시기 (시작)
07:49:40 | 물 마시기 (끝)
07:49:42 | 숟가락을 내려놓는다
```

## 5. 밤 단계 자세히

AI에게 주는 일 설명서(프롬프트)는 4장이다(`ai/prompts/text/`). 밤에 AI가 하는 일은 세 가지인데, 자기반성은 첫날(처음부터 만들기)과 둘째 날부터(고치기)가 달라서 두 장으로 나눴다. 논문도 이렇게 나눠 둔다. 논문 원본에서 바꾼 곳은 원본 줄 번호와 함께 `ai/prompts/text/README.md`에 적었다.

### 5.1 자기반성 (밤 ②)

**입력**
1. 로봇 할 일 목록
2. 검사 기준 시간: "후보 뒤 5분 안에 행동이 오면 따라온 것으로 센다". 숫자는 프롬프트에 쓰지 않고 계산 코드의 값(`pam/trigger_check.py`의 `FOLLOW_SECONDS`)이 자동으로 들어간다. 5분을 바꾸면 코드 한 곳만 고치면 된다.

| 규칙 | 출처 |

**출력:** 자기반성 쪽 FSM. 트리거 후보는 목록(최대 3개)으로 받는다. 글에서 "or"를 기준으로 쪼개면 원래 "or"가 들어 있던 신호가 잘못 갈라질 수 있어서다. 예측 모델에 줄 때만 "or"로 합친다.

### 5.2 언제 했는지 찾기 (밤 ③)

**입력:** 상태 설명, 찾을 후보(속한 상태 포함), 찾을 행동, 그날 한 일 목록

**하는 일**
- 후보와 같은 뜻의 순간이 일어난 시각을 모두 적는다. 표현이 달라도 같은 뜻이면 찾는다.
- 후보는 그 규칙이 속한 상태 안에서 일어난 것만 적는다. 상태는 AI가 상태 설명과 앞뒤 순간을 보고 판단한다.
- 같은 후보가 10초 안에 다시 나오면 한 번으로 친다 (고개를 잠깐 돌린 것 같은 끊김).
- 행동은 사람이 그 일을 직접 마친 순간의 시각을 적는다. 하러 가는 동작(집기, 걸어가기)은 행동이 아니다.
- 사람이 안 보인 구간도 적는다.
- 실행기는 아직 모르는 것만 묻는다. 새 후보가 생긴 밤에는 지난 날짜에서도 그 후보만 찾는다. 찾아 둔 시각은 `night-N/marks/`에 날짜별로 저장해 다시 쓴다.
- 횟수를 세거나 계산하지는 않는다. 그건 코드가 한다. 시각을 적게 하는 이유는, 기록 줄을 열어 맞는지 확인할 수 있기 때문이다.

### 5.3 계산 (밤 ④, 코드)

| 항목 | 정한 값 |
|---|---|
| 따라왔다 | 후보 순간부터 5분 안에 사람이 그 행동을 함 |
| 몇 번 나왔나 (n) | 지금까지 기록 전체에서 후보가 일어난 횟수 |
| 몇 번 따라왔나 (k) | 그중 5분 안에 행동이 따라온 횟수. 단, 행동 전에 같은 후보가 다시 나오면 앞의 것은 세지 않는다. 행동 바로 앞의 마지막 후보만 인정한다 |
| 못 봄 | 후보 뒤 5분 동안 사람이 안 보였으면 그 회차는 세지 않는다. 단, 같은 후보가 다시 보였는데 그 사이에 행동이 없었다면 "안 따라옴"으로 확정한다 |
| 80% 검사 | k ÷ n이 0.8 이상이면 통과 |
| p-value 검사 | 행동이 후보와 상관없이 "다른 때 비율"로 일어난다고 칠 때, n번 중 k번 이상 따라올 확률. 0.001보다 작아야 통과 (같으면 탈락) |
| 다른 때 비율 | 후보 뒤 5분이 아닌 시간을 5분 칸으로 나눠, 그중 행동이 들어 있는 칸의 비율. 사람이 안 보인 칸은 뺀다 |
| 바닥값 | 다른 때 비율이 1%보다 작으면 1%로 올려 쓴다. 그래서 최소 2번은 봐야 통과한다 |

- 두 검사를 모두 통과한 후보만 쓴다.
- 이항 계산은 파이썬 기본 기능(`math.comb`, 조합 수를 세는 함수)으로 직접 한다. 외부 부품을 새로 깔지 않는다.

**채택 규칙 (수식)**

```
채택(c → a)  ⟺  k/n ≥ τ   ∧   Σ_{i=k}^{n} C(n,i) · p₀^i · (1 − p₀)^(n−i) < α

                 p₀ = max(p̂₀, ε)

FSM 트리거(a) = ⋁ { c : 채택(c → a) }        (후보는 최대 3개)

τ = 0.8,  α = 0.001,  ε = 0.01,  Δ = 5분
```

- c는 트리거 후보, a는 로봇이 할 수 있는 고정 행동이다.
- n은 c가 일어난 횟수다. 뒤 5분(Δ)을 못 본 회차는 뺀다. k는 그중 5분 안에 a가 왔고, 그 사이에 c가 다시 나오지 않은 횟수다. 예: 수저를 18:57, 18:58, 18:59에 내려놓고 19:01에 그릇을 치우면 n = 3, k = 1이다.
- 이렇게 세는 이유: 로봇은 트리거를 보는 순간 움직인다. 행동 없이 반복된 후보까지 인정하면, 아직 먹는 중인데 그릇을 치우는 규칙이 생기고, 한 번의 행동이 여러 번으로 세져 첫날 밤에 바로 통과해 버린다.
- k/n ≥ τ: 꾸준함 검사 (80% 검사)
- Σ … < α: 우연 아님 검사 (p-value 검사). a가 c와 상관없이 p₀ 확률로 일어난다고 칠 때, n번 중 k번 이상 따라올 확률이다.
- p̂₀는 다른 때 비율, ε는 바닥값이다.
- ∧는 "그리고", ⋁는 통과한 후보를 "or"로 묶는다는 뜻이다.
- 새로 만든 수학이 아니다. 한쪽 이항검정에 꾸준함 기준(τ)과 바닥값(ε)을 붙인 "이항검정 기반 채택 규칙"이다.
- Δ(5분)는 `pam/trigger_check.py`의 `FOLLOW_SECONDS` 한 곳에서만 정한다. 자기반성 입력에도 이 값이 들어간다(5.1).

발표 자료용 LaTeX(수식 입력 형식):
```latex
\text{Adopt}(c \to a) \iff \frac{k}{n} \ge \tau \;\wedge\; \sum_{i=k}^{n} \binom{n}{i} p_0^{\,i} (1-p_0)^{\,n-i} < \alpha,
\qquad p_0 = \max(\hat{p}_0,\ \varepsilon)
```

### 5.4 예측 모델용 FSM (밤 ⑤, 코드)

지어낸 예:
```
자기반성 쪽 규칙:   후보 [물을 다 마신다, 아침을 다 먹는다, 휴대폰을 본다] → 컵을 식기세척기에 넣기
검사 결과:          통과 / 통과 / 탈락
예측 모델용 규칙:   물을 다 마신다 or 아침을 다 먹는다 → 컵을 식기세척기에 넣기
```
- 예측 모델은 논문 형식의 FSM을 그대로 받는다. 트리거는 글 한 줄이다.
- "휴대폰을 본다"는 지우지 않고 자기반성 쪽 FSM에 남겨, 다음 날 밤 다시 검사한다.

| 처음 며칠에 겹친 우연 | [저녁 휴식] 전화가 매일 17:35~17:43에 옴. 1·2일째에만 통화 뒤 2~4분 안에 캔을 소파 옆에 가져옴 | 2일째 밤 채택 → 3일째 밤 빠짐 | 아니요 (기준의 약점) |
| 반쯤 하는 일 | [공부] "노트북을 닫는다" → 1.5~3분 뒤 책을 보관 장소에 넣음. 1·3·5일째만 | 끝까지 탈락 (5일째 밤 60%) | 아니요 |
| 하루에 몰림 | 4일째 [저녁 휴식]에만 손님이 와서 캔을 3번 다 마심 → 매번 빈 캔을 보관 장소에 넣음 | 4일째 밤 채택, 계속 남음 | 아니요 (기준의 약점) |
| 처음 본 행동 | 5일째에만 청소기를 다 돌리고 → 1.5~3분 뒤 책장에서 책을 꺼내 옆에 둠 | 끝까지 탈락 (1번뿐) | 모름 |
| 원래 자주 하는 행동 | 마실 것을 하루 7~8번 가져옴 (다른 때 비율 약 5.8%). [공부] "책상에 앉는다" 뒤에는 5일 중 4일 가져옴 (3일째 빠짐) | 5일째 밤 채택 (5번 중 4번). 2일째 밤은 2번 중 2번이어도 p-value에서 떨어짐 | 예 |
| 못 봄 | [외출 준비] "가방을 멘다" → 방 불 끄기. 매일. 3·5일째엔 메자마자 나가서 끄는 게 안 보임 | 2일째 밤 채택, 계속 유지 | 예 |
| 행동의 일부 | 모든 행동 앞에 그 행동을 하러 가는 줄이 있음 (예: "빈 그릇을 집는다", "컵을 들고 주방으로 간다") | 예측 모델용 FSM에 들어가면 실패 | 아니요 |

- "처음 며칠에 겹친 우연"과 "하루에 몰림"은 우리 기준으로는 규칙이 되지만 진짜 습관은 아니다. 코드가 틀린 게 아니라 기준의 약점이다. 그래서 정답표에 두 칸을 다 적어 구분한다.
- "원래 자주 하는 행동"은 p-value가 실제로 걸러내는지 확인하려고 넣었다. 마실 것을 원래 자주 가져오는 사람이라, 2번 중 2번만으로는 우연과 구별되지 않는다.
- 고정 행동 10개 중 "스탠드를 보관 장소에 넣기"를 뺀 9개가 쓰인다.
- 심어 둔 행동은 모두 후보 뒤 5분 안(대부분 1~4분)에 온다. 그래서 위 예상은 5분 기준일 때 맞다. 기준 시간을 바꾸면 예상도 다시 따져야 한다.
- 정답표로 돌리기에서 4초보다 긴 후보(예: 휴대폰 보기)는 끝난 순간으로 센다.
- 실제 AI로 돌릴 때는 후보를 자기반성 모델이 낸다. 심어 둔 후보가 아예 후보로 안 나오면 "후보로 안 나옴"으로 따로 적는다. 계산이 틀린 것과 구분하기 위해서다.
- 2026-11-15에 바꾼 것: 7일 → 평일 5일. "후보 둘이 같이 통과"의 두 번째 후보를 숟가락에서 냅킨으로 바꾸고, 숟가락은 현실처럼 자주 내려놓게 해서 "행동 없이 반복된 후보"로 옮겼다. "처음 본 행동"은 스탠드 치우기에서 책 가져오기로 바꿨다. 스탠드를 치우면 그날 밤 책 읽을 때 켤 수 없어서다.

- 1번(합성 기록 생성기)은 2026-11-15에 평일 5일로 다시 만들었다 (4.2). 다시 만든 생성기의 검사는 36개다: 줄 형식, 앞뒤 안 맞는 줄 찾기, 현실 숫자(휴대폰·수저·마실 것·식사 시간), 심은 경우마다 위치, 계산 코드로 센 밤별 통과가 7장과 같은지.

### 9.2 실험 (사용자와 같이)

| 순서 | 무엇 | 확인 | 비용 |
|---|---|---|---|
| ① | 정답표로 돌리기, 평일 5일 | AI 자리(한 일 목록 만들기, 자기반성, 언제 했는지 찾기)에 정답표 값을 넣고 코드만 돌린다. 13가지 경우의 밤별 통과·탈락이 7장 표와 같은지 본다. 다르면 코드 탓이다. **끝 (2026-11-15, 평일 5일로 다시): 후보 12개 × 5밤 = 60칸 모두 같음.** 예전 7일 기록에서도 84칸 모두 같았다 | 없음 |
| ② | 실제 AI로 하루씩 5일: 1일째 밤 → 확인 → 2일째 밤 → … → 5일째 밤 | 밤마다 아래 항목. ①에서 코드를 확인했으니, ②에서 표와 다른 부분은 AI 탓이다. **채점은 9.3에서 만든 뒤 시작한다** | 하루 약 $0.28 + 채점 (9.3) |
| ③ | 처음부터 5일 다시 돌리기 (필요할 때만) | 프롬프트나 기준을 바꿨을 때 정답표와 비교한 표 | 한 번 약 $1.4 |

**밤마다 확인할 것 (②)**
- 한 일 목록: 시작·끝 시각이 정답표의 실제 사건과 맞는지, 짧은 동작을 빠뜨리지 않았는지 (자동 채점은 하지 않고, 다른 데서 틀리면 눈으로 본다)
- 자기반성: 상태와 후보가 말이 되는지, 후보가 3개 이하인지, 행동의 일부를 후보로 내지 않았는지
- 언제 했는지 찾기: 찾은 시각이 정답표와 맞는지
- 계산: 통과와 탈락이 7장 표에 적은 그날 밤 예상과 맞는지
- 자기반성이 바꾼 것: 사라진 후보, 새 후보, 약한 후보를 규칙대로 바꿨는지, 바뀐 상태 이름과 설명, 사라진 규칙
- 다음 날 (낮 채점): 그 밤 FSM으로 다음 날 기록에서 로봇이 맞게 돕는지

### 9.3 실험 ② 채점 만들기 (2026-11-15 결정)

실험 ①은 정답표가 AI 자리를 채워서 이름이 글자까지 같았다. 실험 ②에서는 AI가 후보를 자기 말로 쓰고 상태 이름도 직접 지어서 정답표와 바로 비교할 수 없다. 그래서 채점을 따로 만든다. 고른 방식은 "밤 채점 + 낮 채점(무슨 일이 시작되거나 끝날 때만 묻기)"이다.

**밤 채점: 밤에 규칙이 맞게 만들어졌나**
- 짝 맞추기: LLM(Qwen3.5-27B, 다른 AI 단계와 같음)이 AI가 쓴 후보 문장을 정답표의 사건 하나와 짝짓는다. 맞는 사건이 없으면 "없음"이다. 예: "Person finishes the water" → finish_drinking(물을 다 마신다)
- 후보 문구는 바뀌지 않으므로 새로 생긴 후보만 맞춘다. 짝 맞춘 결과는 파일로 저장하고 밤마다 사람이 같이 확인한다. 채점하는 LLM도 틀릴 수 있고, 후보를 쓴 모델과 같은 모델이라 같은 착각을 할 수 있어서다.
- 상태는 LLM이 맞추지 않는다. 후보를 찾은 시각이 정답표에서 어느 상태였는지로 코드가 맞춘다. 여러 상태에 걸치면 "상태 섞임"으로 표시한다.
- 비교 표: 실험 ①과 같은 모양의 "예상과 같음/다름" 표. 찾은 시각이 정답표와 맞는지, "행동의 일부"를 후보로 냈는지, 심어 둔 후보가 아예 안 나왔는지도 표시한다.
- 자기반성이 바꾼 것 표: 전날 밤과 비교해 사라진 후보, 새 후보, 약한 후보를 규칙(3번 이상·80% 미만)대로 바꿨는지, 바뀐 상태 이름과 설명, 사라진 규칙. AI를 부르지 않고 코드만으로 한다.
- 한 일 목록은 자동 채점하지 않는다.

**낮 채점: 그 규칙으로 다음 날 로봇이 맞게 돕나 (논문 방식)**
- N일째 밤 FSM을 N+1일째 기록으로 채점한다. 2~5일째, 4일이다. 5일째 밤 FSM은 6일째 기록이 없어서 낮 채점을 못 한다.
- 언제 묻나: 정답표에서 무슨 일이 시작되거나 끝난 때. 하루 약 580번이다 (정답표로 만든 한 일 목록이 하루 524~622개). 논문은 1초마다 물었다. 그래서 같은 일이 이어지는 중간에 로봇이 괜히 돕는 것은 못 잡는다.
- 예측 모델에 넣는 것: 기록 5줄(지금부터 8초 전까지), 예측 모델용 FSM, 로봇 할 일 목록, 지금 시각. 정답은 넣지 않는다. 일 설명서는 논문 것(`ai/prompts/paper/predictor_fsm.txt`)을 사진 대신 기록 줄을 읽게 고친다.
- 정답: 정답표로 코드가 "물을 때마다 로봇이 해야 할 일"을 만든다. 규칙은 이분법이다 (11장, 2026-11-15 사용자 결정).
- 점수: 논문과 같은 점수(할 일마다 맞은 비율, 잡아낸 비율, 둘을 합친 점수)와 습관마다 "맞게 도움 / 놓침 / 괜히 도움". 논문 점수는 기존 4일 실험 채점 코드(`ai/pam/routine_scoring.py`)를 다시 쓰고, 1초마다가 아니라 물을 때마다 센다.
- 나중에 10초마다 묻기로 늘릴 수 있게, 묻는 간격만 바꾸도록 만든다.

**비용 (추정)**: 밤 채점은 하룻밤 1센트가 안 된다. 낮 채점은 한 번 약 $0.0005(입력 약 1,900토큰, 출력 약 80토큰으로 잡음) × 하루 약 580번 × 4일 = 약 $1.2. 실험 ② 밤 단계 비용(약 $1.4)과 별도다. 만드는 동안에는 AI를 부르지 않는다.

**만들 순서**

| 순서 | 만들 것 | 확인 방법 | 상태 |
|---|---|---|---|
| 1 | 계획서 고치기 (이 절) | 열어서 보여 드림 | 끝 |
| 2 | 자기반성 일 설명서 고치기: "0부터 다시 센다"를 사실대로 고치고, "기존 상태 이름은 글자 그대로 둔다"를 넣음. 설명 문서 표에도 표시 | 바꾼 문장을 보여 드림. 기존 검사 통과 | 끝 |
| 3 | 밤 채점 ① 짝 맞추기: LLM 일 설명서(`ai/prompts/text/matching.txt`), 부르는 코드, 밤마다 새 후보만 묻고 `scoring/matches-night-N.json`에 저장 | 단위 검사 (가짜 LLM 답) | 끝 |
| 4 | 밤 채점 ② 비교 표, 자기반성이 바꾼 것 표 | 실험 ① 결과(평일 5일)에 돌려서 60칸 모두 같음. 손으로 만든 "바뀐 예시"가 다 잡히는지 | 끝 |

| 6 | 낮 채점 ② 예측 모델 일 설명서 글 버전 | 논문 원본에서 바꾼 곳이 설명 문서 표에 다 있는지 | 끝 |
| 7 | 낮 채점 ③ 돌리기(묻기, 저장, 끊기면 이어서)와 채점 | 정답을 그대로 답하는 가짜 예측 모델로 돌려서 100% | 끝 (2~5일째 모두 100%) |

**이번에 하지 않는 것**
- 후보·상태 이름을 코드로 강제로 지키게 하기: 실험 ②에서 실제로 얼마나 일어나는지 먼저 본다. 일어나면 그 밤을 다시 돌려야 할 수 있다(하룻밤 약 $0.28).
- 사람 피드백 넣는 길, 로봇이 도운 뒤 반응 인식: 지금 것을 다 만든 뒤에 붙인다 (2026-11-15 사용자 결정).

### 9.4 실제 영상 끼워 넣기 실험 (2026-11-15 결정)

**목적:** 합성 기록으로는 확인할 수 없는 앞부분을 한 장면으로 확인한다. 앞부분은 "실제 영상 → 예측 모델이 쓴 문장 → 한 일 목록 → 자기반성 → 규칙"으로 이어지는 흐름이다. 지금까지 기록 문장은 생성 코드가 만들었지만, 실제로는 예측 모델이 영상을 보고 쓴다. 그 문장에서도 신호와 행동이 살아남는지가 가장 큰 미확인이다.

**촬영 (팀원에게 부탁, 2026-11-15 보냄):** 책상 장면 하나를 4번, 한 번에 4~5분 찍는다.
- 준비: 책상에 노트북, 휴대폰, 공책, 물컵(물은 반쯤). 빈 컵을 둘 자리(쟁반이나 바구니)를 정해 화면 안에 둔다. 카메라는 고정하고 사람·책상·컵 둘 자리가 한 화면에 나오게, 사람은 혼자.
- 신호: 물을 끝까지 마시고 빈 컵을 책상에 내려놓기. 행동: 신호 뒤 1~3분 안에 빈 컵을 정해 둔 자리에 두기.
- 가짜 신호: 휴대폰 보기(1·3번), 앉은 채로 기지개(2·3번), 공책에 적기, 노트북 타자. 모두 합성 공부 시간에도 자주 나오는 동작이라 80% 검사에서 떨어져야 정상이다.

| 영상 | 순서 (분:초) | 신호 → 행동 |
|---|---|---|
| 1번 | 0:00 타자(물 한 모금) → 1:00 휴대폰 → 1:30 신호 → 타자 → 2:30 행동 | 1분 |
| 2번 | 0:00 공책(물 한 모금) → 1:00 신호 → 1:10 기지개 → 타자 → 3:00 행동 | 2분 |
| 3번 | 0:00 타자(물 한 모금) → 0:50 기지개 → 1:20 신호 → 1:40 휴대폰 → 공책 → 2:50 행동 | 1분 30초 |
| 4번 | 0:00 타자(물 한 모금) → 1:00 신호 → 타자·공책 → 4:00 행동 | 3분 |

- 찍은 뒤 영상마다 신호와 행동의 실제 시각을 받는다. 채점용이고, 모델에는 주지 않는다.

**끼워 넣기**
- 예측 모델이 각 영상을 2초마다 한 문장씩 글로 바꾼다. 논문 쪽 예측 모델과 영상에서 사진 뽑는 코드를 쓴다.
- 그 문장을 합성 1~4일째의 공부 시간(오전 10시 무렵)에 넣는다. 원래 "물을 다 마셔도 컵을 그대로 둔다"가 있던 자리다. 나머지 시간은 합성 그대로다.
- 단계(상태)는 미리 정하지 않는다. 밤에 AI가 하루 흐름을 보고 정하고, 진짜 장면은 앞뒤 합성 기록 덕분에 공부 단계 안에 들어갈 것으로 본다. 채점은 정답표의 시간대([공부])로 한다.
- 밤 단계를 실제 AI로 4일째 밤까지 하루씩 돌린다.

**볼 것**
- "물을 다 마신다 → 컵을 정해 둔 자리에 둔다"가 2일째 밤부터 통과하고 4일째 밤까지 유지되는지
- 가짜 신호(휴대폰, 기지개)를 후보로 냈다면 80% 검사에서 떨어지는지
- 예측 모델이 쓴 문장에 "다 마셨다"와 "컵을 치웠다"가 드러나는지. 드러나지 않으면 그 뒤 단계는 볼 수 없다.

**바뀌는 것과 만들 것**
- 이 실험에서는 [공부]의 "같은 사건, 다른 상태" 경우를 진짜 영상이 대신한다.
- 로봇 할 일 목록에 "컵을 정해 둔 자리에 둔다"가 없다. 이 실험용 목록에만 하나 더 넣는다. 공용 목록(`ai/scenarios/routine/tasks.json`)은 다른 실험이 쓰므로 고치지 않는다.
- 만들 것: 영상을 문장으로 바꾸기, 합성 기록에 끼워 넣는 도구, 촬영 시각으로 정답표 고치기.

**비용과 주의**
- 사진이 들어가서 글만 보낼 때보다 비싸다. 영상이 오면 길이로 단가와 잔액을 확인해 계산한다. 밤 단계는 4일 × 하루 약 $0.28이다.
- 팀원 얼굴이 나오는 영상이 외부 AI 회사(OpenRouter를 거쳐 Alibaba)로 간다. 팀원 동의를 받는다.
- 한 장면만 보는 좁은 시험이다. 하루 전체를 실제 영상으로 해도 잘 된다는 증거는 아니다.

## 11. 남은 결정

**만들 때 이렇게 해 뒀지만 확인이 필요한 것**
- 기록 언어는 영어다. 실제 PAM 기록(예측 모델 출력)이 영어이기 때문이다. 한국어로 쓰면 비용이 늘어난다.
- 후보가 그 규칙의 상태 안에서 일어났는지는 언제 했는지 찾기 AI가 판단한다.
- 다른 때 비율은 하루 전체에서 센다(사람이 안 보인 칸은 뺀다). 상태 안에서만 셀지는 정하지 않았다.
- 기록 조각 크기는 1,800줄(1시간)이다.
- 같은 후보가 10초 안에 다시 나오면 한 번으로 친다.
- 짧은 일의 기준은 4초(줄 한두 개)다.
- 자기반성 입력에 "오늘 로봇은 아무것도 안 했다"고 적는다. 합성 시험용이고, 로봇이 실제로 돕기 시작하면 로봇이 한 일도 입력에 넣도록 고쳐야 한다.
- 합성 기록의 큰 순서는 매일 같고 시각만 몇 분씩 다르다. 주말은 넣지 않았다(2026-11-15 사용자 결정: 평일 5일만). 마실 것을 하루 7~9번 가져온다는 숫자는 조사가 아닌 추정이다.
- 낮 채점의 정답 규칙은 이분법이다 (2026-11-15 사용자 결정). "도와야 함"은 진짜 습관의 신호가 나온 때부터 사람이 직접 하러 움직이기 전까지이고, 그날 사람이 5분 안에 실제로 한 경우만이다. 신호 바로 뒤에 사람이 안 보이게 되면(외출) 신호 순간만 "도와야 함"이다. 나머지는 모두 "도우면 안 됨"이라, 정답표에 심지 않은 습관을 로봇이 도와도 "괜히 도움"으로 센다.

**아직 정하지 않은 것**
- 5분: 임시 값이다. 합성 기록으로 2분·3분·5분을 비교해도 우리가 심어 둔 시간대로 답이 나올 뿐이라 근거가 되지 않는다. 실제 기록에서 "신호 → 사람이 직접 한 행동"까지 보통 몇 분 걸리는지 재서 정한다.
