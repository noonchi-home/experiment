# 선제적 가정 AI 의사결정 — 조사 결과와 Codex 검증 후 의견

작성일: 2026-10-23  
상태: **설계 후보를 검토하는 회의 자료. 최종 구조·모델 선택 아님.**  
구분: 논문 조사, Codex 독립 초안, Codex 내부 반례 검토를 수행했다. **Claude Opus 5.5 / Max 실제 호출과 상호 피드백은 아직 수행되지 않았다.** 사용자에게 실행 가능하다는 안내를 받은 뒤 21:17:48 KST에 재시도했으나 명령 도구가 같은 샌드박스 오류를 반환했다.

DeepSeek API 추론, 파인튜닝, 제품 구현, 실제 가전 제어는 실행하지 않았다. 아래 수치 예시는 설명을 위해 만든 가상 문제의 산술 검산이다.

## 1. 지금 내 의견

**먼저 시험할 대상으로는 ‘상태·기억을 관리하는 시스템 + 한 개의 API 판단 모델 + 관찰·행동 도구 + 실행 결과 확인’을 제안한다.** 다만 이는 출발 기준이며 최종 답이 아니다. 여러 역할, 미세조정, 계획기 추가가 필요한지는 실패 원인을 확인한 뒤 비교하자.

이유는 사용자가 제시한 어려움 상당수가 모델의 크기보다 다음 문제에 걸려 있기 때문이다.

- 무엇이 실제로 관찰되었고 무엇은 추정인지.
- 사람이 지금 어떤 활동을 하고 있으며 그 활동이 계속되는지.
- 무엇이 도움이 되는 행동이고 무엇이 방해인지.
- 어떤 정보를 더 얻으면 결정이 달라지는지.
- 선택한 행동이 실제로 가능한지, 진행 중 다른 일이 생기면 어떻게 바꿀지.

모델을 여러 개 둬도 없는 관측이 생기지는 않는다. 작은 모델을 미세조정해도 잘못 정의된 ‘좋은 행동’이 저절로 고쳐지지는 않는다. 따라서 첫 실험에서 이 문제들을 구분할 수 있어야 한다.

## 2. 무엇이 어려운 문제인가

### 상황 추정, 사람의 목표 추정, 시스템의 행동 선택은 구분해야 한다

‘가스 ON’은 장치 상태다. ‘국을 끓이고 있다’는 활동에 대한 해석이다. ‘조리를 방해하지 않는다’는 시스템의 목표다. ‘지금 유지하고 일정 조건에서 재확인한다’는 정책이다. 네 가지를 하나의 문장으로 합치면 오류가 어디서 생겼는지 알기 어렵다.

과거에 냄비를 올리고 재료를 넣었다는 이력은 조리 의도를 지지한다. 하지만 그것만으로 현재 조리가 계속되는지, 끝났는지, 중단됐는지까지 확정되지는 않는다. 목표 인식 연구는 이 첫 부분에 참고할 수 있고, 지금의 상태 평가와 행동 선택은 이어서 다뤄야 한다.

### ‘선제적’이라는 목표도 두 가지로 시험할 수 있다

여기서는 사용자의 뜻을 **사용자 명령 없이 필요한 일을 발견하고 스스로 개입하는 것**으로 이해했다. 이미 비가 오는 상황에서 창문을 닫는 것도 이 의미에서는 선제적 지원이다.

‘아직 발생하지 않은 문제를 예상해 미리 예방한다’까지 보려면 별도 시험이 필요하다. 현재·과거 정보만으로 미래 상황을 예측하고, 예방 조치의 이득과 잘못 개입한 비용을 평가해야 한다. 미래 프레임을 미리 주는 실험으로 예측 능력을 주장하면 안 된다.

### 아무리 좋은 모델이어도 관찰만으로 구분 불가능한 경우가 있다

두 집의 관찰 이력이 완전히 같은데 주민의 알려지지 않은 선호 때문에 적절한 행동이 다르다고 하자. 같은 입력을 받는 시스템이 두 경우를 항상 구별할 수는 없다. 학습은 일반적인 경향을 줄 수 있지만 그 사람의 현재 속마음을 관측한 것은 아니다.

그러므로 사용자 입력을 최소화하려면 기본 운영 정책, 이미 알려진 선호, 관찰로 갱신 가능한 정보가 필요하다. 매번 질문하는 경로를 기본으로 삼을 필요는 없지만, 정보에 없는 의도를 안다고 가정해서도 안 된다.

## 3. 집안 사례별로 필요한 정보

아래는 합성 실험의 상황 구분이며 실제 가스 설비의 운영 절차를 정한 것이 아니다.

| 상황 | 먼저 명확히 할 것 | 행동을 바꿀 수 있는 정보 | 시험할 실패 |
| --- | --- | --- | --- |
| 비 + 열린 창문 | 어느 창문인지, 지역 강수인지 실제 유입인지 | 창문별 최신 상태·노출·주변 상태·장치 기능·다른 진행 작업 | 모든 창문에 같은 조치, 오래된 상태로 중복 명령 |
| 조리 미관찰 + 가스 관련 장치 ON | 밸브·버너·불꽃 중 무엇의 ON인지 | 최근 조리 사건·현재 기기 관측·활동 경과·관측 사각지대 | 사람이 안 보인다는 이유만으로 조리 종료 단정 |
| 조리 중으로 추정 + ON | 추정 근거가 무엇이고 얼마나 최근인지 | 정상 활동의 지속·완료·중단 및 별도 이상 신호 | 요리면 항상 유지 / ON이면 항상 중단 |
| 안방 먼지 | 바닥 먼지인지 공기 중 입자인지 | 수면·사용 상태·바닥 접근·청소기 상태·예약·작업 충돌 | 먼지 종류와 무관한 청소기 가동, 수면 방해 |
| 여러 사건 동시 발생 | 독립 작업과 자원 충돌 | 실행 시간·장치 공유·마감·이미 진행 중인 일 | 각 판단은 그럴듯하지만 집 전체에서 충돌 |

추가 정보에는 **이미 모은 기록의 조회**와 **새 센서 관측**이 모두 들어간다. 저장된 자료를 충분히 활용하는 것과 카메라를 다시 움직이는 것은 비용·시간·실패 방식이 다르다.

## 4. 입력을 여섯 묶음으로 생각하자

| 입력 묶음 | 담을 내용 | 구분해야 하는 점 |
| --- | --- | --- |
| 현재 관찰 | 대상 ID·위치·값·단위·출처·관찰 시각·도착 시각 | 모름, 가려짐, 관찰되지 않음, 오래됨, 충돌 |
| 이력·기억 | 최근 사건, 상태 지속 시간, 시작·중단·재개, 객체별 사용 이력 | 원 관찰과 모델이 만든 요약·추정 |
| 관계·활동 가설 | 방–물체–장치 관계, 활동 후보와 지지/반박 증거 | 하나의 추정을 사실처럼 굳히지 않기 |
| 목표·운영 정책 | 유지할 상태, 사용자 활동 방해 기준, 우선순위, 허용 범위 | 관찰 사실에서 가치 기준이 자동으로 나오지 않음 |
| 도구·능력 | 조회 가능한 정보, 실행 가능한 행동, 전제조건·효과·시간·실패 결과 | 모델이 상상한 관측과 실제 제공 가능한 관측 |
| 진행 작업 | 요청·시작·진행·완료·실패·중단 요청·확인, 재판단 조건 | 명령 전송 성공과 현실의 목적 달성 |

‘요리 중’ 같은 인지 결과를 입력으로 쓰면 안 된다는 뜻은 아니다. 다른 인지 모듈이 실제로 산출한 추정치라면 정상적인 입력이다. **연구자만 아는 정답을 오차 없는 사실로 제공하는 것**과 구별하자. 완전한 상태를 주는 판단 시험, 오차 있는 추정 상태를 주는 시험, 원 관찰에서 시작하는 통합 시험은 모두 가능하지만 검증 범위가 다르다.

## 5. 판단 과정의 구체적인 후보

아래는 모듈을 모두 구현하자는 지시가 아니라 첫 실험에서 비교할 논리적 흐름이다. 각 단계가 별도 모델이나 별도 API 호출일 필요는 없다.

1. 관찰과 도구 결과를 받아 상태·이력을 갱신한다.
2. 현재 해석과 대안 해석을 구분한다.
3. 방치했을 때 생길 문제와 도움 될 목표 후보를 만든다.
4. 실행 가능한 행동, 추가 관측, 대기, 진행 작업 유지·변경을 후보로 둔다.
5. 후보별 필요한 조건, 예상 이득·손실, 방해·시간·자원 충돌을 비교한다.
6. 행동 전에 해당 결정과 관련된 최신 상태·전제조건을 확인한다.
7. 도구 결과와 실제 완료 여부를 기록한다.
8. 관련 근거가 바뀌거나 재확인 시점이 오면 다시 판단한다.

예를 들어 출력에는 ‘청소 시작’만 적는 것이 아니라 **목적, 대상, 사용한 관찰, 아직 모르는 조건, 선택한 행동, 실행 시점·종료 조건, 재검토 조건**이 있어야 한다. 이것은 관찰 가능한 결정 기록이며 모델의 숨은 내부 사고를 완벽하게 설명한다는 뜻은 아니다.

확인되지 않은 상태를 모델이 숫자 0.93으로 표현했다고 해서 실제 93% 확률이 되지는 않는다. 확률을 쓰려면 무엇의 확률인지, 어떤 데이터로 보정했는지, 분포가 바뀌어도 적용되는지 따져야 한다.

## 6. ‘더 확인할까?’를 어떻게 결정하나

핵심은 **추가 정보가 현재 또는 이후의 행동을 얼마나 개선하는가**다. 모든 불확실성을 줄이는 것이 목적은 아니다.

- 저장된 이력을 다시 읽으면 충분한가.
- 최신 관측을 얻으면 후보 행동이 달라질 수 있는가.
- 기다리면 유용한 정보가 생기는가.
- 관찰하는 동안 생길 지연·방해·비용은 얼마인가.
- 관측이 실패하거나 결과가 여전히 애매하면 어떻게 할 것인가.

관찰과 실행은 반드시 택일할 필요가 없다. 이동하며 주변을 관찰하거나, 진행 중인 작업을 유지하면서 다른 센서를 조회할 수 있다. 처음에는 순차 실행만 시험하더라도 그 단순화를 명시하면 된다.

현재 첫 행동이 같아도 이후 분기를 바꾸는 정보에는 가치가 있다. 예를 들어 두 가설 모두 주방으로 이동해야 하지만 도착 후 해야 할 작업이 다르면 이동 중 이력 조회가 유익할 수 있다.

### 가상 수치로 보는 관찰 가치

아래 숫자는 설명용으로 직접 만든 것이며 실제 가정 데이터·안전 기준·모델 실험 결과가 아니다. 손실이 작을수록 좋은 한 단계 문제다. 대기는 정해진 짧은 평가 구간 동안 청소를 미루는 선택이다.

| 실제 상태 | 지금 청소의 손실 | 기다림의 손실 |
| --- | ---: | ---: |
| 사람이 잠듦: 가상 확률 40% | 20 | 0 |
| 사람이 깨어 있음: 가상 확률 60% | 0 | 5 |

현재 정보로는 청소의 평균 손실이 8, 기다림은 3이므로 기다림을 고른다.

이제 수면 여부를 확인하는 센서가 있다고 하자. 잠든 경우 80%에서 ‘잠듦’, 깨어 있는 경우 10%에서 잘못 ‘잠듦’을 내고, 관찰 비용은 0.5라고 정한다.

이 조건에서는 ‘잠듦’ 결과면 기다리고, 다른 결과면 청소하는 정책의 평균 상태 관련 손실이 1.9다. 관찰 비용까지 더하면 2.4이므로 관찰 없이 기다리는 3보다 낫다. 관찰 비용이 2라면 합계는 3.9가 되어 이 관측은 유리하지 않다. 이 산술은 검산했다.

이 예가 말하는 것은 “확신이 부족하면 무조건 더 본다”가 아니라 **정보를 얻은 뒤 달라질 행동과 관찰의 비용을 함께 비교한다**는 것이다. 확률·손실·센서 성능을 모르는 실제 상황에서 이 숫자를 LLM에게 임의로 채우게 한다고 계산의 신뢰성이 확보되지는 않는다. 환경이 변하는 여러 단계 문제는 더 일반적인 순차 의사결정으로 확장해야 한다.

## 7. 실행 과정에서 놓치기 쉬운 것

**현재 결정의 취소와 실제 동작의 중단은 다르다.** 청소 중단 명령이 늦게 도착하거나 물체를 옮기는 중간 단계라면 즉시 원래 상태가 되지 않는다. ‘중단 요청’, ‘중단 확인’, ‘이미 완료’, ‘실패’를 구분하고 그 결과로 다음 행동을 정해야 한다.

**지연 비용과 응답 기한도 다르다.** 평균 API 응답이 빠르다는 것만으로 정해진 시간 안에 대응한다는 보장은 없다. 시간 제약이 있는 합성 사례에서는 API·관찰 타임아웃과 사전에 정한 대체 정책도 시험해야 한다. 이 문서에서 특정 가스 장치의 대체 제어 규칙을 임의로 정하지 않는다.

**모든 변화에 모든 결정을 취소하지 않는다.** 어떤 관찰·조건에 의존한 결정인지 기록하면 관련 변화에 재평가할 수 있다. 반대 명령을 반복하거나 아무것도 완료하지 못하는 문제도 평가 대상이다.

## 8. 멀티에이전트·파인튜닝·모델 수정에 대한 현재 판단

| 선택 | 무엇에 도움이 될 수 있나 | 지금 확정하지 않는 이유 | 선택이 바뀔 증거 |
| --- | --- | --- | --- |
| 단일 API + 상태·도구·실행 관리 | 먼저 판단의 오류 위치를 측정 | 우리 과제 성능은 아직 모름 | 첫 비교 기준으로 시험 |
| 추가 검토 호출 | 놓친 조건·잘못된 순서 탐지 | 호출 비용 증가, 같은 오해 공유 가능 | 같은 예산에서 오류 감소 |
| 역할별 여러 에이전트 | 독립 정보·전문성·병렬 작업 분담 | 상태 공유·충돌 해결·지연 추가 | 특정 실패를 지속적으로 줄이는 결과 |
| 로컬 모델 SFT/LoRA | 검증된 행동 선택·도구 사용 패턴 학습 | 좋은 기록과 별도 시험 데이터가 아직 없음 | 반복적 실패와 교정 자료, 분리된 평가에서 개선 |
| 명시적 계획기·제약 풀이 | 제한된 상태·행동의 순서·충돌 처리 | 도메인과 효과를 기술해야 함 | 작은 문제에서 LLM보다 정확·효율적 |
| 강화학습 | 여러 단계 결과와 관측 비용 최적화 | 보상과 시뮬레이터 오류의 영향 | 믿을 만한 환경·보상·평가 확보 |
| 모델 구조 변경 | 기존 구조의 확인된 병목 해결 | 실험 비용과 비교 난도 큼 | 더 단순한 방식의 한계가 명확할 때 |

단일 모델도 인지·평가·결정·피드백을 반복할 수 있다. 네 단계로 나눈다고 네 에이전트가 필요한 것은 아니다. 반대로 여러 물리적 기기의 협업을 다룬 논문이 내부 LLM 토론의 효과를 입증한 것도 아니다.

최근 멀티에이전트 비교 연구는 이득이 과제와 협업 구조에 따라 달라짐을 보고한다. 2026년 4월 v3는 260개 구성·6개 벤치마크를 다루지만 가정 자동제어의 직접 검증은 아니다. 따라서 같은 토큰·비용·지연 조건에서 우리 과제의 비교가 필요하다. [Towards a Science of Scaling Agent Systems](https://arxiv.org/html/2512.08296v3)

PARTNR에서는 성공 기록을 학습한 작은 모델의 가능성을 볼 수 있다. 다만 논문의 부분관찰·oracle skill 조건에서 8B 미세조정/70B 모델의 validation 성공률은 .70/.73, test는 .51/.63이다. ‘작은 모델이 큰 모델과 동등’이라고만 요약하면 조건이 빠진다. [PARTNR §4·부록 A.10–A.11](https://arxiv.org/html/2411.00081)

## 9. 먼저 읽을 핵심 자료

‘유명하다’와 ‘우리 문제에 직접 적용된다’를 구분했다. 아래 자료 전체를 조합한 가정 시스템이 이미 검증됐다는 뜻은 아니다.

| 논문 | 확인한 발표·수상 | 가져올 아이디어 | 적용 한계 |
| --- | --- | --- | --- |
| Planning and Acting in Partially Observable Stochastic Domains — Kaelbling·Littman·Cassandra, 1998 | AIJ, **2021 Classic Paper Award** | 보이는 관찰과 실제 상태를 구분하고 정보 획득도 행동 선택에 포함 | 전이·관측·목적 모델을 정하는 일이 남음 |
| Landmark-Based Approaches for Goal Recognition as Planning — Pereira·Oren·Meneguzzi, 2020 | AIJ, **2024 Prominent Paper Award** | 행동 이력과 목표별 필수 중간조건으로 사람의 목표 후보 비교 | 후보 목표·계획 도메인 가정, 현재 활동의 지속을 별도로 평가 |
| Cognitive Architectures for Language Agents — CoALA, 2024 | TMLR 게재 | 기억·내부 행동·외부 행동·결정 순환을 시스템으로 분리 | 개념 틀이며 집안 성능 보장이 아님 |
| ReAct: Synergizing Reasoning and Acting in Language Models, 2023 | ICLR 게재 | 모델 선택→실제 도구 결과→재판단 | 최적 관찰 선택·선제 목표 발견을 자동 보장하지 않음 |
| Between MDPs and Semi-MDPs: A Framework for Temporal Abstraction in Reinforcement Learning, 1999 | AIJ, **2019 Classic Paper Award** | 청소처럼 지속되는 행동의 시작·진행·종료 | 실제 장치의 즉각 취소·복구 가능성과 다름 |
| ContextAgent, 2025 / ProAgent, 2026 수정본 | ContextAgent NeurIPS; ProAgent는 저자 연구실의 IMWUT 채택 공지 확인 | 사용자 명령 없이 맥락으로 지원을 판단, 관측 빈도 조절 | 센서 종류·시선·대상을 일반적으로 선택하는 해법은 아님 |

수상은 [AIJ 공식 기록](https://aij.ijcai.org/aij-awards-list-of-previous-winners/)에서 확인했다. 논문 원문은 [POMDP](https://people.csail.mit.edu/lpk/papers/aij98-pomdp.pdf), [목표 인식 저자 공개본](https://repositorio.pucrs.br/dspace/bitstream/10923/18610/2/Landmarkbased_approaches_for_goal_recognition_as_planning.pdf), [CoALA](https://arxiv.org/html/2309.02427), [ReAct](https://arxiv.org/abs/2210.03629), [Options](https://www.sciencedirect.com/science/article/pii/S0004370299000521), [ContextAgent](https://arxiv.org/html/2505.14668), [ProAgent v2](https://arxiv.org/html/2512.06721v2)다.

목표 인식 논문은 Kitchen을 포함한 15개 기호 계획 도메인에서 시험했다. 가정과 무관하지 않지만 실제 카메라·센서·가스 제어 실험은 아니다. 정답 목표가 후보에 들어 있다고 가정하므로 후보 밖 활동과 목표 변경을 따로 시험해야 한다. 공개된 저자 사전공개본을 읽었으며 저널판 전체와 문장별 대조는 하지 않았다.

ProAgent는 관측 간격을 고빈도 5초/저빈도 60초로 조절하는 구현을 제시한다. 기본 VLM을 LoRA로 학습한 시스템이며 “컵 속을 봐야겠으니 시선을 바꿔라” 같은 일반적인 목적별 관측 계획까지 푼 것은 아니다. 논문 전체 시스템의 개선을 파인튜닝만의 효과로 읽어서도 안 된다. 채택 상태는 [저자 연구실 공지](https://icsl.ee.columbia.edu/proagent-accepted-to-imwut-ubicomp/)를 기준으로 했으며 수상은 확인하지 않았다.

### 그 밖에 용도가 분명한 참고자료

- **Generative Agents:** UIST 2023 Best Paper. 필요한 기억을 회수하고 계획을 갱신하는 발상에 유용하다. 25명 가상 인물의 행동을 다루므로 가정 자동제어의 정확성 검증으로 읽지 않는다. [원문](https://arxiv.org/abs/2304.03442), [공식 수상](https://uist.acm.org/2023/)
- **KnowNo / Robots That Ask For Help:** CoRL 2023 Best Student Paper. 불확실성을 보정하는 기준에 유용하지만 도움 요청 경로를 센서 확인으로 바꾼다고 원래 보장이 그대로 따라오는 것은 아니다. 최소 사용자 입력 요구에 맞는 선택적 적용이 필요하다. [원문](https://proceedings.mlr.press/v229/ren23a.html), [공식 수상](https://www.corl2023.org/awards)
- **Active Perception:** 필요한 정보를 얻도록 센서의 위치·관측을 제어한다는 기초 발상. [Bajcsy 1988](https://people.eecs.berkeley.edu/~yang/courses/cs294-6/papers/Bajcsy.active%20Perception.pdf)
- **BDI Agents:** 믿음, 원하는 상태, 실행하기로 유지하는 목표를 구분하는 구조. [Rao·Georgeff 1995](https://cdn.aaai.org/ICMAS/1995/ICMAS95-042.pdf)
- **Safe RL via Shielding:** 행동을 실행 전에 별도 명세와 대조하는 발상. 명세·환경 모델의 가정 안에서 보장이 성립하며, 검사 코드를 붙인 모든 시스템이 형식 검증된 것은 아니다. [AAAI 2018](https://ojs.aaai.org/index.php/AAAI/article/view/11797)
- **Embodied Agent Interface:** 목표 해석, 하위 목표, 행동 순서, 상태 전이 오류를 나눠 평가하는 참고자료. 논문의 네 평가 항목은 사용자가 제시한 심리학의 네 단계와 동일하지 않다. [원문](https://arxiv.org/html/2410.07166)

## 10. 첫 합성 실험에서 무엇을 검증할까

가장 먼저 **모델에게 보이는 관찰**과 **평가자가 아는 실제 세계 상태**를 분리하자. 모델이 관찰 도구를 고르면 그 도구에 맞는 결과만 추가로 공개하고, 행동이 환경을 어떻게 바꾸는지도 정한다.

사진을 직접 주지 않고 인지 모듈이 만들어 줄 구조화된 관찰을 합성해도 판단 부분을 시험할 수 있다. 이 경우 영상 인지까지 검증했다고 주장하지 않으면 된다.

### 비교할 조건

| 비교 | 확인하려는 것 |
| --- | --- |
| 현재 관찰 / 시간 이력 포함 | 과거 정보가 실제로 필요한 사례에서 도움이 되는가 |
| 단순 행동 출력 / 근거·미확인 조건·후보 구조화 | 형식 변화가 오류를 줄이는가 |
| 추가 관측 불가 / 선택 가능 | 필요한 정보만 얻어 결과를 개선하는가 |
| 실행 피드백 없음 / 있음 | 실패·중단·환경 변화에 적응하는가 |
| 단일 판단 / 추가 검토 / 역할 분담 | 늘어난 호출량과 구분되는 구조의 이득이 있는가 |
| 좁은 규칙·계획 기준선 / LLM 방식 | 쉬운 사례와 복잡한 사례에서 각각 무엇이 유리한가 |

모든 비교를 처음부터 큰 실험으로 벌일 필요는 없다. 우선 몇 개의 손으로 검토한 에피소드에서 입력·행동·결과·평가 기준이 실제로 연결되는지 확인한 뒤 확장하는 편이 좋겠다.

### 꼭 포함할 반례

1. 현재 장면은 같고 이력만 다른 경우.
2. 한 조건만 바뀌어 적절한 행동이 달라지는 경우.
3. 추가 관측으로 구분 가능 / 어떤 관측으로도 당장 구분 불가능한 경우.
4. 요리 시작·일시 중단·재개·완료·목표 변경.
5. 관찰이 늦게 도착하거나 서로 충돌하는 경우.
6. 여러 방의 일이 동시에 생기는 경우.
7. 실행 실패·타임아웃·취소 불가·이미 완료.
8. 아무 개입도 필요 없는 긴 구간.
9. 학습·예시에서 보지 못한 집 구조·물체·상황 조합.
10. 관찰과 행동을 병행하면 유리한 경우.

정답은 반드시 하나의 행동명일 필요가 없다. 허용되는 대안 집합과 근거를 정하고, 입력에서 알 수 없는 사실을 맞히지 못했다고 무조건 오답 처리하지 않는다. 반대로 항상 대기해서 잘못된 개입만 줄이는 방식도 필요한 개입 누락으로 평가해야 한다.

주요 지표는 적절한 개입, 불필요한 개입, 놓친 개입, 추가 관측의 효용, 작업 완료, 충돌·중복, 재판단, 사용자 질문 수, 비용·지연이다. 사건을 골라서 넣는 데이터와 평상시 빈도를 반영한 긴 데이터의 결과도 나눠 보자. 무작위 문장 분할만으로 평가하면 같은 상황 틀의 복사본이 학습·시험에 섞일 수 있으므로 에피소드·상황 조합 단위 분리도 필요하다. 모델 설명의 그럴듯함만을 다른 LLM에게 채점시키는 평가에 의존하지 않는다.

DeepSeek 공식 문서의 도구 호출·구조화 출력 지원은 확인했다. 다만 실제 모델 ID·버전·추론 설정·도구 명세를 고정하고 실행 결과를 봐야 우리 과제의 적합성을 말할 수 있다. [공식 도구 호출 문서](https://api-docs.deepseek.com/guides/tool_calls/)

## 11. 내부 검증으로 보완한 점

Claude의 피드백이 아니라 **Codex 내부 반례 검토**에서 반영한 사항이다.

| 최초 초안에서 더 명확히 할 부분 | 보완한 설명 |
| --- | --- |
| 같은 행동이면 추가 정보가 필요 없을 수 있음 | 첫 행동이 같아도 이후 분기가 달라지면 정보가 유익할 수 있음 |
| 관찰·실행·대기 분류 | 물리적 실행과 관찰은 병행하거나 한 행동에 함께 들어갈 수 있음 |
| 작업 취소 | 요청·중단 확인·완료·복구를 구분 |
| ‘요리 중’ 입력의 누출 우려 | 숨은 정답과 실제 인지 모듈의 추정을 구분 |
| 관측 지연 비용 | 명시된 응답 기한·타임아웃 정책도 따로 시험 |

최초 독립 의견은 별도 파일로 보존했다. 이 문서는 새로운 연구 근거와 내부 검증을 반영한 의견이며, 아직 상대 모델의 반론을 받지 않았다.

## 12. 다음 회의에서 남겨 둘 선택

아직 모델·에이전트 수를 확정하지 않는다. 먼저 다음을 논의할 가치가 있다.

- 첫 실험이 실제로 볼 수 있는 관찰과 사용할 수 있는 행동의 범위.
- 창문·조리·청소에서 무엇을 좋은 결과로 평가할지.
- 추가 관측의 비용, 실패 가능성, 기다릴 수 있는 시간.
- 상태 추정·관측 선택·우선순위·실행 중 변경 중 어디를 핵심 연구 질문으로 삼을지.
- 어떤 실패가 나오면 계획기·추가 검토·미세조정·여러 에이전트를 시험할지.

내 현재 우선순위는 **‘불완전한 시간 이력에서 행동을 고르고, 필요한 경우 행동을 바꿀 정보를 스스로 요청하며, 결과에 따라 다시 판단하는 능력’**을 먼저 측정하는 것이다. 이는 회의용 제안이며 사용자와의 후속 논의, Claude의 실제 독립 의견, API 실험 결과에 따라 달라질 수 있다.
