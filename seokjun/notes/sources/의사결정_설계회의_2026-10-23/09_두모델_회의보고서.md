# 선제적 가정 AI — Codex·Claude 독립 의견과 상호 피드백 보고서

작성일: 2026-10-23. **실제 독립 의견 수령과 상호 피드백 완료. 최종 시스템 구조·모델·학습 여부는 미확정.**

## 1. 이번에 실제로 진행한 일

Codex가 먼저 작성한 의견을 보존한 뒤, Claude에 사용자 요구만 전달했다. 최초 호출은 600초에 시간 초과했고, 같은 모델·설정의 재시도에서 독립 답변을 받았다. 그 뒤 Codex 의견과 Claude 의견을 실제로 교환하고, 구체적인 반례를 두 차례 주고받았다.

- 모델: **Claude Opus 5.5**, 실제 응답의 모델 사용 기록은 모두 `claude-opus-5-5`.
- 설정: 모든 실행 명령에 **`--effort max`**를 전달했다. CLI가 이 옵션을 지원하는 것을 확인했다. 응답은 effective effort를 별도 필드로 반환하지 않아, 설정 근거는 실제 명령 기록이다.
- 인증: Claude 구독. 별도 API 키나 다른 모델로 대체하지 않았다.
- 호출: 총 4회 시도, 1회 시간 초과, **독립 의견·교차 검토·추가 보완의 3개 응답** 수령.
- 독립성: 첫 성공 호출에는 Codex 초안·추천 논문·검토 결과를 전달하지 않았다. 기존 세션을 재개하지 않았고, 프로젝트 파일·검색 도구와 사용자 설정 로딩을 끈 상태로 진행했다.
- 검증 범위: Codex는 원문·공식 수상 자료를 조사했다. Claude는 전달된 글과 자체 지식으로 답했고 외부 검색을 하지 않았다. DeepSeek 실험, 학습, 실제 가전 제어는 하지 않았다.

이번 회의는 [ai-meeting 스킬](~/.agents/skills/ai-meeting/SKILL.md)로 진행했다. [실제 호출 검증 기록](04_실제회의_호출검증.json)과 [전체 전송·응답 기록](~/ai-collab/meetings/20261023-212745-4f2393/TRANSCRIPT.md)을 보존했다.

## 2. 사용자의 문제를 어떻게 이해했나

우리가 만들려는 것은 **사용자 명령을 기다리지 않고, 집안 이력과 현재 관찰을 바탕으로 필요한 일을 찾으며, 판단에 꼭 필요한 정보를 추가로 확인하고, 실행 결과에 따라 결정을 바꾸는 시스템**이다.

‘가스 ON’은 관찰된 장치 상태다. ‘지금 요리 중’은 그 상태와 이력에서 얻은 활동 해석이다. ‘정상 조리를 방해하지 않는다’는 목적이고, ‘유지하되 특정 조건에서 재확인한다’는 행동 정책이다. 이 네 가지를 구분해야 어디서 잘못 판단했는지 알 수 있다.

공통적으로 중요하다고 본 것은 다음이다.

1. **무엇을 알고 무엇을 모르는지:** 현재 장면뿐 아니라 시간 이력·출처·오래된 정보·충돌을 다룬다.
2. **왜 개입할지:** 방치 손실과 불필요한 개입의 손실, 사람의 활동, 여러 작업의 충돌을 비교한다.
3. **무엇을 더 볼지:** 관측 후 현재 또는 이후 행동이 개선되는지와 관측 비용을 함께 본다.
4. **무엇을 실행해도 되는지:** 기기 능력과 사전에 주어진 정책·전제조건을 확인한다.
5. **실행 후 무엇이 달라졌는지:** 명령 전송, 실제 완료, 실패, 중단 요청과 중단 확인을 구분한다.

‘명령 없이 개입’과 ‘아직 생기지 않은 문제를 예측해 예방’은 나누어 평가한다. 첫 실험에서 두 능력을 동시에 검증했다고 주장할 필요는 없다.

## 3. 피드백을 받은 Codex의 의견

**우선 제안:** 상태·기억을 관리하는 시스템 안에 한 개의 API 판단 모델을 넣고, 관찰 도구와 행동 도구의 실제 결과를 받아 재판단하는 구조부터 비교하자.

내가 특히 중시하는 것은 **AI가 어떤 정보를 선택했고, 그 선택 때문에 이후 결과가 어떻게 달라졌는지 측정할 수 있는 실험**이다. 모델에게 ‘어떤 행동이 맞아?’라고 한 번 묻는 것보다, 관측→판단→도구 결과→재판단이 연결되어야 한다.

Claude의 지적으로 책임 분담을 더 분명히 했다. 코드는 상태·기기 명령을 관리하고, 주어진 정책과 전제조건을 검사한다. 모델은 상황 가설과 후보를 만들고 허용 범위 안에서 행동을 선택한다. 외부에서 명시된 기기별 독립 대응 경로가 있다면 API 완료에 의존하지 않게 둔다. 코드가 모든 불확실한 가치 판단을 대신 계산한다는 뜻은 아니다.

또한 같은 입력의 반복 평가와 위험한 개입 누락의 별도 보고를 추가한다. 다만 일관되게 틀리는 경우도 있으므로 일관성은 정확성을 대신하지 않는다. 허용 행동이 여러 개인 경우 답변이 달라졌다는 이유만으로 실패로 보지도 않는다.

추가 관측의 가치는 모델이 작성한 설명만으로 판정하지 않는다. 정해진 합성 세계에서 관측을 허용했을 때와 막았을 때의 실제 행동·결과를 비교하거나, 사람이 검토한 기준으로 확인해야 한다. 작은 계산 가능한 문제에서는 알려진 확률·비용·시간 범위의 정책과 비교할 수 있다.

**내 의견이 바뀔 조건:** 특정 오류가 추가 검토·명시적 계획기·학습·역할 분담으로 실제 줄어들고, 같은 비용·지연 조건에서 이득이 확인될 때 그 복잡성을 도입하겠다.

전체 의견: [Codex 피드백 반영본](08_Codex_피드백반영_의견.md).

## 4. 피드백을 받은 Claude의 의견

아래는 Claude의 003 수정 의견과 004 보완을 Codex가 정리한 요약이다. 원문은 끝의 링크에서 그대로 볼 수 있다.

**우선 제안:** 어떤 모델을 쓰는지보다, **어떤 판단을 모델에 맡기고 어떤 제한을 모델 밖에서 관리하는지**부터 분명히 하자.

Claude는 첫 실험부터 코드의 허용 검사와 독립 대응 경로를 명시하자는 점을 특히 강조했다. 행동마다 주어진 정책에 따른 허용 수준을 두고, 모델이 이를 임의로 바꾸지 못하게 하자는 의견이다. 구체적인 가스 제어 동작은 이 회의에서 만들지 않고 장치 사양·기존 정책에서 받아야 한다고 수정했다.

모델은 보이지 않는 상태에 대한 가설과 근거, 후보 행동, 허용 범위 안에서의 선택, 재판단 조건을 만든다. 코드는 범위를 벗어난 선택을 거부하고 이유를 돌려준다. 초기의 ‘LLM이 확률·비용을 쓰고 코드가 최종 계산’이라는 제안은 철회했다.

추가 관측은 결정 관련성, 상태 구분 능력과 최신성, 시간 제약, 실패 가능성, 시간·방해·사생활 비용을 함께 비교하자고 보완했다. ‘기록 조회부터 무조건 시작’하는 순서는 채택하지 않는다. 사용자 질문을 적게 하는 목표는 유지하되, 침실 카메라처럼 질문보다 비용이 클 수 있는 관측도 고려해야 한다고 했다.

첫 비교에서는 관측 선택 가능 여부, 시간 이력 여부, 코드 허용 검사 여부를 우선하자고 권했다. 반복 일관성, 위험 누락, 평상시의 시간당 불필요한 개입을 각각 보자는 의견이다. 여러 에이전트와 미세조정은 실패 원인을 확인한 뒤 정하며, 로컬 모델이라는 이유만으로 학습을 먼저 하자는 기존 주장은 철회했다.

**Claude가 남긴 미확정 사항:** 장치별 실제 동작, 행동의 허용 수준, 확률의 사용 여부, 예측형 선제성의 포함 여부, 최종 모델·에이전트 수·학습, 신뢰성을 주장할 평가 규모.

원문: [교차 검토와 Claude 수정 의견](07_Claude_교차검토와_수정의견_원문.md), [관측 기준 추가 보완](07b_Claude_관측기준_보완_원문.md).

## 5. 실제로 피드백 때문에 바뀐 것

| 쟁점 | 피드백 후 변화 |
| --- | --- |
| 코드와 모델의 책임 | Codex가 실행 검사·독립 대응 경로의 위치를 더 명시. Claude는 모든 선택을 숫자 계산으로 옮기는 주장을 철회 |
| 가스 예시 | Claude의 ‘알림에 무응답이면 차단’ 등 구체 예시는 일반 규칙으로 채택하지 않음. 장치별 외부 사양이 필요 |
| 관측 선택 | 첫 행동뿐 아니라 이후 정책까지 고려. 싼 관측의 고정 순서를 제거 |
| 관측 가치 평가 | 결과별 계획은 오류 분석 자료. 유용성은 환경의 결과나 검토된 기준으로 평가 |
| 사용자 되돌리기 | 곧바로 오판으로 학습하지 않고 상황·선호 변경 등을 구분. 되돌리지 않음도 정답 증거가 아님 |
| 로컬 모델 학습 | ‘로컬이면 학습 우선’, ‘LoRA 다음 DPO’ 같은 고정 순서를 철회 |
| 평가 설계 | Codex가 반복 일관성·위험 누락의 별도 보고와 비교 우선순위를 추가 |

큰 구조에 대한 차이는 상당히 줄었다. **Codex는 시간 이력·정보 선택·결과를 연결한 평가를, Claude는 모델 밖의 책임과 정책 검사·위험 평가를 상대적으로 더 강조한다.** 현재의 두 안을 완전히 다른 최종 아키텍처로 해석할 필요는 없다.

한 표현은 그대로 채택하지 않았다. Claude의 마지막 원문에는 ‘모든 관측 결과에 같은 계획을 쓰면 자기모순을 자동 판정’한다는 문장이 남아 있다. Codex는 이를 **검토 대상 표시 정도로만 사용**하자는 입장이다. 같은 계획 자체가 논리적 모순이나 무가치한 관측을 증명하지는 않는다. 모델의 사전 주장, 계획의 완전성, 판단 기간과 실제 결과를 확인해야 한다. 미리 쓴 계획과 달리 행동했다는 사실도 새 정보 때문에 정당하게 재계획했을 가능성을 함께 봐야 한다.

## 6. 논문에서 가져올 아이디어

첫 네 편은 문제와 시스템을 이해하기 위한 읽기 순서 제안이다. 수상과 실제 가정의 장기 신뢰성 검증은 서로 다른 증거다.

| 자료 | 가져올 아이디어 | 확인한 위상·범위 |
| --- | --- | --- |
| [POMDP — Planning and Acting in Partially Observable Stochastic Domains](https://people.csail.mit.edu/lpk/papers/aij98-pomdp.pdf) | 보이는 관찰과 숨은 상태를 나누고, 정보를 얻는 행동도 비교 | AIJ 1998, **2021 Classic Paper Award** |
| [Horvitz — Principles of Mixed-Initiative User Interfaces](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz.pdf) | 개입·비개입·질문의 이득과 방해, 시점의 비용 | CHI 1999, PC 비서 사례. 가정 제어 보장은 아님 |
| [CoALA — Cognitive Architectures for Language Agents](https://arxiv.org/html/2309.02427) | 기억, 내부·외부 행동, 후보 제안·평가·선택의 구조 | TMLR 2024. 개념 프레임워크 |
| [ReAct](https://arxiv.org/abs/2210.03629) | 모델 선택과 실제 도구 결과를 반복 | ICLR 2023. 최적 관측 선택·선제 목표 발견까지 보장하지 않음 |
| [Landmark-Based Approaches for Goal Recognition as Planning](https://repositorio.pucrs.br/dspace/bitstream/10923/18610/2/Landmarkbased_approaches_for_goal_recognition_as_planning.pdf) | 행동 이력으로 사람의 목표 후보 추정 | AIJ 2020, **2024 Prominent Paper Award**. 기호 계획 도메인 평가 |
| [Options — Between MDPs and Semi-MDPs](https://www.sciencedirect.com/science/article/pii/S0004370299000521) | 청소처럼 오래 지속되는 행동의 시작·유지·종료 | AIJ 1999, **2019 Classic Paper Award** |
| [KnowNo — Robots That Ask For Help](https://proceedings.mlr.press/v229/ren23a.html) | 불확실성 보정과 필요한 도움 요청 | CoRL 2023 **Best Student Paper**. 센서 요청으로 바꾼다고 보장이 자동 이전되지는 않음 |
| [Generative Agents](https://arxiv.org/abs/2304.03442) | 필요한 기억 회수와 계획 갱신 | UIST 2023 **Best Paper**. 가상 인물 평가 |

수상은 [AIJ 공식 기록](https://aij.ijcai.org/aij-awards-list-of-previous-winners/), [CoRL 공식 기록](https://www.corl2023.org/awards), [UIST 공식 기록](https://uist.acm.org/2023/)으로 확인했다. 목표 인식은 공개된 저자 사전공개본을 읽었고 저널판 전체와 문장별 대조하지 않았다.

두 가지 적용 범위를 추가 확인했다. [SayCan](https://proceedings.mlr.press/v205/ichter23a.html)은 언어의 유용성 판단을 학습된 스킬 가치·실행 가능성과 연결한다. 이를 범용 안전 승인 장치라고 해석하지 않는다. Horvitz는 매번 명시적 기대값 계산을 하지 않고 설계자가 임계값을 정하는 방식도 논의한다. 따라서 그의 논문을 ‘반드시 LLM 확률을 받아 계산해야 한다’는 근거로 읽지 않는다.

최근 선제 지원의 구체 구현은 [ContextAgent](https://arxiv.org/html/2505.14668), [ProAgent](https://arxiv.org/html/2512.06721v2)도 참고할 만하다. ProAgent의 관측 빈도 조절을 ‘어떤 센서·시선·대상을 확인할지 일반적으로 최적 선택한다’는 결과로 확대하지 않는다. 자세한 범위·실험 조건은 [앞선 조사 보고서](02_조사보고서_Codex_검증후의견.md)에 있다.

## 7. 다음 사용자 회의에서 먼저 구체화할 것

다음 논의에서는 **창문·조리·청소 각각의 한 에피소드**를 정하고 아래 항목을 채우는 것이 두 의견을 실제 실험으로 연결하는 데 도움이 된다. 지금 이 문서에서 구현을 시작하거나 선택을 확정한 것은 아니다.

- 모델이 현재 볼 수 있는 관찰과 시간 이력.
- 아직 알 수 없지만 행동을 바꿀 수 있는 조건.
- 추가로 요청 가능한 관측과 그 결과·비용·실패 가능성.
- 사용할 수 있는 행동과 주어진 정책·전제조건.
- 아무것도 하지 않음, 기다림, 작업 유지·중단을 포함한 허용 판단.
- 실행 후 환경 변화와 재판단 조건.
- 어떤 결과를 오개입·놓친 개입·유효한 관측으로 평가할지.

이를 정한 뒤 **관측 선택 불가/가능 → 시간 이력 없음/있음 → 정책 검사 없음/있음**의 효과를 합성 환경에서 분리해 보자는 것이 현재의 우선 제안이다. 실제 DeepSeek 성능을 확인한 다음에야 여러 에이전트·로컬 모델·미세조정에 필요한 근거가 생긴다.

## 8. 원문과 과거 기록을 읽는 방법

- [01 Codex 최초 독립 의견](01_Codex_독립의견.md)과 [05 Claude 최초 독립 의견](05_Claude_독립의견_원문.md)은 수정하지 않고 보존했다.
- **05에는 후속 검토에서 철회·수정된 가스 정책과 학습 순서가 포함된다. 현재 의견은 07·07b와 이 보고서를 기준으로 읽는다.**
- [06 Codex가 Claude에 보낸 반례](06_Codex가_Claude에게_보낸_검토.md), 07·07b, 08을 통해 무엇이 바뀌었는지 추적할 수 있다.
- 02·03의 ‘Claude 호출 불가’ 문구는 이전 시점의 기록이다. 이후 실행 환경이 복구되어 이번 실제 회의를 완료했다.

이 보고서는 Codex가 실제 응답과 자료 검증을 바탕으로 작성했다. 보고서 전체를 Claude가 다시 승인한 것은 아니며, 모델 간 공통 의견은 제품 성능이나 실제 기기 신뢰성의 검증을 대신하지 않는다.
