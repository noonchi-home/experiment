# Codex 독립 의견 — 선제적 가정 AI의 행동 의사결정

작성일: 2026-10-23  
상태: **Claude 의견을 받기 전에 작성한 독립 초안. 최종 설계 확정 아님.**  
검증: 논문·공식 수상 자료·API 문서를 조사했다. 실제 DeepSeek 추론, 학습, 가전 제어 실험은 하지 않았다.

## 1. 내가 판단한 문제의 성격

이 과제는 ‘관찰된 상황에 맞는 행동 이름을 출력하는 분류기’보다 넓다. **불완전한 관찰로 현재 상황을 추정하고, 먼저 할 일을 발견하고, 추가 관찰과 실제 행동을 비교하며, 여러 작업의 우선순위와 실행 결과를 관리하는 순차 의사결정**이다.

이를 다루는 연구는 충분히 있다. 중요한 출발점은 최신 LLM 논문뿐 아니라 POMDP, 능동적 인지, 시간적 행동 추상화, 목표 관리 연구다. 특히 POMDP 대표논문과 options 논문은 각각 2021·2019 AIJ Classic Paper Award 수상작이다. [AIJ 공식 수상 기록](https://aij.ijcai.org/aij-awards-list-of-previous-winners/)

내 우선 제안은 **명시적으로 관리하는 상태·기억 + 하나의 API 판단기 + 관찰/실행 도구 + 실행 관리**를 첫 비교 대상으로 삼는 것이다. 멀티에이전트나 미세조정은 배제하지 않는다. 어느 오류가 병목인지 확인한 뒤 추가했을 때의 이득을 측정해야 한다. 이 우선순위는 나의 설계 제안이며, 논문에서 우리 집 전체 시스템을 그대로 검증한 결과가 아니다.

## 2. 사용자 예시가 드러내는 핵심 난점

| 상황 | 쉽게 빠지는 단정 | 실제로 구분해야 하는 정보 | 가능한 판단 방향 |
| --- | --- | --- | --- |
| 비가 오고 창문이 열림 | 무조건 모든 창문 닫기 | 어느 창문인지, 빗물 유입·노출 여부, 관찰 시각, 개폐 가능 상태, 다른 목적과의 충돌 | 조건이 충분한 창문 조치, 필요한 관찰, 대기 |
| 가스 관련 장치 ON, 조리 활동 미관찰 | 사람 안 보임 = 요리 안 함 | 밸브·버너·불꽃의 의미, 조리 도구, 최근 활동, 경과 시간, 기기 상태 | 정상 조리와 방치 가능성 구분, 필요 정보 획득, 정해진 장치 정책 적용 |
| 요리 중이고 가스 ON | ON만 보고 끄기 / 요리 중이면 항상 유지 | 정상 조리의 근거, 진행 상태, 이상 신호, 관찰의 신뢰성 | 정상 활동 유지, 상태 변화 감시, 이상 시 별도 판단 |
| 안방에 먼지가 많음 | 먼지 = 즉시 로봇청소기 | 바닥 먼지인지 공기 중 입자인지, 사람이 자는지, 바닥 상태·접근 가능성, 청소기 상태 | 청소, 실행 시점 조정, 다른 종류의 대응, 추가 관찰 |

이 표는 실제 가스 설비의 제어 절차가 아니라 합성 실험의 상태 구분 제안이다. ‘요리 중’이라는 말도 관찰을 해석한 결과다. 처음부터 입력에 정답처럼 넣으면 중요한 판단을 이미 사람이 대신해 준 셈이다.

세 가지 어려움이 특히 크다.

1. **관찰만으로 구분되지 않는 상황이 있다.** 현재 사진이 같아도 과거 사건이 다르면 올바른 행동이 달라진다. 이력까지 같고 숨은 의도만 다르면 관찰만으로 정답을 하나로 좁힐 수 없는 경우도 있다.
2. **유용한 행동이 다른 목적을 방해할 수 있다.** 청소는 필요하지만 수면을 방해할 수 있다. 창문·환기·실내 환경처럼 여러 목적이 연결될 수 있다.
3. **판단 중에도 집은 바뀐다.** 사용자가 돌아오고, 기기 상태가 바뀌고, 작업이 이미 시작된다. 단일 응답의 정확도만으로 전체 시스템을 평가하기 어렵다.

## 3. 어떤 정보를 판단기에 주어야 하나

‘가능한 모든 데이터를 매번 긴 프롬프트로 보낸다’는 구현에 먼저 고정할 필요는 없다. 저장할 정보와 이번 결정에 꺼내 쓸 정보를 나눈다.

### 관찰 기록

각 기록에 대상 ID, 장소, 측정값·단위, 관찰 시각, 도착 시각, 출처, 관찰 가능 여부를 붙인다. 센서가 측정한 신뢰도가 있으면 함께 보관하되, 언어모델이 쓴 자신감과 구분한다.

예: 창문 접촉 센서는 열림을 측정하고, 카메라는 특정 창문 주변의 물방울을 관찰하고, 날씨 서비스는 일정 지역의 강수를 알려 준다. 세 정보는 같은 사실의 복사본이 아니다. 중복된 동일 센서 기록을 여러 개의 독립 증거로 세어 확신을 키우지 않도록 한다.

### 상태와 관계

집 → 방 → 가구·기기 → 물체의 관계, 물체의 위치·소유·사용 관계, 현재 기기 상태를 관리한다. 꼭 그래프 데이터베이스를 설치할 필요는 없다. JSON으로 시작해도 관계가 명시되어 있으면 된다.

‘관찰됨’, ‘관찰되지 않음’, ‘가려져 모름’, ‘오래되어 현재 상태 불명’, ‘관찰끼리 충돌’을 구분한다.

### 시간과 활동

최근 사건 순서, 상태가 지속된 기간, 활동의 시작·중단·재개, 반복 사용 패턴을 저장한다. ‘사람이 잠깐 주방 밖으로 나감’과 ‘조리 종료 후 장시간 활동 없음’을 같은 상태로 압축하지 않는다.

처음부터 모든 활동에 정확한 확률을 붙일 필요는 없다. 확인된 사실, 가능한 해석, 지지·반박 근거, 미확인 조건을 구조화하는 방식으로 시작할 수 있다. 이것이 정식 베이지안 확률 추정을 구현했다는 뜻은 아니다.

### 목표·정책·능력

집 상태만으로 무엇이 ‘좋은 결과’인지 자동으로 정해지지는 않는다. 시스템이 유지할 목적, 방해를 줄일 조건, 우선순위, 허용된 기기 행동이 필요하다. 매 상황마다 사용자에게 물어볼 필요는 없고, 시스템 정책과 이미 얻은 설정·기록으로 제공할 수 있다.

센서가 실제로 제공할 수 없는 정보를 요구하거나, 장치가 할 수 없는 행동을 고르지 않도록 관찰·행동 목록과 전제조건도 입력한다.

### 진행 중 작업과 결과

활성 목표, 실행 요청, 실행 중/완료/실패/취소, 그 판단에 사용한 근거, 재판단 조건을 관리한다. ‘명령 전송 성공’과 ‘현실에서 목적 달성’을 구분한다.

기억 모듈과 행동 선택을 시스템 차원에서 다루는 설명 틀로는 CoALA가 특히 직접적이다. CoALA는 기억, 내부·외부 행동, 후보 제안·평가·선택·실행의 순환을 정리한다. 개념적 프레임워크이며 가정 자동제어 성능을 입증한 연구는 아니다. [CoALA §4, TMLR 2024](https://arxiv.org/html/2309.02427#S4)

## 4. 내부 의사결정을 어떻게 구체화할까

다음은 초기 실험용 가설이다. 각 칸을 서로 다른 LLM으로 만들 필요는 없다.

```text
새 관찰·의미 있는 사건·재평가 시점
             ↓
현재 사실·이력·진행 중 작업 갱신
             ↓
지금 방치했을 때 생길 문제 / 도움 될 목표 후보
             ↓
후보 행동과 필요한 전제조건
             ↓
실행 / 추가 관찰 / 대기 / 작업 유지·변경·취소 비교
             ↓
실행 조건·최신성·충돌 검사
             ↓
도구 실행과 결과 기록
             └──── 상태 갱신 후 다음 판단
```

여기서 내가 가장 중요하게 보는 출력은 행동명 하나가 아니라 다음의 **결정 계약**이다.

- 어떤 목표 후보를 왜 고려했는가.
- 어떤 관찰을 근거로 삼았는가.
- 어느 미확인 조건이 결정을 바꿀 수 있는가.
- 지금 선택한 행동은 무엇이며 대상·시점·종료 조건은 무엇인가.
- 무엇이 바뀌면 이 결정을 무효화하거나 재검토하는가.

후보 비교는 ‘해도 되는가’와 ‘하는 것이 좋은가’를 구분한다. 전제조건이 안 맞는 행동은 제외하고, 남은 행동의 목적 적합성·지연 손실·사용자 활동 방해·자원 비용을 비교한다. 단순히 LLM이 0~1 점수를 쓰게 했다는 이유로 점수가 보정된 성공 확률이라고 해석하지 않는다.

실행 전 검사는 별도 코드로 할 수 있지만, 코드로 작성했다는 사실만으로 내용까지 옳아지는 것은 아니다. 검사의 범위·가정·누락을 시험해야 한다. 학습 시스템의 행동을 별도 실행 계층에서 검사한다는 발상은 shielding과 연결되지만, 형식적인 보장은 명세와 환경 모델의 조건 안에서만 성립한다. [Safe Reinforcement Learning via Shielding, AAAI 2018](https://ojs.aaai.org/index.php/AAAI/article/view/11797)

## 5. ‘더 봐야 하나?’를 결정하는 핵심

정보가 부족하다고 항상 추가 관찰하는 정책은 좋지 않을 수 있다. 중요한 질문은 **그 정보를 알면 최선의 행동이 달라질 수 있는가**다.

예를 들어 청소 여부를 정할 때 바닥의 청소 가능 상태는 중요하지만, 무관한 물체 색깔을 더 정확히 알아내는 것은 도움이 적다. 반대로 현재 가능한 모든 해석에서 같은 행동이 타당하다면, 불확실성을 전부 없앨 필요는 없다.

판단에 필요한 추가 정보는 세 종류로 나누어 비교한다.

1. **이미 저장된 정보를 다시 꺼내기:** 최근 활동·기기 이력·과거 사건 검색.
2. **새 관찰을 얻기:** 카메라 방향·센서 조회·현재 상태 재확인.
3. **시간을 두고 다시 보기:** 지금은 정보가 생기지 않지만 다음 사건이 구분에 도움이 되는 경우.

관찰 요청에는 대상, 확인할 속성, 가능한 결과, 결과별로 달라질 결정, 시간·횟수 제한이 필요하다. 같은 질문을 같은 센서에 반복해서 답이 생긴다고 가정하면 안 된다.

좁은 합성 세계에서는 다음 식을 계산 기준선으로 사용할 수 있다.

```text
관찰의 순가치
= 관찰 후 결과별로 가장 좋은 행동을 골랐을 때의 평균 가치
  - 지금 가장 좋은 행동의 가치
  - 관찰 비용
  - 지연 때문에 발생하는 손실
```

이는 정지 환경에 가까운 한 단계 근사다. 관찰 중 환경이 변하거나 여러 단계가 이어지면 더 일반적인 순차 모델이 필요하다. POMDP는 관찰 이력에 대한 믿음 상태와 미래 관찰을 고려해 행동을 선택하는 대표적인 틀이다. [Kaelbling·Littman·Cassandra 1998, §3~4](https://people.csail.mit.edu/lpk/papers/aij98-pomdp.pdf)

첫 API 실험에서는 이 수식을 집 전체에 정확히 풀 필요는 없다. 대신 모델이 ‘부족한 조건 → 가능한 관찰 → 결과에 따라 달라질 행동’을 일관되게 제안하는지 확인하고, 작은 합성 문제에서 명시적 계산과 비교할 수 있다. 사용자의 확인을 기본 경로로 삼지 않는다.

## 6. 여러 일을 동시에 다루는 부분

창문·주방·안방을 각각 잘 판단해도 집 전체에서 잘 행동한다는 보장은 없다. 최소한 다음은 별도 비교가 필요하다.

- 여러 후보 중 무엇을 먼저 실행할지.
- 동시에 실행 가능한지, 장치·공간·목적이 충돌하는지.
- 진행 중인 작업을 계속할지, 잠시 멈출지, 취소할지.
- 새 관찰이 기존 결정의 어떤 근거를 깨뜨리는지.
- 같은 명령을 중복 전송하거나 반대 명령을 번갈아 내리지 않는지.

모든 집 상태가 조금 바뀔 때마다 모든 결정을 취소할 필요는 없다. 결정이 의존하는 대상·조건을 기록해 관련 변화에 재평가하는 방식이 후보가 된다.

청소는 한 순간의 행동이 아니라 지속되는 작업이다. 시작 가능한 상태, 진행 정책, 종료 조건을 가진 행동 단위로 보는 options의 발상이 도움이 된다. 다만 원래 연구는 강화학습의 시간 추상화 틀이며, 우리 실행 관리에 적용한다고 그 학습 알고리즘을 재현하는 것은 아니다. [Sutton·Precup·Singh 1999](https://www.sciencedirect.com/science/article/pii/S0004370299000521)

## 7. 멀티에이전트·미세조정·모델 수정 중 무엇이 필요할까

현재 근거만으로 어느 하나가 반드시 필요하다고 결론내릴 수 없다.

| 접근 | 해결하려는 문제 | 해결해 주지 못하는 것 | 도입을 검토할 증거 |
| --- | --- | --- | --- |
| 상태·기억·도구를 갖춘 단일 API 판단기 | 판단 과정을 먼저 측정하고 오류 위치 찾기 | 입력에 없는 사실을 알게 하지는 못함 | 첫 기준 구조 |
| 같은 모델의 추가 검토 호출 | 후보의 누락·상충·순서 오류 탐지 | 같은 오해를 공유할 수 있음 | 정해진 비용 안에서 오류를 실제 줄임 |
| 여러 역할의 LLM 에이전트 | 독립적으로 처리할 영역·전문성·관찰을 분담 | 공유 상태·최종 우선순위 문제는 남음 | 동일 예산의 단일 구조보다 순이득이 있음 |
| 로컬 모델 SFT/LoRA | 반복되는 판단·도구 선택·출력 방식 특화 | 잘못된 정책·레이블·누락 센서를 해결하지 못함 | 충분한 교정 기록, 별도 평가에서 반복적 실패 |
| 시뮬레이션 기반 강화학습 | 여러 단계 결과와 관찰 비용을 고려한 정책 학습 | 잘못된 보상·세계 모델 문제 | 신뢰할 시뮬레이터와 명시적 목표·실패 평가 확보 |
| 모델 구조 자체 변경 | 기존 모델·시스템으로 못 푸는 확인된 병목 | 연구·학습 비용이 매우 큼 | 더 단순한 방법의 실패와 대안의 실증 근거 |

**모듈을 나누는 것과 여러 독립 에이전트를 두는 것은 다른 선택**이다. 인지·기억·판단·실행 관리가 나뉘어 있어도 핵심 판단 모델은 하나일 수 있다.

최신 비교 연구도 멀티에이전트의 이득이 과제 구조에 따라 달라짐을 보고한다. 2026년 4월 수정본은 260개 구성·6개 벤치마크를 비교하며, 병렬 분해와 순차 의존성에 따른 차이를 분석한다. 집안 판단을 직접 시험한 결과는 아니므로, 이를 ‘멀티에이전트는 항상 좋다/나쁘다’로 일반화하지 않는다. [Towards a Science of Scaling Agent Systems, v3](https://arxiv.org/html/2512.08296v3)

미세조정의 가능성은 PARTNR에서 볼 수 있다. 다만 미세조정 8B가 70B와 비슷하다는 validation 결과(.70/.73)와 test 결과(.51/.63)를 구분해야 한다. 실제로 검증된 기록을 작은 모델에 학습시키는 방향은 후보지만, 우리 합성 가정 데이터에서의 효과는 아직 미확인이다. [PARTNR §4.2·부록 A.10~A.11](https://arxiv.org/html/2411.00081)

## 8. 첫 DeepSeek 실험에서 무엇을 분리할까

현재 공식 문서는 DeepSeek의 사고 모드, 도구 호출, JSON 출력을 지원한다고 명시한다. 이 기능으로 관찰 요청→도구 결과→재판단 순환을 구현할 수 있다는 것은 확인되지만, 우리 과제 성능은 아직 측정하지 않았다. 실행 시점의 실제 모델 ID·버전·effort·도구 규격을 기록해야 한다. [모델 문서](https://api-docs.deepseek.com/quick_start/pricing/), [도구 호출](https://api-docs.deepseek.com/guides/tool_calls/)

한 번에 모든 구조를 비교하기보다 다음을 분리한다.

1. **현재 관찰만 / 이력 포함:** 시간이 주는 정보의 효과.
2. **직접 행동 선택 / 상태·후보·미확인 조건을 구조화:** 판단 형식의 효과.
3. **추가 관찰 불가 / 선택 가능:** 능동적 관찰의 효과.
4. **실행 결과 미반영 / 반영:** 재판단의 효과.
5. **단일 판단 / 추가 검토 / 역할 분담:** 같은 토큰·비용·지연 예산에서 구조의 효과.

‘모듈이 많아졌더니 성능이 좋다’는 관찰만으로 멀티에이전트의 효과라고 부를 수 없다. 모델 호출량이 증가한 효과와 분리해야 한다.

## 9. 합성 실험을 잘못 설계하면 어려운 판단을 시험하지 못한다

합성 환경에는 연구자만 아는 실제 상태와 모델에게 보이는 관찰을 따로 둔다. 예를 들어 실제 세계의 조리 활동 여부는 정답 쪽에 있을 수 있지만, API에는 이를 추정할 수 있는 사건·센서 기록을 준다. 처음부터 ‘요리하지 않는다’고 알려주고 끌지 묻는 실험은 더 쉬운 문제다.

중요한 평가 사례는 다음과 같다.

- 현재 장면은 같지만 이력이 달라 선택이 바뀌어야 하는 쌍.
- 한 가지 조건만 바꾼 반례: 먼지는 같고 사람이 수면 중인지 여부만 다름.
- 현재 정보로 구분 불가능하지만 특정 관찰로 구분할 수 있는 경우.
- 어떤 관찰로도 당장 구분하기 어려운 경우.
- 여러 사건이 동시에 생기는 경우.
- 관찰 지연·중복·상충·누락.
- 실행 실패·지연·중간 상태 변화.
- 아무 일도 하지 않는 것이 적절한 긴 구간.

모델에게 사건마다 ‘이제 뭔가 해라’라고 암시하지 않는 것도 중요하다. 도움이 필요 없는 상태에서도 판단 주기가 돌아가야 과잉 개입을 측정할 수 있다.

관찰 요청을 하면 실제로 그 요청에 맞는 합성 정보가 반환되어야 한다. 선택과 무관하게 미래 정답을 순서대로 공개하는 실험과 행동에 따라 정보가 달라지는 실험을 구분한다.

평가는 행동 적절성만 아니라 불필요한 개입, 필요한 개입 누락, 유효한 추가 관찰, 완료·취소 대응, 중복·충돌, 비용·지연을 함께 기록한다. 정책상 허용되는 대안은 정답 집합으로 두고, 입력에서 알 수 없는 속마음을 맞히지 못했다고 무조건 오답으로 처리하지 않는다.

## 11. 내 의견의 약점과 바뀔 조건

- 단일 판단기부터 시작하면 병목을 찾기 쉽지만, 여러 방에서 빠르게 발생하는 독립 사건이 많거나 모델 문맥이 부족하면 역할 분담이 유리할 수 있다.
- 구조화된 상태도 인지 결과가 틀리면 잘못된 결정을 유도한다. 완벽한 입력과 불완전한 입력의 평가를 분리해야 한다.
- 좁은 문제에서는 명시적 계획기·규칙이 더 정확하고 저렴할 수 있다. LLM을 사용한다는 이유만으로 그 부분을 대체할 필요는 없다.
- ‘정책을 정한다’는 작업 자체가 어렵다. 사용자 입력 최소화와 개인별 기대 충족 사이의 충돌을 어떤 기본 정책·기존 기록으로 해결할지 남아 있다.
- 내가 제안한 전체 조합은 아직 실행해 보지 않았다. 각 연구의 성공을 합치면 통합 시스템도 성공한다는 보장은 없다.

다음 회의에서는 먼저 ‘주어진 관찰 이력 → 상황 해석 → 추가 관찰 또는 행동 → 피드백’의 한 에피소드를 창문·주방·청소에서 각각 구체화하고, 어떤 정보를 실제로 관찰할 수 있는지와 어떤 결과가 좋은 판단인지부터 논의하는 것이 좋겠다.
