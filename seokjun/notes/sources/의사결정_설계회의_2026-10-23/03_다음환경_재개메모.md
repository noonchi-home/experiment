## 실행이 복구되면 이어갈 순서

1. 사용자에게 한국어로 이번 입력·도구·범위를 짧게 알리고, 명령 실행·Claude CLI 버전·구독 인증을 확인한다.
2. ai-meeting 스킬과 사용 절차를 따른다. 스킬 위치는 ~/.agents/skills/ai-meeting/SKILL.md. 요청 모델은 claude-opus-5-5, effort는 사용자가 명시한 max다. 다른 모델·effort·외부 API로 조용히 바꾸지 않는다.
3. 실행기의 기본 저장 경로는 ~/ai-collab/meetings이며 현재 작업의 쓰기 허용 범위와 일치하는지 확인해야 한다. 전역 실행기·설정을 임의 변경하지 않는다.
4. 최초 독립 호출에는 00 파일만 문제 자료로 보낸다. 01·02 파일, 연구 결과, Codex의 평가나 추천을 전달하지 않는다. 새 문맥이며 기존 프로젝트 파일·대화·검토 이력이 유입되지 않도록 실제 입력과 도구 접근을 확인한다. 실행기의 기존 기본 Read/Glob/Grep 권한 때문에 주변 초안을 읽게 만들지 않는다.
5. 실제 모델·effort, 명령 옵션, 전송 원문, 실제 응답을 파일에 보존한다. 기본 실행기에 effort 인자가 없을 수 있으므로 현행 CLI가 지원하는 설정과 실제 적용 여부를 확인한다. 모델에게 max라고 말하는 것만으로 설정이 적용됐다고 기록하지 않는다.
6. Claude 독립 응답을 받은 다음 Codex가 원자료·반례로 검증한다. 그 이후에만 02 의견을 Claude에게 전달한다. 검토는 --kind review --candidate 방식이며 원래 사용자 문제도 함께 제공한다.
7. Claude의 Codex 검토와 Codex의 Claude 검토를 구분한다. 지적은 사실·논문·구체 반례로 확인하고 각자의 수정 의견을 만든다. 합의를 강요하거나 상대 반응을 미리 만들어 놓지 않는다.
8. 최종 보고에서는 두 수정 의견, 수용한 피드백, 유지하는 차이, 실험으로 확인할 사항을 구분한다. 동일 파일이 실제 검토를 거치지 않았다면 ‘검토 승인’으로 표시하지 않는다.
