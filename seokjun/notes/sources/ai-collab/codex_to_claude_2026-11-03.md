5. “바로 마심 / 뜸들이다 마심 / 고개를 저어 거절 / 원상복귀로 거절”은 촬영자가 알려준 연출 의도이며 **평가자만 보관한다.** 모델이 영상에서 자유롭게 관찰·해석해야 한다. 네 종류를 코드의 정답 대응표나 모델의 강제 선택지로 넣지 않는다. 평가용 JSON 전체를 그대로 모델에 넘기지 않는다.
6. 즉시 마시지 않음·옆으로 이동함만으로 거절을 확정하지 않는다. 거절 의도를 알아도 이유와 장기 선호는 모를 수 있다. 고개 젓기 영상의 거절 의도는 촬영자가 확인한 것이며, 초기 표본 관찰만으로 확정한 결과가 아니다.
7. 최종 행동 판단 모델은 비교 조건에서 동일하게 유지하는 방향이다. 추가 분석과 추가 정보·계산량 때문에 좋아지는 효과를 역계획 효과와 구분해야 한다.

## 설계 제안과 구현 전 확인할 코드

실제 역계획은 가능한 목표에서 행동 계획을 예측한 뒤 관찰 행동과 얼마나 맞는지 비교하는 구조로 제안했다. 상태·행동의 전제조건과 결과·비용·목표 후보·점수 계산은 **아직 확정하지 않았다.** 프롬프트에 “역계획을 해라”만 넣는 것과 별도 계획 계산 구현을 구분해야 한다. 앞선 h(도움 자체의 선호)·w(간섭 특성별 민감도) 수치 모델도 확정되지 않았다.

`ai/pam/`에서 볼 부분:

- `observations.py`: 서로 다른 두 카메라 이미지를 받아 나란히 구성한다. 이번 한 카메라 영상과 시간순 입력 경로가 필요하다.
- `messages.py`의 `build_reflector_messages`: 초기 생성과 갱신을 지원한다. 초기 생성에는 기존 기억·요약·사람 피드백을 넣지 않는 규약이 있다. 갱신은 요약 필수, 피드백 선택이다.
- `reflection_experiment.py`: 초기 기억을 파일로 읽고 고정된 아침 시나리오를 사용한다. 이 실행기는 요약과 사람 피드백 모두 빈 값을 거부한다. 처음부터 음료 도움 규칙을 배우는 실행 흐름은 아직 연결되지 않았다.
- `memory_store.py`: 논문 방식의 기억을 다음 달력 날짜에 적용한다. 같은 날 실험 회차를 반복할 방법이 필요하며, 날짜를 속여 해결한 것으로 처리하지 않는다.
- `contracts.py`: 형식·행동 번호를 검증한다. 적절한 개입 시점이나 도움의 유용성을 보장하는 검사와 다르다.

기존 구현은 논문에 근거한 상황 변경 재현이며 저자 공식 실행 코드가 아니다. 원문 지시문 7개와 PDF의 보관 해시 일치를 지난 작업에서 확인했지만 전체 동작·성능의 동일성 증명은 아니다. 기존 합성 이미지에서 실제 Qwen 호출과 별도의 사람 피드백 기반 반성 실험은 존재한다. “기존 실험도 전혀 안 했다”와 “새 촬영 영상 실험을 완료했다”는 둘 다 잘못된 설명이다.

비교 조건은 논문 흐름 기준 / 일반 언어 모델 반응 분석 추가 / 반응 분석만 역계획 / 자기반성만 역계획 / 둘 다 역계획이라는 **제안**이다. 초기 규칙 생성 자체는 별도로 비교하고, 갱신 효과 비교는 같은 초기 기억에서 시작한다. 정보·모델·최종 판단을 맞추고 호출 수·사진 수·시간을 기록한다. 같은 관찰을 두 단계에서 사용했다고 독립 증거처럼 중복 계산하지 않는다. 개입 시점 평가에는 그 시점까지의 영상만 제공하고, 정답 시간 구간을 별도로 정해야 한다. 마지막 프레임 한 번만 판단하거나 같은 촬영본의 인접 프레임을 학습용·시험용으로 나누지 않는다.
