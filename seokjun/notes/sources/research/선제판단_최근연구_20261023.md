# 선제적 가정 AI 판단 — 최근 연구와 검증 근거
검토일: 2026-10-23. 원문·학회·저자 자료 중심. API 실험·모델 학습은 실행하지 않았다.

## 핵심 발견

이 과제에서 참고할 논문은 ‘주어진 명령을 수행하는 계획기’, ‘명령 없이 개입 필요성을 찾는 선제성’, ‘누적 기억과 환경 상태’, ‘모르는 것을 알아내는 정보 획득’, ‘실행 과정의 평가’를 나누어 읽는 편이 좋다. 하나의 유명 논문이 모두를 검증했다고 보기는 어렵다.

- 현재 API 실험에는 ReAct의 관찰→선택→도구 실행→새 관찰 구조, EAI의 객체·관계·전제조건 표현과 오류 분류가 직접적이다.
- 선제성 자체에는 Proactive Agent가 더 가까우나 사용자에게 도움을 제안하는 디지털 업무 맥락이 크다. 가정 내 물리적 자동 실행의 성공을 검증한 것으로 옮겨 읽으면 안 된다.
- 미세조정은 실제 개선 증거가 있으나 데이터·평가 범위가 정해진 뒤의 선택이다. PARTNR과 Proactive Agent는 일반적으로 작은 모델이 언제나 큰 모델을 대체한다는 증거가 아니다.
- PARTNR의 ‘multi-agent’는 여러 물리적 행위자의 협업이다. 내부 판단을 여러 LLM 역할로 나누는 설계와 같지 않다. 중앙/분산 결과를 LLM 토론의 보편적 효능으로 해석하면 안 된다.

## 1. ReAct — 정보 획득과 행동을 반복하는 기본 구조

**ICLR 2023.** [원문](https://arxiv.org/html/2210.03629), [저자 설명·코드](https://react-lm.github.io/).

원문 §2·§4는 모델의 판단 서술, 환경에 대한 행동, 돌아온 관찰을 번갈아 사용한다. ALFWorld의 텍스트 환경과 WebShop 등에서 평가한다. WebShop 표4에서 Act 성공률30.1%, ReAct40.0%; 같은 언어모델의 프롬프트 방식 비교와 학습형 기준선 비교를 구분해야 한다. ALFWorld의 유명한71%는 best-of-6 prompt trial이며 평균은57%다. [원문 §4·표3~4](https://arxiv.org/html/2210.03629#S4).

**우리 적용 해석:** ‘컵 안쪽을 조회한다’, ‘현재 주방 활동을 재관찰한다’도 action으로 만들고, 모델이 결과를 받은 뒤 실행 여부를 다시 정하는 골격으로 적합하다. 이것만으로 관찰 비용 최적화, 신뢰도 보정, 선제적 목표 생성이 보장되지는 않는다. 명령 수행 벤치마크가 주된 검증 범위다. 공개된 사고 서술을 실제 내부 인지과정의 완전한 설명으로 취급할 필요도 없다.

## 2. Generative Agents — 누적 기록을 현재 판단에 연결하는 기억 구조

**UIST 2023 Best Paper.** 학회가 직접 수상 목록에 명시한다. [UIST 공식 수상](https://uist.acm.org/2023/), [원문](https://arxiv.org/html/2304.03442).

원문 §4는 사건 기억에서 최근성·중요도·관련성으로 필요한 기록을 검색하고, 추상화한 reflection과 계획·재계획을 연결한다. 25개 가상 인물의 작은 마을 시뮬레이션이며, §6의100명 평가자는 행동의 그럴듯함을 비교했다. 기억·계획·reflection의 제거 실험은 있으나, 가정 내 물리 제어의 정확도·안전성을 측정한 연구는 아니다. 기억 회수 누락과 내용 부풀리기도 보고한다. [원문 §4·§6](https://arxiv.org/html/2304.03442#S4).

**우리 적용 해석:** ‘모든 과거 센서 데이터를 매번 붙이기’보다 객체별 이력, 최근 사건, 현재 후보와 관련된 기록을 검색하는 구조를 가져올 수 있다. 원시 관찰과 모델이 만든 추정 요약은 따로 저장해야 한다. 예를 들어 ‘오랫동안 요리 활동이 관찰되지 않음’과 ‘요리가 끝남’을 같은 사실로 만들면 안 된다. 수상은 설계 아이디어의 가치를 보여주지만 우리 도메인의 검증을 대신하지 않는다.

## 3. Proactive Agent — 언제 도움을 제안할지 학습

**ICLR 2025.** [공식 서지](https://proceedings.iclr.cc/paper_files/paper/2025/hash/75c37811e830bf029584b1c6fac17726-Abstract-Conference.html), [공식 PDF](https://proceedings.iclr.cc/paper_files/paper/2025/file/75c37811e830bf029584b1c6fac17726-Paper-Conference.pdf).

ProactiveBench는 학습6,790 events·평가233 events를 포함한다. 키보드·마우스·브라우저 등으로부터 얻은 시간순 맥락, 합성 환경, 수용/거부 판단을 사용한다. 원문 §4.2·표3에서 같은Qwen2-7B의 미세조정 전후F1은60.74%→66.47%다. 같은 프롬프트·greedy decoding·동일평가분할을 사용한다. 하지만 자동 평가는 학습한 reward model의 판정이다. 미세조정 후에도 precision49.78%, false-alarm50.22%이며 저자도 오개입을 한계로 지적한다. [PDF §4.2·표3·Limitations](https://proceedings.iclr.cc/paper_files/paper/2025/file/75c37811e830bf029584b1c6fac17726-Paper-Conference.pdf#page=7).

**우리 적용 해석:** 실행한 경우만 학습하면 늘 개입하는 편향을 만들 수 있다. ‘할 일이 없음’과 ‘기다려야 함’도 정상 사례로 넣고, 필요한 개입 누락과 불필요한 개입을 별도로 측정할 근거다. 사용자에게 매번 질문하는 구조를 그대로 채택할 이유는 없다. 가정용 데이터로 바꾼 뒤에도 같은 개선이 나오는지는 별도 문제다. arXiv본문 일부 문장과 표의 숫자가 불일치하므로 보고서에서는 공식PDF 표3의 수치를 기준으로 삼았다.

## 4. PARTNR — 협업·상태 표현·작은 모델 미세조정의 실제 비교

**ICLR 2025.** [공식 ICLR 논문](https://openreview.net/forum?id=T5QLRRHyL1), [저자 원문 HTML](https://arxiv.org/html/2411.00081), [프로젝트](https://aihabitat.org/partnr/).

집·방·가구·물체의 world graph, 행동 이력, 준비된 스킬을 사용한다. 데이터는10만개 지시·60개 집으로 구성된다. §4는 중앙/분산, 관찰범위, oracle/학습스킬을 나누어 비교한다. 부록A.10의 미세조정은 큰 모델의 성공한 ReAct 기록으로8B 모델을 학습하는 방식이다.

**수치의 조건:** §4.2 표2의 부분관찰·oracle-skill 조건에서70B ReAct .73, 미세조정8B .70, 추론8.6배 빠름을 보고한다. 이는 부록표10 validation값과 같다. 부록표11 test에서는 각각 .63, .51이므로 “작은 모델이 큰 모델과 동등”이라는 일반화는 피해야 한다. 중앙/분산 비교는 상대 상태·의도에 대한 접근 차이를 포함한다. [원문 §4·부록A.10~A.11](https://arxiv.org/html/2411.00081).

**우리 적용 해석:** 객체 중심 상태+행동 이력을 먼저 설계하고, 성공·실패가 검증된 기록이 쌓인 뒤 로컬 모델로 압축하는 순서의 근거다. ‘주방 모델·창문 모델·청소 모델’을 따로 두면 상태·자원·우선순위가 충돌할 수 있으므로, 역할 분해와 여러 독립 판단자의 도입을 구분해야 한다. 다만 PARTNR은 분산된 로봇·사람의 협력 문제이므로 내부 LLM 역할 분담의 직접 비교 증거는 아니다.

## 5. Embodied Agent Interface (EAI) — 판단을 오류 원인별로 측정

**NeurIPS 2024 Datasets and Benchmarks Track.** [공식 서지](https://proceedings.nips.cc/paper_files/paper/2024/hash/b631da756d1573c24c9ba9c702fde5a9-Abstract-Datasets_and_Benchmarks_Track.html), [원문](https://arxiv.org/html/2410.07166).

§2는 객체·상태·관계·행동·목표를 표현하고, 목표 해석·하위목표 분해·행동 순서·상태 전이 모델의 네 능력을 분리한다. VirtualHome과BEHAVIOR에서 문법·환각·누락 단계·잘못된 순서·전제조건 등 오류를 분석한다. 부록G/H는 파이프라인, 피드백, 재계획을 따로 비교한다. 원문 평가 모듈은 한 능력을 LLM으로 시험하고 나머지는 데이터/도구로 고정해 원인을 분리하는 방식이다. [원문 §2·그림4·부록G/H](https://arxiv.org/html/2410.07166#S2).

**우리 적용 해석:** ‘가스를 꺼야 한다고 고른 비율’만 보지 말고, 요리 활동을 잘못 추정한 것인지, 목표 우선순위를 잘못 고른 것인지, 실행 조건이 빠졌는지 구분하자. 특히 입력의 `on` 하나를 가스밸브열림·불꽃유무·버너전원·조리활동으로 뭉뚱그리지 않는 도메인 모델이 필요하다. 이 논문의 네 능력은 사용자가 제시한 심리학 네 단계와 같은 분류가 아니다. 미리 주어진 목표를 평가하므로 선제성 자체의 검증으로 읽지 않는다.

## 6. IS-Bench — 끝난 상태만 아니라 수행 순서의 문제 평가

**AAAI 2026.** [공식 논문 페이지](https://ojs.aaai.org/index.php/AAAI/article/view/40880), [PDF](https://ojs.aaai.org/index.php/AAAI/article/view/40880/44841).

161개 시나리오·388개 위험을 시뮬레이터에 구성하고, 위험 완화가 필요한 동작보다 앞/뒤에 수행되는지 과정 단위로 평가한다. 표2의 같은GPT-4o에서 안전CoT를 강조하면 일부 안전 지표는 좋아지지만 작업성공률은81.3%→53.8%로 감소한다. 이는 ‘더 생각하라’는 프롬프트가 모든 목표를 동시에 개선한다고 가정하면 안 된다는 증거다. L3의 정답 안전목표 제공 결과는 위험을 스스로 발견하는 능력과 구분해야 한다. [PDF 표2·분석](https://ojs.aaai.org/index.php/AAAI/article/view/40880/44841#page=6).

**우리 적용 해석:** 합성 실험에서도 ‘최종적으로 가스가 꺼졌음’만으로 정답을 정의하면 요리 중 갑자기 끄는 오류를 놓친다. 중간 상태·필요한 시간·개입 순서·사용자 활동을 훼손했는지도 평가해야 한다. 실제 가스 설비 제어 정책은 이 논문 수치로 정할 수 없으며, 현재는 시뮬레이션 판단 실험의 평가 아이디어로 사용한다.

## 7. EmbodiedBench — 높은 수준 판단과 낮은 수준 제어를 구분

**ICML 2025.** [공식 서지](https://proceedings.mlr.press/v267/yang25f.html), [프로젝트](https://embodiedbench.github.io/).

1,128개 테스트·4개 환경·24개MLLM을 평가하고, 상식·시각·공간·장기계획 등 능력을 나누어 본다. 높은 수준의 의미적 과제와 낮은 수준의 이동·조작 사이의 성능 차이를 보고한다. 모델·페이지 갱신 시점에 따라 표시 수치가 달라지므로, 오래된 “최고 모델” 수치를 현재 모든 모델의 한계로 인용하지 않는다.

**우리 적용 해석:** 합성JSON→행동 선택은 높은 수준 판단 실험이다. 실제 이미지 입력과 로봇 제어까지 포함한 전체점수와 직접 비교하지 않는다. 사용자 과제를 ‘너무 어려워서 못 한다’고 결론낼 자료가 아니라, 먼저 무엇을 고정해 어느 능력을 측정할지 구획할 자료다. 이 과제의 첫 구현에서 대규모 물리 시뮬레이터가 반드시 필요한 것은 아니다.

## 첫 API 실험에 관해 제안할 수 있는 것 (논문 결과 아님)

1. 상태를 객체·장소·활동·관계·시각·출처·불확실성으로 표현한다. 원시 관찰과 ‘요리 중’ 같은 추정 상태를 구분한다.
2. 후보 행동에는 장치 동작뿐 아니라 조회·관찰·대기·취소를 포함한다. 필요한 관찰을 구체적 도구로 연결한다.
3. 한 API 판단기로 기준선을 만든 뒤, 역할 분할·검토기·미세조정은 같은 데이터와 호출/토큰 예산으로 비교한다.
4. 판단자가 여러 개여도 최종 실행 권한과 최신 상태는 한 곳에서 조정해야 같은 창문에 열기/닫기를 동시에 보내는 충돌을 관찰·방지할 수 있다.
5. 기억 검색·추가관찰·실행결과 피드백을 각각 빼는 비교를 한다. 복잡한 프롬프트 전체를 한꺼번에 바꾸면 원인을 알기 어렵다.
6. 합성 정답에 숨은 실제 상태를 그대로 입력하지 않는다. ‘요리 안 함’이라는 정답 대신 그 판단에 사용될 관찰을 제공하고, 불충분한 사례에는 관찰/보류도 허용한다.
7. 일반적 모델구조 변경의 필요성은 이 논문들로 입증되지 않는다. 먼저 실패를 상태추정·기억회수·목표선택·행동순서·실행검증으로 나눠 어떤 부분이 병목인지 확인한다.

## 이번 조사에서 검증하지 않은 것

- DeepSeek API 또는 로컬Qwen의 이 과제 실제 성능·지연·비용.
- 내부 역할형 멀티LLM이 단일LLM보다 낫다는 동일연산예산 비교.
- 센서와 실제 주택 설비 연결 시 성능·안전성.
- 위 방법을 합쳤을 때 시너지. 통합안은 새로운 실험 대상이다.

## 추가 후보: ProHSR — 원문 확보 후 검토할 직접 관련 연구

**A cloud-edge collaborative framework with confidence-aware perception and cognitive dual-stream memory for proactive service robot decision-making.** Expert Systems with Applications 327 (2026), 132623. DOI:10.1016/j.eswa.2026.132623. [출판사](https://www.sciencedirect.com/science/article/pii/S0957417426015368).

직접 페이지 열기는403으로 실패했으며, 저자 공개본문·코드를 이 조사에서 확보하지 못했다. 아래는 출판사 검색 색인에 노출된 초록·도입부로 확인한 범위다.

- 인지→기억→판단→피드백을 연결하는 가정용 선제 서비스 프레임워크.
- edge의 Visual Confidence Estimator와 단기 사건/장기 사용자프로필의 dual-stream memory.

## 추가 핵심 읽기: ProAgent — 언제 센서를 더 자주 볼지 판단

**ProAgent: Harnessing On-Demand Sensory Contexts for Proactive LLM Agent Systems in the Wild.** 2025-12-07 최초공개, 2026-05-07 v2. 제목의 LLM 표기는 arXiv 메타데이터와 HTML 사이에 차이가 있다. 2026-09-25 저자 연구실은 **IMWUT 채택·UbiComp2027 발표 예정**이라고 공지했다. 수상은 확인하지 않았다. [버전](https://arxiv.org/abs/2512.06721), [Columbia 공지](https://icsl.ee.columbia.edu/proagent-accepted-to-imwut-ubicomp/).

### 원문에서 확인한 방법·실험

- **추가 관측:** IMU/GPS의 움직임·주변장소 신호가 고빈도 관측을 켠다. VLM의 선제지원 필요/불필요 출력으로 영상 취득 간격을 5초/60초로 조절한다. 반복 활성화 억제는20초다(§4.4).
- **판단:** 실제 영상과 위치·움직임·오디오·최근기록·관련 사용자선호를 단일 VLM에 넣어 지원 필요성·도구호출을 결정한다. 시선 지속성에 대응하는 영상 일치도와 반복응답 필터를 별도로 둔다(§4.2–4.3).
- **학습:** 기본 Qwen3-VL-4B. Qwen2.5-VL-32B의 설명 trace를 추가한 자료로 LoRA 미세조정(rank8,10epochs). pretrained 모델 그대로의 prompting 실험만은 아니다(§4.3.2,5.1.2).
- **자료:** CAB-Lite300개, 무작위60%학습/40%시험. 별도 실생활92시간·20명·5도시. 동일20명이 사용자평가에도 참여했다. 초기선호 입력과 후속 발언피드백을 사용한다(§5.2,5.7).
- **수치:** 저자는 최대27.7% Acc-P 향상·20.5% FD 감소, 평균추론4.5초, 사용자85% 긍정응답을 보고한다. 이 조사에서는 도표 원시값과 %의 분모를 재계산하지 않았다(§5.3,5.7).
- **비교조건:** 모델 규모를 맞추지만 학습·샘플링·선호검색·전달필터가 함께 달라지는 시스템 비교다(§5.2.3).
- **ContextAgent와 차이:** 영상→설명→LLM의 두 단계를 raw영상+context→VLM으로 합치고, 장시간 실제 센서 취득주기 제어를 추가했다(§2.2,4.3,5.2.3).

근거: [ProAgent v2 본문](https://arxiv.org/html/2512.06721v2).

### 우리 과제에 대한 해석과 남는 연구문제

**‘더 자주 관찰할까’를 실제 센서에 연결한 직접 참고자료다. 그러나 ‘컵 안이 비었는지 확인하려면 어떤 관측을 해야 할까’를 일반적으로 푸는 정책은 아니다.** 취득 주기 선택을 관측 대상·시점·시선 방향·센서 종류의 최적 선택으로 확대 해석하면 안 된다. 존재하지 않는 관측값을 LLM이 추정해서 채우는 것도 새 센서 관측과 다르다.

우리 합성실험에서는 관측행동을 구체화할 수 있다. 예를 들어 가스 상태만 보이면 현재 사용 여부를 추정하되, 주방 활동의 최신 기록 조회·현재 화구 이미지 확인처럼 실제 반환값이 있는 도구를 선택하게 한다. 호출 전에는 숨겨진 상태를 제공하지 않고, 호출 후에만 새로운 관측값을 공개한다. 이는 이 논문의 구현을 복제하는 것이 아니라 우리의 확장 가설이다.

이 논문으로 미세조정 필수성이나 멀티에이전트 우월성을 결론낼 수 없다. 이 연구의 27.7%를 ‘파인튜닝만 하면 얻는 향상’으로 인용하지 않는다. 사용자 선호가 거의 없는 조건은 별도로 시험해야 하며, AR 정보지원 수치를 창문·가스·청소기 자동제어의 신뢰성으로 전환하지 않는다. 다음 실험에서는 **행동만 선택 / 관측 주기 선택 / 목적 있는 추가관측 선택**을 같은 합성환경과 예산에서 구분하여 비교할 가치가 있다.
