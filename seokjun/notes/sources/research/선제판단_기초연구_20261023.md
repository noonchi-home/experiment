# 선제적 가정 AI 판단 — 기초 의사결정 연구 검증

작성일: 2026-10-23. 원문·학회·출판사·저자 기관 자료를 읽은 조사 기록이다. 실제 DeepSeek API, 로봇, 시뮬레이터를 실행하지 않았다. 아래 스마트홈 설계는 논문의 직접 실험 결과와 구분한 적용 제안이다.

## 핵심 판단

이 문제는 “언어모델에게 집 사진을 보여주고 할 일을 묻기”보다 넓다. 이력으로 현재 상태를 추정하고, 할 일 후보를 만들고, 행동과 추가 관찰을 비교하고, 시간에 걸친 작업을 유지·중단하며, 여러 목적의 충돌을 해결하는 **부분 관측하의 순차 의사결정**이다. LLM 수나 미세조정 여부보다 먼저 이 의사결정 문제의 상태·행동·관찰·목적을 정의할 필요가 있다.

가장 직접적인 이론적 출발점은 POMDP다. 첫 API 실험에서 집 전체의 정확한 POMDP 해법을 구현하라는 뜻은 아니다. “현재 관찰이 곧 실제 전체 상태는 아니다”, “정보를 얻는 행동도 행동이다”, “더 관찰할지는 의사결정 이득과 비용으로 결정한다”는 구조를 먼저 가져올 수 있다.

## 1. POMDP: 관측한 것과 실제 상태를 구분한 의사결정

**Kaelbling, Littman, Cassandra (1998), Artificial Intelligence 101, 99–134.**  
[저자 MIT 원문](https://people.csail.mit.edu/lpk/papers/aij98-pomdp.pdf), [출판사 서지](https://www.sciencedirect.com/science/article/pii/S000437029800023X).

### 원문 핵심

§3.2~3.4는 과거 행동·관찰을 요약한 **belief state**를 두고, 새 관찰과 직전 행동으로 이를 갱신한 뒤 행동을 선택한다. 가장 가능성 높은 상태 하나만 택하면 불확실성을 잃는다. 정보 수집과 환경 변화 행동을 같은 의사결정 틀에서 다룬다. §4는 미래 관찰별 분기를 고려하는 정책과 가치함수를 설명한다.

이 논문은 세계 전이·관측 모델과 보상 구조가 주어진 계획 문제를 다룬다. 정확한 풀이의 상태·이력 공간 증가가 주요 한계다. 원문 §1, §3, §4, §7을 참고한다. 모델이 틀리면 이론적 최적성을 현실에 옮길 수 없다.

### 우리 적용 제안

- “가스 ON” 한 값으로 상황을 대표하지 않는다. 기기 상태, 관측 가능한 연소 상태, 조리 도구와 음식, 사람의 최근 행동, 경과 시간 등 서로 다른 증거를 표현한다.
- “사람이 화면에 없음”에서 바로 “요리 안 함”으로 점프하지 않는다. 추정 상태와 그 근거·미확인 내용을 별도로 유지한다.
- 어떤 행동의 전제조건을 판단할 수 없으면, 그 조건을 구분할 센서 조회·다른 시점 관찰을 행동 후보로 둔다.
- 초기 belief 구현은 명시적 facts/unknowns/alternative hypotheses 구조여도 된다. 이 구조를 썼다고 정식 베이지안 POMDP 보장까지 생기지는 않는다.

**API 실험 핵심:** 같은 현재 관찰이지만 이력이 다른 쌍을 만든다. 실제 조리가 이어지는 이력과 조리가 끝난 이력이 같은 ON 상태로 끝나게 하고, 행동이 달라져야 하는지 본다. 현재 입력만으로 구분 불가능한 쌍에서는 숨은 정답을 맞히라고 요구하지 않는다.

## 2. Active Perception: 필요한 정보를 스스로 얻는 행동

**Ruzena Bajcsy (1988), Proceedings of the IEEE 76(8), 996–1005, invited paper.**  
[원문](https://people.eecs.berkeley.edu/~yang/courses/cs294-6/papers/Bajcsy.active%20Perception.pdf), [저자 대학 출판 목록](https://people.eecs.berkeley.edu/~bajcsy/).

### 원문 핵심

§II는 인지 목표와 현재 해석에 따라 데이터 획득 방식을 조절하는 active sensing을 정의한다. 단순히 센서가 방사 신호를 보내는 의미의 “능동 센서”와 다르다. §VIII는 추정 오차뿐 아니라 관측 횟수·센서 제어 비용을 포함한 손실과 관측 종료를 다룬다. 초점·스테레오 등 사례를 제시하며, 일반 가정 행동 판단을 검증한 연구는 아니다.

### 우리 적용 제안

OBSERVE를 추상적인 “더 확인”으로 두지 않는다. 최소한 다음을 출력한다.

- 부족한 사실: 예를 들어 창문 안쪽으로 비가 유입되는지.
- 현재 후보를 가르는 이유: 유입 여부가 창문 조치의 우선순위를 바꿀 수 있음.
- 수행 가능한 관찰: 해당 창문 방향 카메라 조회 또는 관련 센서 조회.
- 반환 기대값: 유입 / 유입 안 됨 / 관찰 실패.
- 관찰 후 분기와 제한: 어떤 결과가 오면 어느 후보를 재평가할지, 기다릴 수 있는 시간.

단순 정보량 최대화보다 **결정을 바꾸는 정보**가 중요하다. 예를 들어 청소 여부를 정하는데 벽 색깔을 더 정확히 아는 것은 큰 도움이 없다. 관측 비용에는 API 비용만 아니라 이동·시간·사생활 부담·지연에 따른 손실도 포함될 수 있다. 이는 우리 문제에 대한 적용이다.

## 3. Horvitz: 먼저 행동하는 것의 이득과 방해 비용

**Eric Horvitz (1999), Principles of Mixed-Initiative User Interfaces, CHI ’99, 159–166.**  
[Microsoft Research 공식 페이지](https://www.microsoft.com/en-us/research/publication/principles-mixed-initiative-user-interfaces/), [저자 기관 원문](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz.pdf).

### 원문 핵심

원문 “From Beliefs to Actions”는 사용자가 서비스를 원할 가능성과 행동·무행동의 효용을 결합한다. “Dialog as an Option for Action”은 질문도 비용·이익이 있는 대안으로 다룬다. “User Attention and the Timing of Service”는 개입 시점과 지연을 다룬다. LookOut 일정 관리가 사례이며 가정 로봇 실험이 아니다.

### 우리 적용 제안

사용자 질문을 최소화한다는 목표는 “불확실할 때마다 ASK” 정책을 피해야 한다는 뜻이다. 대신 자동 관찰, 잠시 대기, 덜 침해적인 조치가 충분한지 비교한다. 질문을 0회로 만들기 위해 불확실한 일을 무조건 수행하는 것도 목표에 맞지 않는다.

먼지가 있는 방에서 로봇청소기를 돌릴지는 청소 이익만으로 정해지지 않는다. 방 사용 중 여부·소음 민감 시간·이동 가능 상태·진행 중인 작업 등 후보 행동의 비용과 충돌을 평가해야 한다. “선제적”은 “항상 많이 개입”이 아니다.

**API 실험 핵심:** 똑같이 먼지 많은 장면에서 방 사용 상태만 바꾸어 즉시 청소·예약·대기의 선택이 정책과 맞는지 본다. 효용이나 우선순위는 시스템 목적에 속하므로 모델이 임의로 새로 만들어내는 숫자를 정답으로 간주하지 않는다.

## 4. Options: 행동은 한 번의 출력보다 오래 지속된다

**Sutton, Precup, Singh (1999), Artificial Intelligence 112(1–2), 181–211.**  
[출판사 원문·서지](https://www.sciencedirect.com/science/article/pii/S0004370299000521), [논문 사본](https://people.eecs.berkeley.edu/~russell/classes/cs294/f05/papers/sutton%2Bal-1999.pdf). 일부 사본의 텍스트 추출 인코딩은 불량하므로 출판사 서지를 기준으로 쓴다.

### 원문 핵심

options는 시간에 걸쳐 수행되는 닫힌 고리 정책이다. 시작 가능한 상태, 내부 정책, 종료 조건으로 표현하고, 일반 행동과 함께 계획·학습할 수 있게 한다. 논문은 실행 중 옵션 중단, 부분 실행으로부터의 학습, 하위 목표를 다룬다. 완전 관측 MDP 기반 틀을 그대로 부분 관측 가정 문제의 해법으로 간주하면 안 된다.

### 우리 적용 제안

“청소 시작” 이후에도 작업 상태를 유지한다.

- 시작 조건: 필요한 장치·접근 조건 충족.
- 실행 상태: 시작 요청 / 진행 중 / 일시정지 / 성공 / 실패 / 취소.
- 성공 조건: 요청 전송 성공과 실제 청소 완료를 구분.
- 중단·재판단 조건: 새 사용자 활동, 우선순위 높은 사건, 장치 오류 등.
- 중복 방지: 이미 청소 중인데 매번 동일한 시작 명령을 내리지 않음.

이 아이디어를 쓰는 데 처음부터 강화학습을 할 필요는 없다. 기존 장치 기능을 이런 실행 단위로 감싸고, API는 어느 단위를 시작·유지·취소할지 선택하는 방식으로 시험할 수 있다. 옵션을 정의하는 것과 옵션 정책·종료 조건을 학습하는 것은 다른 작업이다.

## 5. BDI: 할 수 있는 일, 원하는 결과, 실제로 맡은 일을 구분한다

**Rao and Georgeff (1995), BDI Agents: From Theory to Practice, ICMAS ’95.**  
[AAAI 원문 PDF](https://cdn.aaai.org/ICMAS/1995/ICMAS95-042.pdf).

### 원문 핵심

belief·desire·intention은 정보 상태·목표 상태·현재 채택한 계획을 구분한다. “Abstract Architecture”의 반복 구조는 사건에서 후보 생성, 숙고, 의도 갱신, 실행, 새 사건 수신과 완료·불가능한 의도 제거를 포함한다. commitment는 매순간 계획을 바꾸는 것과 상황 변화에 둔감한 것 사이의 균형이다. OASIS 항공 교통 관리 응용을 설명하지만, 모든 불확실성 판단을 자동으로 해결하는 단일 학습 알고리즘은 아니다.

### 우리 적용 제안

집 전체에서는 창문·주방·청소 문제가 동시에 발생한다. 각 객체별 독립 판단만으로는 충돌을 해결하기 어렵다. 별도 목표 후보 목록과 현재 진행 중 작업을 둬야 한다.

BDI라는 표현 때문에 반드시 LLM 세 개, 혹은 방마다 LLM 하나를 둘 이유는 없다. 하나의 모델을 호출하더라도 사건·상태 저장소와 실행 관리 코드를 분리해 이 구조를 구현할 수 있다. 실제 분산 실행·정보 분리가 필요할 때 멀티에이전트를 비교한다.

**API 실험 핵심:** 청소를 시작한 뒤 더 시급한 사건이 나타나는 시나리오, 같은 사건이 반복 전달되는 시나리오, 이미 불가능해진 목표를 계속 고집하는 시나리오를 넣는다.

## 6. Simplex: 판단 모델의 성능과 실행 보장을 분리한다

**Rivera et al. (1996), An Architectural Description of the Simplex Architecture, CMU/SEI-96-TR-006.**  
[CMU SEI 보고서·초록](https://www.sei.cmu.edu/library/an-architectural-description-of-the-simplex-architecture/), [원문 PDF](https://www.sei.cmu.edu/documents/1146/1996_005_001_16463.pdf).

### 원문 핵심

복잡한 제어기와 단순한 고신뢰 제어기를 구분하고, 실행 시점에 제어 권한을 선택하는 아키텍처다. §2.2.1은 상태·성능을 충분히 빨리 평가할 수 있고 단순한 안전 제어기를 설계할 수 있어야 한다고 명시한다. 보고서는 CSP 모델과 FDR 도구로 구조의 안전성·활성 속성을 검토한다. 임의의 LLM 뒤에 if 문을 붙이면 같은 보장이 생기는 것은 아니다.

### 우리 적용 제안

모델이 추천하는 행동과 실행 명령을 분리한다. 상태 버전, 장치별 전제조건, 명령 허용 범위, 동시 동작 충돌, 응답 기한 등을 실행 계층에서 검사한다. 긴 언어모델 숙고를 기다릴 수 없는 상황은 별도의 응답 경로가 필요할 수 있다.

가스 관련 사례에서 어떤 센서 상태를 무엇으로 간주하며 어떤 조치를 허용할지는 장치·현장 안전 요구사항의 문제다. 일반 LLM이 임의로 만든 규칙을 실제 가스 제어의 검증된 정책으로 취급하지 않는다. 이번 단계는 합성 시나리오의 판단 비교로 제한한다.

| 명시적 상태·사건 저장소 + 하나의 API 판단기 + 실행 관리 | 모델 교체 가능, 오류 위치 추적, 중복·오래된 명령 관리 | 상태 표현과 정책을 직접 정해야 함 | 첫 본 실험 후보 |
| 작은 영역의 명시적 POMDP/VOI 계획 | 관찰과 행동을 계산적으로 비교, 가정 명확 | 전이·관측 확률·보상·시뮬레이터가 필요 | 창문 또는 컵 등 작은 문제의 비교 기준 |
| 여러 LLM 에이전트 | 정보/전문 역할 분담 가능 | 통신비용·상충 결론·공통오류, 최종 판단자 필요 | 단일 모델의 구체적 실패가 확인될 때 비교 |
| 미세조정된 로컬 모델 | 자주 반복되는 판단·출력·도구 정책 특화 가능 | 레이블·평가 자료와 안정된 정책 필요 | 먼저 실패 유형과 교정 자료 확보 후 검토 |

여기서 모듈 분리는 멀티에이전트와 동의어가 아니다. 상황 추정과 후보 평가를 구조화했다고 해서 네트워크 가중치를 수정해야 하는 것도 아니다. 모델 수정 여부는 설계 의도가 아니라 같은 평가 조건에서의 성능·지연·비용 결과로 정하는 편이 타당하다.

## 추가 관찰의 가치: 첫 실험에 쓸 수 있는 좁은 계산 예

현재 belief에서 가장 좋은 행동의 기대 효용과, 관찰 q의 가능한 결과를 받고 다시 선택했을 때의 평균 효용을 비교한다.

```text
추가 관찰 가치(q)
= 관찰 결과별 최선 행동의 평균 가치
  - 지금 바로 고른 최선 행동의 가치
  - 관찰 비용
  - 관찰을 기다리는 지연 비용
```

이는 정지 환경에 가까운 한 단계 근사 예시다. 관찰 중 상태가 바뀌거나, 여러 번의 관찰이 연쇄적으로 필요하면 더 일반적인 순차 모델이 필요하다. 모델이 그럴듯한 숫자를 출력했다는 것만으로 이 계산을 제대로 수행했다고 판단할 수 없다.

첫 실험에서는 정답을 아는 작은 합성 세계에서 비교할 수 있다. 예를 들어 동일 입력에 대해 “가능한 상태 A/B”, 각 상태에서 허용 행동과 손실, 관찰 성공률·비용을 연구자가 명시한다. API가 판단하는 것과 작은 계산 기준선이 선택하는 것을 비교한다. 이때 실제 센서 확률을 측정했다는 주장을 하지 않는다.

## 데이터와 평가에서 놓치기 쉬운 부분

1. 관측 기록에는 시각뿐 아니라 출처·관찰 시각·객체 ID·신선도·오류 가능성이 필요하다. 중복 기록을 독립 증거로 더하면 확신이 부풀 수 있다.
2. 상태 추정에는 확인된 사실, 미확인 값, 상충하는 증거를 구분한다. 자연어 설명이 확신에 차 있다고 믿음을 숫자로 보정한 것은 아니다.
3. 행동 집합에 실행·관찰·대기 외에 진행 중 작업의 유지·중단·취소를 고려한다. 새 실행 후보만 생성하는 판단기는 생활 전체의 흐름을 다루기 어렵다.
4. 정보획득 평가는 “무언가를 관찰했는가”가 아니라 “실제 결정에 필요한 정보를 얻었는가, 쓸모없는 관찰·반복은 얼마나 했는가”로 한다.
5. 집 전체 평가에는 다중 사건·자원 충돌·시간 제약을 넣는다. 청소와 창문을 따로 잘 판단하는 것만으로 우선순위 판단을 검증할 수 없다.
6. 에피소드 전체의 과도 개입, 필요한 개입 누락, 행동 완료, 중단 대응, API 시간·호출 수를 함께 본다. 단일 시점 행동 정확도만으로는 기다리기만 하는 정책이나 과잉 행동을 구분하기 어렵다.
7. 평가 레이블에 미래·숨은 의도 정보를 사용하더라도 모델이 그 정보를 관측할 수 없었다면, 허용 가능한 관찰/대기 대안도 정해야 한다. 전지적 정답을 강요하지 않는다.
8. 합성 데이터 작성자의 상식과 모델의 상식이 같은 편향을 공유할 수 있다. 반례 쌍·경계 사례·실패 피드백을 먼저 정하고 모델 실행 뒤 결과에 맞춰 정답을 바꾸지 않는다.

## 권장 독서 순서

설계 질문을 직접 푸는 순서는 **POMDP §3 → Active Perception §II·§VIII → Horvitz의 From Beliefs to Actions → Options → BDI → Simplex**다. 전부 구현할 필요가 없다. 첫 세 편으로 “무엇을 알고, 무엇을 더 볼지, 언제 행동할지”를 정리하고, 뒤 세 편으로 “얼마 동안 지속하고, 언제 바꾸며, 누가 실행을 승인할지”를 구체화할 수 있다.
