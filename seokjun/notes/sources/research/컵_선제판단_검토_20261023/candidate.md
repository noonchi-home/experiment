# 컵을 언제 치울 것인가: 선제 판단 연구와 첫 합성 실험 설계

조사 기준: 2026-10-23. 아래 논문 설명은 원문 확인 내용이고, 컵 입력·출력·실험 구성은 Codex의 설계 제안이다. 예시는 실제 DeepSeek 실행 결과가 아니다.

**맞다. ‘해석→제안→승인’이라는 상자만 그려서는 네가 연구하려는 핵심을 설명한 것이 아니다. 핵심은 명령을 받기 전에, 관찰 이력에서 ‘사용자가 아직 컵을 쓰는 중인지, 이제 치워 주는 것이 도움이 되는지’를 추정하고 개입 시점을 선택하는 것이다.** 이번에는 집 전체를 다루는 층별 설계를 잠시 내려놓고 이 판단 자체를 좁혀 보자.

## 1. 이번에 찾은 직접적인 논문

### A. PAM — 컵 문제를 설계할 때 가장 먼저 읽을 논문

**An Agentic Framework for Proactive Robots with Procedural Assistance Memory** (2026-10-15 공개).

논문은 같은 빈 그릇이 식사 전에는 준비 도움의 단서이고, 식사 후에는 치울 대상이 되는 문제를 직접 다룬다. 최근 관찰과 사용자의 생활 흐름을 함께 보는 접근이다. 실제 판단 모델은 최근 5개 프레임, 활동 단계·조건·행동을 담은 외부 기억, 가능한 작업 목록을 받아 작업 번호 또는 NO_ACT를 출력한다. 기억의 상태도는 코드로 강제 실행하는 규칙표가 아니라 모델이 읽는 문맥이다. 판단 모델의 가중치를 바꾸지 않고 관찰 기록으로 기억을 갱신한다. 로봇 팔 실행기는 별도로 미세조정한다. [원문 §3, 부록 A.2–A.3·E.3](https://arxiv.org/html/2610.21211v1)

한계도 명확하다. 주요 판단 평가는 한 사람의 약 3.5–4.5분 책상 루틴을 5일 기록한 것이다. 집 전체에서 장기간 검증한 결과가 아니다. ‘그릇 치우기’의 마지막 날 판단 F1은 0.60±0.09이며, 어떤 추가 관찰을 할지 고르는 행동은 없다. 저자 페이지와 arXiv는 CoRL 2026으로 표기하지만 수상이나 독립 재현은 확인하지 않았다. [원문 부록 A.1·B](https://arxiv.org/html/2610.21211v1), [저자 페이지](https://davian-robotics.github.io/PAM/)

**가져올 아이디어:** 컵 자체의 상태뿐 아니라 ‘준비→사용→잠시 중단→사용 종료’ 같은 활동 맥락을 표현한다. 이 단계 이름과 컵 적용은 우리의 설계 제안이며, 논문이 이 상태들을 그대로 정의한 것은 아니다.

### B. Proactive Physical AI — 개입 시점을 학습하는 접근

**Proactive Physical AI through Continuous Observation and Timely Intervention** (2026-10-12 공개).

연속 관찰에서 ‘지금 개입할 것인가’를 결정하는 Timing Model과, 개입한다면 무엇을 할지 만드는 Response Model을 구분한다. 구체적인 매번의 명령 없이 지속적인 역할만 주는 조건도 평가한다. Timing Model은 Qwen3.5-4B를 바탕으로 학습하며, 영상에서 만든 시점별 감독 신호를 사용한다. 응답 모델은 별도 가중치 학습 없이 문맥 프롬프트를 사용한다. 따라서 이 논문은 **선제 판단을 실제로 추가 학습하는 방향**의 직접적인 예다. [원문 §3·부록 G.2–G.3](https://arxiv.org/html/2610.16967v1)

저자 보고 role-only 조건의 개입 시점 F1은 33.45%로, 아직 해결된 문제라고 볼 수 없다. 사람에게 말하거나 기기 기능을 호출하는 체계여서 컵 치우기만을 검증한 연구도 아니다. 현재 확인 범위에서는 최신 사전공개 논문이며, 수상·충분한 재현 검증을 주장할 근거는 없다. [원문 §4.1](https://arxiv.org/html/2610.16967v1)

**가져올 아이디어:** ‘좋은 행동을 말하는 능력’과 ‘말하거나 행동해야 할 순간을 고르는 능력’을 따로 평가한다. 처음부터 모델 두 개를 만들어야 한다는 뜻은 아니다. 같은 API 모델로도 두 평가 항목을 분리할 수 있다.

### C. Proactive Robot Assistance via Spatio-Temporal Object Modeling

**Maithili Patel·Sonia Chernova, CoRL 2022 / PMLR 2023.** 학회 논문집에 정식 게재된 앞선 연구다.

시간에 따른 물체 배치 이력으로 그래프 신경망을 학습하고, 추론할 때는 현재 배치와 시각으로 미래 위치를 예측하여 미리 옮기는 도움을 제공한다. 5개 가상 가정의 50일 이상 일상 물체 이동 데이터를 사용한다. ‘사용자가 어떤 물체를 언제 어디에서 쓰는가’를 학습한다는 점에서 물체 기억과 연결된다. 다만 미래 위치 예측과 지금 치워도 되는 판단은 같지 않다. 저자들도 식사가 평소보다 길어지면 너무 일찍 치울 수 있고 물체의 깨끗함/더러움을 모델링하지 않는 한계를 설명한다. [학회 원문](https://proceedings.mlr.press/v205/patel23a.html), [PDF §8](https://proceedings.mlr.press/v205/patel23a/patel23a.pdf)

**가져올 아이디어:** 모델이 현재 장면뿐 아니라 물체별 사용 이력을 이용하게 한다. 다만 ‘보통 이때 싱크대에 있었다’를 곧바로 ‘오늘도 지금 치워도 된다’로 바꾸지 않는다.

### D. ContextAgent는 무엇을 실제로 학습하는가

ContextAgent는 시각·음성·알림을 상황 문맥으로 만들고, 사용자 문맥과 함께 판단 모델에 넣는다. 모델이 선제 서비스 점수와 도구 호출을 출력한다. 논문의 주 제안은 고급 모델에서 얻은 판단 설명을 포함하는 데이터로 SFT/LoRA를 하는 방식이다. 예시만 프롬프트에 넣는 ICL 방식은 비교군과 구분해야 한다. [원문 §4.2–5.1](https://arxiv.org/html/2505.14668)

공식 저장소의 API 비교군도 확인했다. 상황 설명·사용자 문맥·예시·도구 명세를 프롬프트로 구성한 뒤 모델 출력을 파싱하고 도구를 실행한다. 상황별 상식 전체가 거대한 if문으로 들어 있는 것은 아니다. 이 경로는 논문에서 학습한 모델 그 자체의 구현과 구분해야 한다. [고정 커밋의 API 코드](https://github.com/openaiotlab/ContextAgent/blob/f4674bf2a1385ce829c6a7f2ea9c53871dd1a8ce/src/icl/inference_api.py)

따라서 **PAM은 생활 흐름에 따른 해석, Proactive Physical AI는 개입 시점 학습, ContextAgent는 상황에서 선제 판단·도구 호출을 학습하는 방법**을 참고할 수 있다. 유명한 논문 하나가 모든 판단을 해결해 주지는 않지만, 이전에 소개한 범용 명령 수행 논문보다 이 세 연구가 현재 질문에 더 직접적이다.

## 2. 입력 데이터는 ‘관측 사실’과 ‘추정’을 나눠 해석해야 한다

첫 합성 실험에서는 사진 인식까지 한꺼번에 시험하기보다, **센서가 이미 관측했다는 설정의 시간표가 붙은 구조화 데이터**로 시작할 수 있다. 그러면 이번 실험이 검증하는 것은 시각 인식 성능이 아니라 그 데이터로 행동을 결정하는 능력이다. 나중에 실제 영상 인식이 추가되면 오인식까지 별도로 평가해야 한다.

컵 실험에 필요한 최소 입력 후보는 다음과 같다. 가스·날씨처럼 이 상황과 무관한 모든 집안 정보를 매번 넣을 필요는 없다.

| 정보 | 예 | 왜 필요한가 |
|---|---|---|
| 물체 식별과 현재 상태 | cup_07, 책상 오른쪽, 내용물은 가려져 알 수 없음 | 다른 컵과 이력이 섞이지 않도록 함 |
| 시간 순서의 사건 | 10:00 컵에 물을 따름, 10:10 입에 대고 마심, 10:12 내려놓음 | 준비/사용/중단의 맥락 추정 |
| 사람과 주변 활동 | 노트북을 닫음, 가방을 들고 방에서 나감, 이후 관측은 없음 | 자리 비움과 활동 종료를 구분할 단서 |
| 물체별 과거 기록 | 비슷한 상황에서 재사용했는지, 나중에 직접 치웠는지 | 일반 상식과 개인 생활 습관 구분 |
| 기록의 출처와 시각 | 카메라 A, 10:13 관측, 내용물 판독 불가 | 과거 사실을 현재 사실로 착각하지 않도록 함 |
| 허용된 도움의 범위 | 사용이 끝난 빈 컵을 지정 수거 위치로 이동 | ‘도움이 되는 행동’의 기준 설정 |
| 가능한 확인 방법 | 컵 내부 확인, 최근 물 따르기 기록 조회 | 무엇을 더 보면 결정이 달라질지 선택 |

‘비어 있음’은 관측값이고, ‘사용이 끝났음’은 보통 추정이다. `사용종료=true`, `치워도됨=true`를 입력에 넣으면 시험하려는 판단의 답을 미리 알려 주게 된다. 반대로 실제로 확인하지 못한 상태를 모델이 말로 만들어 채우게 해서도 안 된다.

## 3. 컵 하나로 판단이 실제로 어떻게 흘러가는가

아래는 **우리 실험을 설명하기 위한 가상의 사례**다. 임시 실험 조건은 ‘사용이 끝난 빈 컵을 수거 위치로 옮기는 도움은 허용, 내용물이 있는 컵은 이동하지 않음’이다. 이것은 사용자의 실제 선호를 알아냈다는 뜻이 아니며, 일반적인 컵 이동의 필수 조건도 아니다. 무엇이 정답인지 정하기 위한 조건이다. 세척이나 내용물 버리기는 이번 행동에 포함하지 않는다.

```text
관측 E1  10:00  cup_07에 음료가 담김
관측 E2  10:10  사람이 cup_07로 마심
관측 E3  10:12  컵을 책상 가장자리에 내려놓음
관측 E4  10:13  노트북을 닫고 가방을 들고 방에서 나감
현재     10:14  컵은 그대로 있음. 내용물은 보이지 않음
기억 M1  과거 유사 장면에서 컵 사용이 끝난 사례가 여러 번 있었음
```

먼저 코드가 하는 일은 같은 물체의 기록을 묶고, 시간 순서를 맞추고, 경과 시간과 누락 상태를 계산하는 것이다. 코드가 E4를 읽고 무조건 ‘음료 사용 종료’라고 확정하지 않는다.

그 다음 모델이 해야 하는 해석은 다음과 같다.

- **주요 가설:** 방금 활동을 마치고 떠났으므로 컵 사용도 끝났을 수 있다. E4와 M1이 근거다.
- **경쟁 가설:** 가방을 들고 잠깐 나갔거나 나중에 다시 마실 수도 있다. 현재 관측만으로 배제할 수 없다.
- **결정에 영향을 주는 빈칸:** 내용물이 있는지는 모르며, 이것은 이번 실험의 이동 조건에 직접 영향을 준다.
- **다음 선택:** 내부 확인이 실제로 가능하고 다른 미확인 조건보다 우선할 가치가 있으면, 곧바로 치우는 대신 확인 행동을 고른다.

여기서 ‘내부를 본다’는 행동도 무조건 정답은 아니다. 사람이 컵을 현재 잡고 있다면 내용물이 무엇이든 지금 옮길 수 없으므로, 내부 확인은 당장 쓸모없는 추가 행동일 수 있다. **확인 결과가 다음 행동을 바꿀 수 있는지가 정보 선택의 기준**이다.

API 출력 형식의 예를 들면 다음과 같다. 아래 내용은 원하는 형식의 예시이지 모델이 실제로 답했다는 기록이 아니다.

```json
{
  "object_id": "cup_07",
  "activity_assessment": "사용 종료 가능성은 있으나 재사용 가능성이 남음",
  "supporting_observations": ["E4", "M1"],
  "unresolved": ["현재 내용물", "재사용 의도"],
  "next_step": "OBSERVE_CONTENTS",
  "why_this_check": "내용물이 있으면 현재 정책상 이동 불가",
  "after_observation": {
    "liquid_present": "LEAVE",
    "empty": "사용 종료 근거까지 다시 평가하고 이동 또는 기다림 선택",
    "unreadable": "LEAVE_AND_RECHECK_ON_NEW_EVENT"
  }
}
```

내용물이 빈 것으로 나와도 자동으로 치우면 안 된다. ‘비어 있음’은 물체의 상태만 해결했고, ‘더 쓸 것인가’는 아직 남아 있기 때문이다. 재사용 준비를 하는 최근 행동이 보이면 놔둬야 한다. 반대로 과거 이력과 현재 활동 종료 단서가 함께 충분하다고 판단되는 시험 사례라면 이동을 선택할 수 있다. 얼마나 충분해야 하는지는 검증 데이터에서 오개입과 놓친 도움을 함께 보고 정할 대상이다.

또한 카메라를 더 본다고 항상 속마음이 드러나지는 않는다. 추가 관찰로 구분할 수 없는 사례에서는 기다리거나 개입하지 않는 것도 정당한 결론이다. 사용자에게 매번 묻는 것을 기본 해결책으로 두지 않는다.

**이것이 거대한 로직의 핵심이다: 관측을 사실로 정리하고 → 활동이 어느 단계인지 추정하고 → 그 추정이 틀렸을 가능성을 남기고 → 행동을 바꿀 정보가 있는지 평가하고 → 지금 할 행동을 선택한다.** 각 단계를 별도 에이전트로 만들 필요는 없고, 첫 API 실험에서는 하나의 모델이 이 구조의 응답을 내도록 할 수 있다. 다만 이 출력 설명은 모델의 내부 작동을 증명하는 것이 아니라 검증할 수 있는 판단 보고서다.

## 4. 같은 현재 상태에서도 다른 결정을 해야 한다

다음은 논문 결과가 아닌, 우리가 만들어야 할 반례형 합성 사례다.

| 같은 현재 상태: 책상 위 빈 컵 | 서로 다른 과거·현재 단서 | 기대하는 판단 방향 |
|---|---|---|
| 빈 컵 | 방금 꺼냈고 물을 따를 준비 중 | 사용 전이므로 놔둠 |
| 빈 컵 | 막 마셨고 물병을 가져와 다시 따르려 함 | 재사용 중이므로 놔둠 |
| 빈 컵 | 사용 후 다른 활동으로 넘어갔으며 종료를 뒷받침하는 이력 있음 | 허용 범위에서 치우기 후보 |
| 빈 컵 | 가려졌던 컵이라 누가 언제 썼는지 모름 | 빈 컵만 보고 사용 종료를 확정하지 않음 |

여기서 연구할 것은 마지막 행까지 항상 정답을 알아맞히는 초능력이 아니다. **구분할 근거가 있으면 활용하고, 없으면 그 한계를 행동에 반영하는가**다. 반대로 모든 상황에서 놔두기만 하면 유용한 선제 도움을 제공하지 못하므로, 실제로 치워야 하는 양성 사례도 반드시 포함해야 한다.

## 5. 우리가 만들어야 할 로직은 어디에 있는가

| 구성 | 첫 합성 API 실험에서 맡길 일 |
|---|---|
| 데이터 처리 코드 | 물체 ID·시각·관측 출처 관리, 사실 이력 구성, 모르는 값 보존 |
| 모델과 프롬프트 | 사용 단계·재사용 가능성 해석, 도움 필요성 판단, 관찰/대기/이동 선택 |
| 외부 기억 | 관측된 과거 사례와 생활 흐름 제공. 정답 라벨이나 미래 기록은 제외 |
| 실행 검사 코드 | 존재하는 컵·지원하는 행동·필수 조건 확인. 허용하면 선택된 행동을 모의 실행하고, 거절하면 이유를 반환 |
| 합성 환경 | 관찰 요청 결과와 행동 이후의 상태를 반환 |
| 평가기 | 너무 일찍 치움, 필요한데 안 치움, 불필요한 확인, 지연, 중복 행동 측정 |

초기에 언급한 ‘코드가 피해 비용표로 최종 행동을 고른다’는 설계는 반드시 채택할 구조가 아니다. 모델이 의미를 해석하고 행동을 선택하며, 코드는 실행 조건을 검사하도록 시작할 수 있다. 모델이 만들어 낸 확률을 사실처럼 비용 계산에 넣으면 코드로 계산했다는 이유만으로 정확해지는 것이 아니다.

프롬프트에는 역할·행동 목록·판단 보고 형식·예시를 준다. 그 안에 모든 생활 상황의 정답을 if문으로 쓰지는 않는다. 상황을 연결하는 능력은 사전학습된 모델에 의존하되, **컵 문제에서 그 능력이 실제로 충분한지 실험으로 확인한다.** 반복되는 실패가 입력 부족인지, 기억 표현 문제인지, 판단 정책의 학습 부족인지에 따라 개선 방법이 달라진다.

## 6. 합성 데이터는 한 장면 묘사보다 ‘진행하는 에피소드’로 만든다

실험 환경이 보관하는 전체 상태와 모델이 현재 볼 수 있는 관측을 분리한다. 관찰 도구는 미리 생성한 합성 세계에서 해당 시점의 결과만 반환한다. 모델이 ‘컵 안을 봤더니 비어 있었다’고 스스로 결과를 지어내는 방식은 사용하지 않는다.

```text
관측 이력 제공
  → 모델: 컵 내부를 확인
  → 합성 환경: 액체 있음 / 비어 있음 / 확인 불가
  → 모델: 놔둠 / 더 기다림 / 이동
  → 합성 환경: 후속 상태와 사용자 행동
  → 평가
```

추가 확인 후에는 시간이 흘렀으므로 컵이나 사람의 상태가 변했을 수 있다. 실행 직전 상태를 다시 확인하고, WAIT도 다음 사건이나 정해진 재평가 시각에 다시 판단하게 한다. 한 번의 응답만으로 실험을 끝내면 이 부분을 시험하지 못한다.

라벨 설계에는 주의가 필요하다. 합성 생성기가 ‘사실 사용자는 다시 마실 생각이었다’는 숨은 답을 알고 있어도, 모델이 가진 관측으로 구분할 수 없었다면 유일한 정답 행동을 강요하지 않는다. 정보가 충분한 사례에는 행동·허용 시점 구간을, 모호한 사례에는 허용 가능한 행동 집합이나 추가 관찰 필요성을 표시한다. 과거 기록으로 만든 기억에도 시험 에피소드의 미래가 새면 안 된다. 사람이 나중에 컵을 되돌렸다는 사실 하나만으로 이전 결정이 무조건 잘못이었다고 라벨링하지 않는다.

## 7. 첫 실험에서 비교할 것

같은 DeepSeek 모델·행동 목록·가정 정책·출력 형식을 유지하고 다음 입력 조건을 비교하는 것을 제안한다.

1. 현재 상태만 제공.
2. 현재 상태 + 시간순 사용 이력.
3. 2번 + 이전 에피소드에서 얻은 활동 흐름 기억.
4. 3번 + 필요한 관찰을 선택하는 도구.

1–3번은 판단 입력의 차이를, 3–4번은 추가 정보 획득의 효과와 비용을 평가한다. 단순 시간·상태 규칙도 비교군으로 둔다. 활동 단계 설명을 출력하게 하는 형식은 모든 조건에 공통으로 주어, 기억 유무와 출력 형식의 효과가 섞이지 않게 한다.

정확도 하나만으로 판단하지 않는다. 안 치워야 할 때 치운 비율, 치워도 되는 기회를 놓친 비율, 적절한 시점에서 얼마나 늦었는지, 불필요한 관찰 횟수를 함께 본다. 너무 일찍 개입한 사례, 일시적 자리 비움, 재사용, 여러 컵, 관측 누락, 습관 변경, 긴 무개입 구간을 포함한다. 같은 템플릿의 문장만 바꾼 사례를 학습·시험 양쪽에 나누지 않고 에피소드·루틴 단위로 분리한다.

그 다음에 모델 학습 여부를 결정한다. 추가 정보와 기억을 줘도 반복해서 잘못된 시점에 개입한다면, **관측 이력→개입 여부/행동/추가 관찰** 데이터로 SFT/LoRA를 하는 가설을 시험할 수 있다. 이런 학습 방향은 존재한다. 하지만 먼저 라벨과 평가를 만들지 않은 채 모델부터 미세조정하면 ‘무엇을 더 잘하게 만들었는지’를 알기 어렵다.

**지금 제안하는 연구 초점은 ‘명령 없이, 컵의 시간적 사용 맥락에서 치울 시점을 판단하고, 부족한 경우 행동을 바꿀 관측을 선택하는가’이다.** PAM을 중심으로 첫 판단 구조를 잡고, 개입 시점 학습과 추가 관찰을 각각 검증할 가설로 두는 편이 현재 목표와 맞는다. 이것이 새로운 학술 기여인지, 실제 가정에서도 유효한지는 별도의 비교와 후속 검증이 필요하다.
