# Codex 초안 검토: 일부 수정 필요 (revise)

**검토 범위:** 첨부된 출처 메모(source_evidence.md)와 초안(candidate.md)만 대조했습니다. 논문 원문과 코드는 직접 열람하지 않았고, 실험도 실행하지 않았습니다.

## 총평
초안의 큰 구조는 좋습니다.
- 논문이 실제로 한 일과 컵 실험 설계 제안을 구분했습니다.
- 예시 JSON이 실제 DeepSeek 실행 결과가 아니라고 명시해, 실제 API를 돌린 것으로 오해할 표현이 없습니다.
- '비어 있음(관측)'과 '사용 종료(추정)'를 분리했습니다.
- 라벨 누출을 막고, 실제로 치워야 하는 사례도 포함하도록 했습니다.
- "확인 결과가 다음 행동을 바꿀 때만 관찰한다"는 기준을 세웠습니다.

다만 아래 사항은 고쳐야 합니다. 대부분 해당 부분만 손보면 됩니다.

## 맞음 (출처 메모와 일치)
- **PAM:** 공개일, 최근 5프레임 입력, 작업 번호 또는 NO_ACT 출력이 메모와 같습니다. 기억 상태도가 코드로 강제되는 규칙이 아니라는 점, 판단 모델은 재학습하지 않고 로봇 실행 모델만 미세조정했다는 구분도 맞습니다. 한 사람의 5일 책상 루틴, F1 0.60±0.09, 학회 게재 미확인 표기도 일치합니다.
- **ProAgent:** 개입 시점 모델(Timing)과 응답 모델(Response)의 분리, Qwen3.5-4B 학습, 응답 모델은 프롬프트만 사용한다는 설명이 맞습니다.
- **Patel·Chernova:** 게재 정보와 §8 한계 설명이 맞습니다.
- **ContextAgent:** 주 제안이 SFT/LoRA라는 점, API 경로가 프롬프트 구성→출력 파싱→도구 실행 순서라는 설명이 맞습니다.

## 일부 수정 필요
1. **ContextAgent 문장 오기**
   - "ICL 방식은 비교군과 구분해야 한다"는 틀린 문장입니다. ICL이 곧 비교군입니다. "ICL은 비교군이며 주 제안(SFT)과 구분해야 한다"로 고쳐야 합니다.
   - 메모에 따르면 논문은 점수가 기준값 이상일 때만 개입하지만, API 코드 경로에서는 그 기준값 비교가 보이지 않습니다. 예시의 비개입 점수 0도 논문의 1–5 척도와 다릅니다. 이 차이는 사용자의 3층(코드 승인)과 직결되는데 빠져 있습니다.
   - 사용자의 현재 방식(DeepSeek + 예시 프롬프트)은 구조적으로 ContextAgent의 ICL 비교군에 해당한다는 점도 적어 주면 좋습니다. 단, 둘의 성능 수치는 메모에 없어 판단할 수 없습니다.
2. **ProAgent 결과 보고가 불완전함**
   - 33.45%만 제시했습니다. 같은 입력·예산 조건에서 F1 28.72→33.45%, 분당 오개입 0.62→0.18이었다는 비교를 함께 적어야 합니다. 그래야 "개입 시점 모델이 오개입을 줄였다"는 핵심이 전달됩니다.
   - 이 F1은 에피소드 평균값입니다. 출처 위치도 §4.1보다 표1이 정확합니다.
3. **Patel 논문: 합성 데이터라는 사실 누락**
   - 이 논문의 HOMER 데이터는 실제 사람의 일정을 바탕으로 만든 합성 데이터입니다. 합성 데이터로 시작하려는 사용자에게 바로 쓸 수 있는 선례인데 빠졌습니다.
   - "50일 이상"보다 "50일 학습·10일 시험"이 정확합니다.
   - 그릇을 싱크대로 옮기는 로봇 시연(§7.4)도 컵 치우기와 가까운 사례입니다.
   - 초안의 PDF 링크는 메모에 없는 주소라 확인할 수 없습니다.
4. **PAM: 사용자 피드백 누락**
   - 메모상 PAM은 기억을 갱신할 때 사용자 피드백이 있으면 함께 반영합니다(§3.3). 사용자의 4층(피드백)에 대한 직접 선례인데 빠졌습니다.
   - "PAM에는 추가 관찰 행동이 없다"는 행동 목록(6개 작업+NO_ACT)에서 추론한 것이므로, 확인된 사실이 아니라 추론이라고 표시해야 합니다.
5. **사용자 1층의 '확신 정도'가 빠짐**
   - 사용자가 1층에 명시한 '확신 정도'가 출력 형식에 없습니다.
   - 모델이 낸 확률을 그대로 계산에 쓰지 말라는 경고는 타당합니다. 하지만 해결책은 확신 정도를 버리는 것이 아닙니다. 기록해 두고, 같은 확신 구간에서 실제로 얼마나 맞았는지(보정 정도) 측정하는 것입니다.
   - 초안 §3의 "얼마나 충분해야 하는지는 검증 데이터로 정한다"는 사실상 비용 기준값을 맞추는 일입니다. 그런데 §5는 비용표를 꼭 쓸 구조가 아니라며 뒤로 미룹니다. 두 부분이 어긋납니다.
   - §7에 'LLM이 직접 선택' 대 'LLM 판단 + 검증 데이터로 맞춘 기준값/비용표' 비교 조건을 추가하기를 권합니다.
6. **'유명하고 검증된 연구' 요구가 덜 충족됨**
   - 주력으로 소개한 PAM과 ProAgent는 기준일 1–2주 전에 나온 사전공개 논문입니다. 초안이 이를 정직하게 밝혔지만, 검증된 결정 이론 근거는 비어 있습니다.
   - 초안의 정보 선택 기준은 고전적인 정보가치(VOI)·POMDP 정보수집과 같은 원리입니다.
   - Horvitz의 "Principles of Mixed-Initiative User Interfaces"(CHI 1999)는 불확실한 사용자 의도 아래에서 행동·확인·무개입을 기대효용 기준값으로 고르는 원칙을 다루며, 사용자 질문에 가까운 고전입니다. 사용자에게 묻는 단계는 '관찰'로 바꿔 쓸 수 있습니다.
   - 이 항목들은 검토자의 배경지식이며 이번에 원문을 확인하지 않았습니다. 초안에 넣으려면 원문 확인이 필요합니다.

## 추가 권장 (필수 수정 아님)
- **기억 M1:** "끝난 사례가 여러 번"만으로는 기억이 한쪽으로 치우칩니다. 종료와 재사용 횟수를 함께 넣으세요(예: 10회 중 7회 종료, 3회는 30분 안에 다시 사용).
- **10:14 예시:** 사람이 나간 지 1분밖에 안 됐으므로 '기다림'도 유력한 선택입니다. 시간이 지나면 판단이 바뀌는 쌍 사례를 추가하면 좋습니다.
- **합성 데이터 생성:** 같은 LLM이 에피소드를 만들고 판단까지 하면 생성과 판단의 편향이 겹칩니다. 에피소드는 규칙 기반 시뮬레이터로 만들고, 정답 라벨은 생성 규칙에서 뽑는 방식을 권합니다.
- **반복 실행:** 같은 입력으로 여러 번 실행해 답이 일관되는지도 측정하세요.
- **0층 가스 안전:** 컵 단계에서 뺀 것은 "첫 상황은 컵"이라는 지시에 맞습니다. 다만 0~4층이 컵 실험의 어느 부분에 해당하는지 한 줄로 대응시켜 주면 사용자 질문에 더 직접 답이 됩니다.
- **판단 불가:** "이전에 소개한 범용 명령 수행 논문"은 이 문서만 읽는 독자에게는 무엇을 가리키는지 알 수 없습니다.
