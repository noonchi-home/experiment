# 컵을 치울지·둘지·더 관찰할지: 직접 관련 논문 조사

확인일:2026-10-23. 이 날짜까지 공개된 원문·저자 자료만 사용했다. 실제 모델 호출이나 구현 실험은 하지 않았다.

**이번 문제에 가장 가까운 읽기 순서는 PAM → Proactive Physical AI → Spatio-Temporal Object Modeling이다.** PAM은 사용이 끝난 그릇을 언제 치울지, Proactive Physical AI는 요청 없이 개입할 시점을, Spatio-Temporal은 물체 이력에서 선제 이동을 예측하는 방법을 직접 다룬다. 세 편 모두를 합쳐 이미 검증된 하나의 해법이라고 보아서는 안 된다.

## 1. PAM: 지금 이 그릇을 치울 때인지 활동 맥락으로 판단

정식 제목: **An Agentic Framework for Proactive Robots with Procedural Assistance Memory**, Lee 등. [arXiv](https://arxiv.org/abs/2610.21211)는2026-10-15 공개다. [저자 프로젝트](https://davian-robotics.github.io/PAM/)와 [연구실](https://davian-robotics.github.io/)은 CoRL2026으로 표기한다. 이번 조사에서는 학회 자체 프로그램·정식 proceedings 항목을 별도로 확보하지 못했다. 수상 확인 없음.

### 원문에서 확인한 것

- **입력·출력:** Qwen3.5-27B에 최근5프레임(t,t−2,…,t−8초), 시각, FSM기억, 고정된6개 행동목록을 제공한다. 매초 JSON의 `observation`, `reasoning`, `task_index`를 출력하며 −1은 NO_ACT다(§3.1, 부록A.2·E.3).
- **판단 방식:** 활동단계·단계별 조건→행동·단계전환을 텍스트로 읽는 **prompt 기반 VLM 선택**이다. FSM은 강제 실행기가 아니다. E.3은 단일상태에 확정할 필요가 없다고 하며, 기억과 상태배정이 정확히 일치하지 않아도 의미상 적합하면 선택하도록 한다.
- **실제 프롬프트 발췌:** “Treat the memory as a REFERENCE, not as a strict matcher.” 사람의 손이 닿은 물체는 내려놓을 때까지 조작하지 않도록 지시한다.
- **정리 사례:** §3.2의 빈 그릇은 식사전에는 시리얼 배달, 식후에는 정리 대상이다. §4.1·그림4의 T5는 식후 노트북 작업으로 전환할 때 빈 그릇을 보관장소로 옮긴다.
- **학습:** 판단모델 가중치는 갱신하지 않는다. 하루 영상200프레임·기존기억·행동요약·선택적 사용자피드백으로 다음날 기억을 수정한다. 물리실행용 π0.5는 행동별10회 시연으로 미세조정한다(§3.3, 부록A).
- **명령·관측:** 매번 과제명령을 받지 않지만 도움목표·보관장소·가능행동은 설정되어 있다. 추가관측을 고르는 출력은 없으며 정기 영상입력에 의존한다.
- **평가:** 한 사람의3.5~4.5분 루틴×5일, 총1,146프레임이다. T5 Day5의 precision/recall/F1은0.66/0.69/0.60. 표1의8/10은 별도 물리실행 결과다(부록A.1·B).
- **한계:** 잠깐 물체를 건드린 것을 의도로 오인한다. 새 사용자·배치·물체 일반화와 질문정책은 검증범위 밖이다(§5).

[원문·전체 프롬프트](https://arxiv.org/html/2610.21211v1), [공개 기억 예시](https://github.com/DAVIAN-Robotics/PAM/blob/656a63ef4607177dd3b404042086486531a573f4/docs/static/data/pam-fsm.json).

### 컵 실험으로 옮길 때의 해석

이 논문의 핵심 질문은 ‘물체가 있는가’보다 **‘이 물체가 현재 활동에서 어떤 역할을 하는가’**에 가깝다. 사용자 컵 과제에서도 빈 컵의 겉모습이 같아도, 막 음료를 따르려는 순간과 음료 사용이 끝난 순간을 구분해야 한다. 이때 필요한 것은 길고 화려한 추론문보다, 현재 관찰을 해석할 수 있는 이전 행동과 활동 맥락이다.

기억을 사용하면 항상 좋아진다고 가정해서는 안 된다. 오래된 습관을 현재 증거보다 강하게 믿으면 새로운 루틴에서 먼저 잘못 행동할 수 있다. 합성 사례에는 ‘평소와 달리 계속 사용하는 날’도 포함할 가치가 있다.

**우리가 가져올 후보는 구조화한 활동기억과 NO_ACT 비교다.** ‘그릇이 비었으니 치운다’라는 규칙, FSM문자열, 실제 실행을 막는 프로그램 조건은 서로 다른 실험 조건이다. 논문의 FSM문자열을 그대로 넣었다는 이유만으로 단계 제약이 강제로 지켜진다고 판단하지 않는다.

### 원자료를 바로 읽을 위치

- [§3.1–3.3](https://arxiv.org/html/2610.21211v1#S3): 입력→선택→기억갱신.

- [부록B](https://arxiv.org/html/2610.21211v1#A2): 행동별 판단 지표, 특히 T5.
- [부록C.3](https://arxiv.org/html/2610.21211v1#A3.SS3): 같은 그릇을 잡는 행동을 단계별로 다르게 해석한 사례.
- [부록E.3](https://arxiv.org/html/2610.21211v1#A5.SS3): 실제 FSM판단 프롬프트.
- [부록F.3–F.4](https://arxiv.org/html/2610.21211v1#A6.SS3): 기억 생성·갱신 프롬프트.

## 2. Proactive Physical AI: 개입할 때와 행동 내용을 나눠 학습

정식 제목: **Proactive Physical AI through Continuous Observation and Timely Intervention**, Yang 등. [arXiv](https://arxiv.org/abs/2610.16967)2026-10-12 공개. 이번 조사에서는 학회 게재·수상을 확인하지 못했다. 논문 시스템명도 ProAgent지만, Columbia의 arXiv2512.06721 ProAgent와 **다른 연구**다.

### 원문에서 확인한 것

- **입력:** 관측이력·역할/권한·가능장치행동·이전응답/실행상태를 사용한다. 역할조건 평가에서는30초 영상과 최근5개 완료응답을 유지한다(§2, 부록D.2).
- **판단 방식:** 학습된 Timing Model이 `fθ(관측이력,역할,출력상태) → silence/response`를 고르고, 별도 Response Model이 말이나 함수호출을 정한다(§3.1 식9).
- **실제 역할프롬프트 발췌:** “You are a cooking assistant supporting everyday food preparation.” 이어 진행상황·재료/도구·안전에 주의하고 불필요한 반복개입을 피하도록 지시한다(부록D.1 표D.1).
- **학습:** Qwen3.5-4B의 언어모델·출력헤드를3epoch학습하고 영상인코더는 고정한다. 기존영상20,258개에서224,268개 시퀀스·2,058,267개 결정라벨을 생성한다. Response Model은 별도학습 없이 문맥 prompting을 사용한다(부록G.2–G.3).
- **데이터:** 역할·현재프레임·이전출력상태가 들어가고, 후속턴에 새 관측이 붙는다. 입력은 해당시각까지로 제한하지만 offline 라벨러는 전체영상을 보며, 모르는 구간은 침묵 정답으로 만들지 않는다(§3.1).
- **관측:** silence 중에도 정기관찰을 계속한다. ‘컵 내부를 보라’처럼 관측 대상·방식을 선택하는 정책은 검증하지 않는다.
- **평가:** 선택된200영상의 역할조건에서 동일Worker·입력·스케줄의 Base→학습Timing은 F1 28.72→33.45%, FP/min0.62→0.18이다(표1). 정답창과 대응되지 않은 응답이 모두 실제로 불필요한 것은 아니라고 인정한다(부록D.1).
- **물리평가:**60개 Reachy Mini 사례이며 사람의 실행도 포함한다. 컵정리 실험은 확인하지 못했다. 청소기 함수호출 예시는 부록G.3에 있다.

[원문](https://arxiv.org/html/2610.16967v1).

### 컵 실험으로 옮길 때의 해석

우리 과제에서 ‘항상 요청을 기다리지 않고 스스로 판단한다’는 정의를 명확히 하는 데 도움이 된다. ‘사용 중인 물건을 방해하지 않고 필요하면 정리한다’는 상시 책임을 주는 것과, ‘지금 저 컵을 치워라’라는 사건별 명령을 주는 것은 실험상 다르다. 전자는 과제의 범위를 정하고, 구체적 시작시점은 관측에서 찾아야 한다.

또한 현재는 아무 행동도 하지 않는 사례를 적극적으로 평가할 필요가 있다. 그렇다고 보류를 모두 정답 처리하면 영원히 기다리는 모델이 좋아 보인다. 정리해야 할 시점을 놓침과 너무 이른 정리를 함께 평가하는 것이 이 문제에 더 직접적이다.

이 논문의 두 모델을 반드시 복제할 필요는 없다. 먼저 한 API에서 개입 필요성·선택행동을 구조화해 출력하게 하고, 분리가 필요한 이유가 실제 실패로 드러나는지 확인할 수 있다. 이는 **우리 실험 제안**이며 논문이 단일 API의 동일 성능을 입증한 것은 아니다.

추가관찰은 별도의 확장이다. 정기적으로 다음 사진을 받는 것과, 결정에 필요한 특정 사실을 얻기 위해 관찰 도구를 선택하는 것은 다르다. ‘컵 안을 확인’이라는 요청이 실제 새 정보로 돌아오는 실험을 구성해야 후자를 평가할 수 있다.

### 원자료를 바로 읽을 위치

- [§4.1 표1](https://arxiv.org/html/2610.16967v1#S4.SS1): 같은Worker를 고정한 비교.
- [부록D.1–D.2](https://arxiv.org/html/2610.16967v1#A4.SS1): 실제 역할프롬프트·관측 범위·평가 제한.
- [부록G.2](https://arxiv.org/html/2610.16967v1#A7.SS2): 데이터 생성과 학습 설정.

## 3. Spatio-Temporal Object Modeling: 미래 배치 예측을 선제 정리에 연결

정식 제목: **Proactive Robot Assistance via Spatio-Temporal Object Modeling**, Patel·Chernova. CoRL2022 논문이며 PMLR205는2023년 출간이다. [공식 논문 페이지](https://proceedings.mlr.press/v205/patel23a.html), [공식 권호](https://proceedings.mlr.press/v205/). 수상 확인 없음.

### 원문에서 확인한 것

- **입력·이력:** 객체별 고유ID와 현재 위치의 scene graph, 시각을 받는다. 여러날 이력은 학습자료이며, 추론입력이 긴 과거영상 시퀀스인 것은 아니다(§3–4).
- **판단 방식:** 지도학습한 생성형 GNN이 `Φ(G_t,t) → p(G_(t+δ))`로 미래 배치분포를 예측한다. 각 객체의 최대확률 목적지를 고르고, 현재·미래 배치의 차이를 이동행동으로 바꾼다. LLM프롬프트는 없다.
- **시간·출력:**10분 뒤를 순차예측하며 대표평가는30분 범위다. 예측상 움직이지 않는 물체는 그대로 둔다(§6).
- **명령·관측:** 개별 요청이나 활동명 인식이 필요하지 않다. 물체가 식별되고 현재 배치가 주어진다는 전제이며, 추가관측 선택정책은 제시하지 않는다.
- **합성자료:** HOMER는5가구·가구별4방·108객체의 VirtualHome 일상을 구성한다. 사람에게 수집한 활동시간·행동순서를 확률적으로 조합한다. 대표평가는가구별50일학습/10일시험이다(§5·7.1).
- **수치:** 사용될 객체의 올바른이동40.51%, 잘못이동3.79%, 놓침55.70%; 미사용객체를 잘못이동0.81%다(표1). 가정 전체 성공률이 아니다.
- **정리 사례:** §7.1은 사용중 그릇을 찬장에 치우는 오류와 싱크대로의 다음 이동을 구분한다. §7.4·그림8에는 아침식사 전 준비·식후 시리얼/우유 복귀·그릇 싱크대 이동의 Fetch 시연이 있다.
- **한계:** 현재 사람행동과 물체의 청결상태를 모델링하지 않는다. 식사가 평소보다 길면 너무 일찍 치울 수 있다고 직접 명시한다(§8).

[원문](https://arxiv.org/html/2211.15501), [공식 코드](https://github.com/Maithili/SpatioTemporalObjectTracking).

### 컵 실험으로 옮길 때의 해석

이 논문은 ‘합성데이터로 시작해도 연구를 할 수 있는가’에 직접 참고할 수 있다. 실제 가정 촬영만을 기다리기보다, 행동순서와 시간 변화를 포함한 일상을 만들고 예측을 평가한다.

그러나 **사람이 나중에 이동할 위치를 맞히는 것과 지금 로봇이 대신 이동해도 되는 것은 같은 질문이 아니다.** 이 구분이 컵 과제에서 특히 중요하다. 컵이 나중에 싱크대로 갈 가능성이 커도 현재 한 모금 더 마시려는 사용자에게서 가져가면 잘못된 행동이다. 이 해석은 논문의 너무 이른 정리 한계와 함께 읽어야 한다.

따라서 이 모델의 객체이력 아이디어는 입력 설계에 쓰되, 현재 사용 여부·내용물·소유자·다시 쓸 가능성까지 자동으로 해결했다고 보지 않는다. 합성자료에 그런 변수가 있어도 모델 입력에 관측되지 않은 답을 그대로 넣어서는 판단능력을 측정하기 어렵다.

- [§5·부록A](https://arxiv.org/html/2211.15501#S5): HOMER 합성 일상 생성.
- [§7.1](https://arxiv.org/html/2211.15501#S7.SS1): 조기정리 오류·보수적인 미행동·수치.

- [§8](https://arxiv.org/html/2211.15501#S8): 오래 먹는 사람·물체 상태 누락의 명시적 한계.

## 우선순위에서 내린 후보

[LIT, arXiv2406.13787](https://arxiv.org/html/2406.13787)의 §4.1은 처음에 어떤 요리를 할지 사용자 전체과제명령을 받는다고 명시한다. §3.3의 Bayesian filtering은 관측이력에 따른 의도 갱신을 구체화하지만, 이번 ‘명령 없이 컵 정리 필요성 자체를 발견’하는 과제의 가장 직접적인 기준선으로 보기는 어렵다. 공개본의 학회상태는 CVPR2024 워크숍이며, 본학회 수상작처럼 소개하지 않는다. [서지](https://arxiv.org/abs/2406.13787).

Housekeep·TidyBot처럼 정리 목적이 이미 정해진 작업은 물체 목적지 판단에 유용할 수 있지만, 이번 선정에서는 ‘정리할 때가 되었는가’와의 직접성을 우선했다. 별도 깊은 검증을 했다는 의미는 아니다.

## 다음 회의에 가져갈 구체적인 비교 질문

아래는 논문 결과가 아니라 **현재 사용자 과제를 위한 검증 가설**이다.

| 비교할 조건 | 확인할 질문 |
| --- | --- |
| 현재 상태만 | 빈 컵처럼 모양이 같은 경우 사용전/사용후를 구분할 수 있는가? |
| 현재 상태+시간이력 | 마지막 음용·컵 이동·자리이탈이 추가되면 너무 이른 정리가 줄어드는가? |
| 현재 상태+시간이력+활동기억 | 같은 행동의 의미를 사용자 루틴에 맞춰 해석하는가? 루틴이 바뀌면 오히려 틀리지 않는가? |
| 위 입력+추가관찰 도구 | 어떤 미확인 사실이 행동을 바꿀지 골라 실제 정보요청을 하는가? |

컵의 정답을 ‘깨끗한 집’ 하나로 만들지 않는 것이 중요하다. 지금 사용 중이어서 두는 경우, 끝나서 치워도 되는 경우, 보이지 않는 내부 상태 때문에 더 확인해야 하는 경우가 모두 있어야 한다. 특히 **두기와 더 관찰하기를 모델 출력·평가에서 어떻게 구분할지**가 아직 남은 설계사항이다.

이 문서의 세 논문만으로 그 세 가지 선택을 모두 잘하는 방식이 확정되지는 않는다. 지금 얻은 직접 근거는 활동 맥락을 기억하는 방법, 요청 없이 개입시점을 학습하는 방법, 객체이력에서 선제 이동을 예측하는 방법이다. 추가관찰의 가치와 선택은 별도 검증 대상이다.
