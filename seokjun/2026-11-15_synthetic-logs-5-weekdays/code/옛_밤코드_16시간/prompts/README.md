# 글 버전 프롬프트 (`prompts/text`)

밤 단계에서 AI에게 주는 시스템 프롬프트 4개와, 실험 ② 채점에만 쓰는 2개(`matching.txt`, `predictor_text.txt`)다. 실행할 때마다 쓴 파일의 지문 값(sha256)을 기록에 남긴다(`pam/text_messages.py`). 논문 원본(`prompts/paper/`)은 고치지 않는다. 계획: `../../../설계문서/2026-11-14_PAM_80퍼센트_p-value_구현계획서.md`

| 파일 | 단계 | 받는 것 | 내는 것 | 논문 원본 |
|---|---|---|---|---|
| `moments.txt` | 순간 목록 만들기 | 기록 한 조각(2초마다 한 줄), 앞 조각 마지막 줄에서 하던 일(문장만, 시각 없이) | 순간 목록: 시각, 종류(start 시작 / end 끝 / moment 짧은 순간), 내용 | 없음 (새로 씀) |
| `reflector_text_build.txt` | 첫날 밤 자기반성 | 로봇 할 일 목록, 그날 순간 목록 | 후보 FSM (규칙마다 트리거 후보 1~3개) | `reflector_fsm_build.txt`를 고침 |
| `reflector_text_update.txt` | 다음 날부터 자기반성 | 로봇 할 일 목록, 그날 순간 목록, 지금까지의 FSM, 검사 결과, 피드백 | 후보 FSM | `reflector_fsm_update.txt`를 고침 |
| `marking.txt` | 후보 시각 찾기 | 상태 설명, 찾을 후보(상태 포함), 찾을 행동, 그날 순간 목록 | 후보와 행동이 일어난 시각, 사람이 안 보인 구간 | 없음 (새로 씀) |
| `matching.txt` | 밤 채점: 후보 짝 맞추기 (채점 전용, 밤 단계의 입력이 아님) | 정답표 사건 목록(사건 이름과 기록에 쓴 문장들), 번호 붙인 후보 문장 | 후보 번호마다 같은 순간인 사건 이름 하나. 없거나 애매하면 null | 없음 (새로 씀) |
| `predictor_text.txt` | 낮 채점: 다음 날 기록을 따라가며 지금 도울지 고르기 (채점 전용) | 최근 기록 5줄(2초 간격, 마지막 줄 시각이 지금), 예측 모델용 FSM, 로봇 할 일 목록 | 장면 한 문장, 이유 한 문장, 할 일 번호(안 도우면 -1) | `predictor_fsm.txt`를 고침 |

## 논문 원본에서 바꾼 곳

줄 번호는 논문 원본 파일의 줄이다. 적지 않은 줄은 원문 그대로다(같은 물건 트리거 금지, 로봇이 도와도 사람이 할 신호만 트리거로, 상태 나누기, 전이, 첫 상태 정하기 등).

### `predictor_text.txt` ← `prompts/paper/predictor_fsm.txt`

| 원본 줄 | 바꾼 것 | 이유 |
|---|---|---|
| 5~7 | 책상 → 집 전체(식탁, 식기세척기 있는 주방, 책상, 소파, 침대와 스탠드), 보관 장소와 식기세척기 | 자기반성 프롬프트와 같은 집이다 |
| 12 | 불 끄기 도움을 한 줄 더 넣고, pick-and-place 뒤에 switch-off를 붙임 | 할 일 목록에 방 불 끄기와 스탠드 끄기가 있다 (자기반성 프롬프트와 같다) |
| 15~18 | 카메라 사진(1초에 1장, 뒤쪽 카메라 2대를 이어 붙인 사진) → 관찰 기록 줄(2초에 1줄, `HH:MM:SS \| 문장`, 마지막 줄 시각이 지금) | 글 버전이다. 사진 대신 합성 기록 줄을 넣는다 |
| 22~24 | frames → record lines, final frame → last line | 글 버전이다 |
| 29 | "on the desk"를 뺌 | 책상만 있는 집이 아니다 (자기반성 프롬프트와 같다) |

- 나머지는 원문 그대로다. 원본 41~44줄 "기억(FSM)은 참고용이다. 상태나 신호 문구가 딱 맞지 않아도, 행동이 지금 장면에 맞으면 해도 된다"도 그대로 뒀다. 논문의 예측 모델과 똑같이 두려는 것이다. 이 문장 때문에 아침 식사 규칙을 공부 시간에 쓸 수도 있는데, 낮 채점에서 실제로 그런 일이 생기는지 본다.
- 몇 줄을 넣을지(`{window}`), FSM(`{fsm_block}`), 할 일 목록(`{tasks_block}`)은 논문처럼 돌릴 때 채운다. 5줄이면 지금부터 8초 전까지라, 논문이 2초 간격으로 넣은 사진 5장과 같은 시간이다.
- 대답 모양(장면 한 문장, 이유 한 문장, 할 일 번호)도 논문 그대로다.

## 정해 둔 숫자와 가정 (확인 필요)

- **검사 기준 시간:** 프롬프트 글에는 숫자를 쓰지 않는다. 계산 코드의 값(`pam/trigger_check.py`의 `FOLLOW_SECONDS`, 지금 5분)을 자기반성 입력에 자동으로 넣는다(`pam/text_messages.py`). 5분을 바꾸면 코드 한 곳만 고치면 되고, 프롬프트와 계산이 어긋나지 않는다. 5분 자체는 임시 값이다.
- **후보를 바꿀 수 있는 기준:** 3번 이상 나왔고 80% 미만. 계획서에는 "계속 떨어지는 후보"라고만 적었다.
- **시각 찾기:** 같은 후보가 10초 안에 다시 나오면 한 번으로 친다 (고개를 잠깐 돌린 것 같은 끊김).
- **순간 목록:** 줄 한두 개(4초 이하)면 짧은 순간, 그보다 길면 시작과 끝 두 줄.
- **기록 문장 모양:** 한 줄이 장면 전체(자세, 하는 일, 주변 물건)를 적고, 방금 한 일을 몇 초 동안 다시 말한다. 실제 예측 모델 관찰 문장(`artifacts/routine_vllm_fsm_2026-11-04`)이 그렇다. 그래서 `moments.txt`에 "자세와 주변 물건은 일이 아니다", "방금 한 일을 다시 말하는 줄은 새 일이 아니다" 두 줄을 넣었다(2026-11-16, 합성 기록을 실제 문장 모양으로 다시 만든 뒤).
- **할 일 찾기 (`marking.txt`):** 할 일은 로봇 입장에서 쓴 문장이라, 사람이 직접 같은 결과를 만들었으면 말이 달라도 센다. 장소 이름이 다른 경우("사람 옆" = 그 사람이 있는 곳에서 손 닿는 곳)와 물건 이름이 다르거나 더 구체적인 경우(같은 물건일 때만)를 적고, 아무것도 바뀌지 않는 순간(방금 쓰던 물건 내려놓기)은 세지 않게 했다. 이 집의 가구·전등 이름은 일부러 넣지 않았다. 실험 ② 1일째(2026-11-16)에 식탁·책상에 컵을 놓은 4번과 "천장 불 끄기"를 "사람 옆에 컵 놓기", "방 불 끄기"로 찾지 못해서 넣었다.
- **조각 경계:** 조각마다 시작과 끝을 그 조각 안에서 다 적는다. 조각 끝까지 이어지는 일은 마지막 줄에서 끝, 다음 조각 첫 줄에서 다시 시작으로 적고, 같은 문장이면 코드(`pam/daily_run.py`의 `join_parts`)가 하나로 잇는다. 다음 조각에는 앞 조각 마지막 줄에서 하던 일을 문장만 넘긴다. 처음에는 "이미 하고 있던 일"을 시작 시각과 함께 넘겼는데, 실험 ② 1일째 밤(2026-11-15)에 AI가 그 시작 시각을 끝 시각으로 베껴 목록 시간이 거꾸로 가서 바꿨다. 조각 밖 시각을 쓴 답은 거절한다.
- **"로봇은 오늘 아무것도 하지 않았다":** 합성 기록 시험용이다. 로봇이 실제로 돕기 시작하면 로봇이 한 일도 입력에 넣도록 고쳐야 한다.
- **집 설명(Environment):** 합성 기록의 집에 맞췄다. 실제 집이 다르면 바꾼다.
