# PAM에 개인별 선호 모델 적용하기 — 연구 방향

작성일: 2026-11-01

> **현재 상태: 연구 방향 제안. 개인별 선호 모델은 구현·실험 전이며, 성능 개선이나 연구 차별성이 검증된 결과는 없다.**

사용자가 매번 이유를 설명하지 않아도, 여러 도움에 대한 행동 기록에서 개인의 개입 선호를 추정하고 그 사람에게 아직 제공하지 않은 도움의 적절성을 판단하는 방법을 검토한다. 여기서 최소화하려는 것은 사용자가 직접 답해야 하는 질문과 평가 요청이다.

## 기존 PAM에서 출발하는 부분

PAM(Procedural Assistance Memory)은 활동 단계, 도움 조건, 행동을 저장하는 절차 기억이다. 현재 상황과 기억을 읽어 도움을 고르고, 하루 기록을 검토하는 자기반성으로 다음 날의 기억을 갱신한다. 기존 PAM도 생활 습관과 사용자 피드백을 반영한다. 따라서 개인화를 추가했다는 사실만으로 새로운 연구라고 주장할 수는 없다.

현재 저장소의 구현·실행 범위는 [프로젝트 설명](../../README.md)에 정리되어 있다. 이번 문서는 그 구현에 추가할 연구 방향이며, 아래 선호 추정 과정이 이미 동작한다는 뜻은 아니다.

## 처음 h·w 아이디어에서 유지할 것과 보완할 것

| 구분 | 처음 아이디어 | 현재 검토 방향 |
| --- | --- | --- |
| 사람마다 다른 선호 | h(도움 자체에 대한 선호)와 w(개입 특성별 간섭 민감도)로 표현 | 도움의 이득과 개입의 부담을 나누어 본다는 관점 유지 |
| 여러 행동에 적용 | 행동의 성질과 개인별 가중치를 결합 | 공통 특성을 통해 새로운 도움을 판단한다는 목표 유지 |
| 반응 해석 | 관찰한 반응을 정해 둔 기준에 따라 점수 갱신으로 연결하려 함 | 상황과 다른 가능한 이유를 함께 검토하고, 근거가 약하면 갱신 유보 |
| 특성과 학습 방법 | 근접성·영역 침범·통제권·타이밍 등의 요인과 수치 갱신식을 제안 | 특성의 정의, 반응과의 연결, 학습식과 불확실성 표현을 비교 실험으로 결정 |
| 적용 시점 | 밤에 개인 선호를 반영해 다음 날 도움 방식을 정함 | 자기반성에서 도움의 유지·수정·제외를 검토하는 구조 유지 |

**원래 h(도움 선호)·w(간섭 민감도) 모델도 새로운 행동에 적용하려는 아이디어였다.** 이번 보완의 핵심은 일반화라는 목표를 새로 붙이는 것이 아니라, 어떤 관찰로 개인 특성을 추정할 수 있는지와 잘못된 추정이 퍼지는 것을 어떻게 줄일지 구체화하는 데 있다. h와 w라는 이름, 차원 수, 계산식은 확정하지 않았다.

## 해결해야 할 한계

### 같은 반응에 여러 이유가 있다

로봇이 우유를 가져다준 뒤 사용자가 우유를 옮기고 사용했다면, 확인된 것은 위치 변경과 사용이다. 가까운 접근이 싫었는지, 작업 공간이 필요했는지, 사용하기 편한 위치로 옮겼는지는 이 기록만으로 구분하기 어렵다. 사용했다는 사실도 로봇의 개입을 반겼다는 증거는 아니다.

따라서 한 번의 위치 변경을 간섭 민감도 상승으로 바로 바꾸거나 도움 자체를 끄는 근거로 삼지 않는다. 비슷한 반응이 반복되어도 상황이 함께 바뀌었다면 원인을 확정할 수 없다. 서로 다른 도움과 상황을 비교할 수 있는 기록이 필요하다.

### 잘못 배운 특성이 다른 도움에도 적용된다

한 번의 거절을 모든 도움에 대한 거부로 해석하면 유용한 도움까지 제외할 수 있다. 반대로 도움은 원하고 방식만 싫어한다고 단정하면 원치 않는 개입을 반복할 수 있다. 무반응이나 사람이 직접 한 행동에도 같은 주의가 필요하다.

목표는 사람의 고정된 성격이나 진짜 속마음을 알아냈다고 주장하는 것이 아니다. **관찰 근거가 허용하는 범위에서, 특정 상황의 개입 선호를 예측하는 것**이다. 두 수치를 별도로 추정할 충분한 관찰 차이가 없으면 도움 선호와 간섭 민감도를 정확히 분리했다고 말할 수 없다.

## 제안 구조: 언어 모델의 해석과 개인별 선호 추정을 연결

```text
행동·상황·로봇 개입·사용자 반응 기록
                    ↓
언어 모델: 공통 특성과 가능한 해석 제안
         근거가 된 기록과 다른 설명을 함께 제시
                    ↓
개인별 선호 모델: 특성별 선호와 불확실성 갱신
                근거 부족·상충 시 미확인으로 유지
                    ↓
PAM 자기반성: 도움 후보를 유지·수정·제외할지 검토
                    ↓
다음 날 상황과 도움 조건 확인 → 선제적 실행 → 반응 기록
```

언어 모델(LLM)은 기록을 읽고 “작업 중 물건 배치를 바꾼다”처럼 여러 행동에 공통인 특성과 해석 후보를 찾는 역할을 맡기는 방안을 검토한다. **그 답변을 곧바로 사용자의 확정 선호나 정답 라벨로 저장하는 방식은 아니다.** 별도의 신경망 학습을 확정한 것도 아니다.

개인별 선호 모델은 다음 정보를 지속적으로 보관하는 구조를 검토한다.

| 보관할 정보 | 예시와 용도 |
| --- | --- |
| 도움의 공통 특성과 적용 상황 | 작업 중 배치 변경, 사용이 끝난 물건 정리 등을 구분 |
| 개인별 선호 추정 | 그 특성을 꺼리거나 반기는 방향과 정도; 수치화 방법은 미정 |
| 근거와 반대 근거 | 어떤 기록이 추정을 뒷받침하거나 반박하는지 연결 |
| 불확실성과 갱신 이력 | 자료가 부족하거나 해석이 갈리는 특성을 구분하고 수정 가능하게 보관 |

예를 들어 서류 정리와 공구 정리의 반응에서 작업 중 배치 변경에 대한 공통 선호를 추정했다면, 케이블 정리에도 같은 특성이 있는지 비교한다. “서류 정리 거절” 같은 행동별 기록만 재사용하는 것과 구별되는 지점이다. 단, 물건 이름이 달라도 실제 맥락이 다를 수 있으므로 적용 범위도 함께 확인해야 한다.

밤의 자기반성에서는 후보 행동을 검토하고, 낮에는 현재 상황과 도움 조건을 다시 확인한다. 명시적 거절은 해당 개입을 즉시 중단·보류하는 근거로 사용하며, 거절한 행동을 다른 방식으로 계속 시도하지 않는다. 거절의 범위를 모든 도움으로 자동 확대하지도 않는다. 불확실할 때 매번 질문하는 대신 기존에 확인된 도움 유지, 해당 후보 보류 등의 선택지를 비교하되 유용한 도움을 얼마나 놓치는지도 평가한다.

## “PAM에 프롬프트만 추가”하는 것과 어떻게 비교할 것인가

기록을 언어 모델에 주고 선호를 판단하라는 지시문만 추가한 방법도 유효한 비교 대상이다. 별도 선호 모델의 필요성은 이 방법보다 낫다는 증거로 보여야 한다. 현재 차별성이 충분하다고 결론 내리지 않는다.

검토할 차이는 공통 특성을 보관하는 방식, 근거에 따라 개인별 선호를 갱신하는 규칙, 불확실한 추정의 적용을 제한하는 방법이다. 이 요소들을 명확하게 정의하지 못하면 구조 설명만 바뀐 제안에 머무를 수 있다.

## 검증 계획 — 아직 실행하지 않은 비교

### 학습한 행동과 평가할 행동을 분리

- 예시: 서류·공구 정리에 대한 기록으로 개인 선호를 추정하고, 그 사람의 학습 기록에 없는 케이블 정리에서 평가한다.
- “처음 보는 도움”은 개인 선호를 배우는 기록에서 제외한 행동을 뜻한다. 로봇에 없는 동작 능력을 새로 만든다는 뜻은 아니다.
- 현재 아침 식사 구현은 우유 제공·컵 정리·접시 정리와 대기를 다룬다. 서류·공구·케이블 예시는 개념 설명이며 현재 실행 결과가 아니다. 이 예시로 실험하려면 별도 판단 자료와 행동 목록을 먼저 마련해야 한다.
- 가능한 한 같은 행동에서 개입 시점이나 배치 변경 여부를 달리한 사례도 마련해, 물건 종류와 개입 특성이 항상 함께 바뀌는 문제를 줄인다.
- 같은 사람의 새로운 행동 평가와, 한 번도 관찰하지 않은 새로운 사람에 대한 평가는 구분한다.

### 같은 자료와 선택지로 비교

| 비교할 방법 | 확인할 질문 |
| --- | --- |
| 기존 PAM | 기존 자기반성·피드백 반영보다 보완 효과가 있는가? |
| 행동별 사례 기억 | 같은 행동을 기억하는 것보다 새로운 행동 판단에 도움이 되는가? |
| 언어 모델 직접 판단 | 같은 기록과 선호 판단 지시문만으로도 충분한가? |
| 공통 특성 기반 개인별 선호 모델 | 특성·근거·불확실성을 보관하고 갱신하는 과정이 추가 이득을 주는가? |

비교 방법에 제공하는 관찰 기록, 명시적 피드백, 가능한 행동과 질문 예산을 맞춘다. 언어 모델을 쓰는 방법끼리는 가능한 한 같은 모델을 사용하고, 입력 길이·호출 횟수 차이를 기록한다. 이후 고정 특성만 쓰는 방법과 언어 모델이 특성을 제안하는 방법, 불확실성 처리를 뺀 방법을 비교하면 어느 요소가 기여했는지 확인할 수 있다.

### 간섭과 유용성을 함께 평가

| 확인할 결과 | 측정 방향 |
| --- | --- |
| 원치 않는 개입 | 평가에서 원치 않았다고 확인된 도움의 실행 빈도 |
| 유용한 도움 유지 | 원했던 도움을 적절하게 제공한 비율과 누락 빈도 |
| 새로운 행동의 적절성 | 학습에서 제외한 행동에 대한 선택과 사용자 평가의 일치 |
| 사용자 부담 | 질문·명시적 평가 요청·사용자의 수정 또는 되돌림 횟수 |
| 불확실성 처리 | 확신했던 판단이 틀린 정도, 판단을 보류한 비율과 그때 놓친 도움 |

주관적 불편함은 관찰만으로 정답을 만들 수 없다. 연구 평가를 위한 사용자 응답을 별도로 받아야 하며, 그 응답은 해당 평가에 앞선 학습 입력과 분리한다. 실제 운용에서 요구하는 피드백과 연구에서 측정을 위해 받는 평가도 나누어 보고한다. 아무 도움도 하지 않는 방법과 비교해, 개입 감소가 단순한 도움 포기 때문인지 확인한다.

가상 사용자를 쓰는 초기 실험은 가정한 반응 규칙에서 방법이 작동하는지를 확인하는 용도다. 모델과 같은 규칙으로 만든 정답을 맞힌 결과를 실제 사람의 선호를 파악한 증거로 해석하지 않는다.

## 다음에 결정할 것

1. 첫 실험에 쓸 행동·상황과 기록 단위, 필요한 관찰 자료를 확정한다.
2. 공통 특성의 정의와 언어 모델 출력 형식, 근거를 확인하는 방법을 정한다.
3. 개인별 선호 갱신식과 불확실성 처리 방법을 정하고, 단순한 비교 방법부터 구현한다.
4. 평가용 사용자 응답의 수집 시점, 질문 예산, 성공 기준을 실험 전에 정한다.

이번 문서에서 완료한 것은 연구 방향과 비교 계획의 정리다. 실제 모델 실행, 사용자 평가, 선호 모델 학습 및 성능 측정은 하지 않았다.
